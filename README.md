# 大创项目工作区

本目录用于规划家居移动操作机器人项目，并逐步完成项目立项申报书。各文件按照“项目定义—研究拆解—系统设计—验证依据—申报书表达”的关系分工，避免把所有内容集中在一个文件中，也避免不同文件重复定义同一问题。

## 文件关系

```text
项目目标.md
    ↓
研究问题与研究内容
    ↓
架构设计.md + 语义地图设计 + 验证方案与评价指标
    ↓
创新点、技术路线、进度安排、已有基础
    ↓
立项依据.md
```

`正文思路.md` 位于这条链路的上方，用于约束申报书的论证顺序和章节逻辑，不承载具体技术方案。

## 根目录文件

### `项目目标.md`

项目的正式目标与边界依据，说明：

- 项目是什么，面向什么应用背景；
- 要解决的核心问题；
- 首年必须完成的验证闭环；
- 通用性和扩展性的含义；
- 项目明确不承担的内容；
- 如何判断项目是否完成。

其他规划文件应以本文件中的目标和边界为依据。该文件不展开通信协议、具体模型参数或实现代码细节。

### `正文思路.md`

申报书的写作思路与论证逻辑，说明七个章节分别回答什么问题，以及各章节如何衔接。它用于指导《立项依据.md》的写作，不是项目大纲，也不是申报书正文。

### `立项依据.md`

按照申报书要求编写的正式正文，保留现有七项结构：

1. 研究目的；
2. 研究内容；
3. 国内外研究现状和发展动态；
4. 创新点与项目特色；
5. 技术路线、拟解决的问题及预期成果；
6. 项目研究进度安排；
7. 已有基础。

该文件是最终汇总表达，不作为所有讨论材料的存放处。正文内容应在相关规划和论证材料稳定后再写入。

### `架构设计.md`

系统工程设计文档，说明：

- Agent、环境语义地图、技能专家、机器人支持层和硬件层的职责；
- 层间接口、胶水机制和事件驱动运行方式；
- 仿真模块、软件模块和真实硬件之间的适配关系；
- 系统如何支持技能替换、任务扩展和硬件升级。

它回答“系统如何组织”，不负责重新定义项目目标，也不替代申报书中的技术路线。

### `通信_胶水_草稿.md`

记录通信、接口适配、任务生命周期、状态反馈和事件传递等实现层面的讨论。它是架构设计的技术补充，内容成熟后再提炼到正式设计文档或代码接口中。

### `参考项目_references.md`

保存参考项目、论文、代码库和相关技术资料的索引与备注，用于支撑技术选型和申报书中的研究现状分析。资料记录与申报书正文分开维护。

## `ai_note` 目录

`ai_note` 用于保存阶段性讨论稿、规划草案、版本记录和 AI 辅助材料。这里的文件默认属于工作稿或讨论稿，只有经过确认后，才整理到根目录正式文档。

主要类型包括：

- 项目规划与申报书推进计划；
- 项目目标与边界的讨论稿；
- 研究问题与研究内容分解；
- 语义地图设计草案；
- 验证方案与评价指标；
- 国内外研究现状与问题分析；
- 申报书章节大纲或阶段性正文草案；
- 对历史会话和讨论结果的整理记录。

`ai_note` 中带时间戳的文件用于保留讨论过程和版本差异，不自动代表当前最终结论。阅读工作稿时，应以最新确认的正式文件和用户明确决定为准。

## 后续拟补充的工作文档

随着规划推进，建议在 `ai_note` 中分别建立以下文档：

- `项目研究问题与内容分解.md`：将总体目标拆分为研究问题、研究内容和非目标；
- `环境语义地图设计.md`：规定空间、区域、物体实例、历史和查询更新接口的最小范围；
- `验证方案与评价指标.md`：规定仿真、真机、基线、指标和扩展性验证方法；
- `研究现状与问题分析.md`：从参考资料中提炼已有方案、发展趋势和本项目切入点；
- `项目年度阶段计划.md`：规定一年期项目的阶段目标、里程碑、交付物和风险替代方案；
- `已有基础与条件保障.md`：整理现有硬件、软件、实验记录、团队能力和条件缺口。

这些工作文档分别为《立项依据.md》的不同章节提供依据，不应互相替代。

## 维护原则

1. 项目目标和范围只在 `项目目标.md` 中正式确认。
2. 技术架构和接口设计主要放在 `架构设计.md` 及其技术补充文档中。
3. 调研资料保留来源和事实，分析结论单独整理，不直接把资料堆入申报书。
4. `正文思路.md` 只说明申报书如何组织，不扩写成项目大纲或技术方案。
5. `立项依据.md` 只保留面向申报书的正式表达，避免成为讨论记录的总仓库。
6. 讨论稿先放入 `ai_note`，确认后再同步到根目录正式文件。
