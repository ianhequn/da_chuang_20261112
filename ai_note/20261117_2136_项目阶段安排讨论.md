## 二、首期：受控条件下的寻物取回与体系验证

### 1. 环境

- **地形与空间**
    - 受控室内家居环境，房间与区域用途先由用户设置，具体房间数量待确定。
    - 物品先放在简单、显眼、便于观测与接近的位置，不固定目标坐标与导航路径，由Agent结合任务和环境信息组织行动。
- **物体**
    - 使用经模型应用、调优和测试确定的有限优质物品集合，同时采用开放词汇技术；已有SmolVLA小木块抓取是调优起点，最终范围由实测形成。
    - 在有限集合内研究物体搬动、遮挡、同类实例等情况，维护观测历史、实例身份与位置候选。
    - **中期简化条件**：可将目标物放在地面，降低空间定位与操作难度。地面放置是阶段性条件，不是首期最终能力的永久限制。

### 2. 系统与平台

- **硬件方案**
    - 集成差速底盘与一台六自由度机械臂，前期停车后操作，定位与环境观测持续运行。
    - 现有技术记录包括2D激光雷达与腕上相机；深度相机拟结合实际配置落实。用户本轮补充：大概率至少配备低价二手深度相机。
    - **中期简化条件**：可采用2D激光雷达配合地面物体开展验证，降低对昂贵三维建图设备的依赖。雷达提供几何与定位基础，物体识别仍需相机；物体地图位置需结合相机标定、位姿与地面约束或深度信息获得。
    - 上述简化拟用于贯通主要技术链路；它能支持哪些感知与操作条件，应通过实测说明，不等同于完整验证三维感知能力。
- **软件方案**
    - **Agent层**：先采用主Agent方案，以Pi Agent SDK为优先路线，搭建常驻事件驱动主程序，接入用户输入、执行事件、环境查询与能力说明；组织任务上下文、记忆和持续状态，依据反馈开展后续决策、失败恢复与任务调整。
    - **环境认知服务**：统一组织几何空间、区域用途、物体和历史观测；重点研究概率性实例关联与位置推断的共享证据和状态更新。观测与维护原则上持续运行，频率结合算力调整。
    - **技能专家**：优先优化SmolVLA的任务数据、相机条件及推理到控制链路，结合测试形成能力边界；接入导航、搜索动作、抓取和放置等所需能力。Agent选择能力，技能后端负责执行组织与模型输入适配。
    - **调用与协同**：以SKILL说明和异步CLI对接技能服务，支持Agent选择、调用与组合首期所需能力，通过事件和查询衔接任务状态；公共通信与适配机制融入各模块，支持同机或跨主机部署。
    - **支撑与仿真**：利用ROS 2、Nav2、设备固件和驱动等支撑移动操作；按工作适用性使用Gazebo、MuJoCo及真机，完成标定、接口适配与联调，不固定为所有工作先仿真后真机。

### 3. 任务：寻物取回

- **指令输入**
    - 首期通过GUI软件、命令行等方式发送指令即可，不要求实时语音交流。
- **基本任务链**
    - 用户提出目标 → 查询环境 → 导航与搜索 → 抓取入篮 → 返回用户位置 → 反馈结果、更新状态。
    - 首期应能够返回用户所在位置；中期可简化为将物品送至指定区域，不要求追踪用户。跟踪用户移动纳入扩展。当前任务是入篮取回，不额外承诺手递交付。
- **行动组织**
    - Agent依据可用技能、环境信息和执行反馈选择搜索方法，可调整机器人或相机姿态，也可调用适用搜索程序。
    - 搜索动作创造观测条件，环境认知服务提供感知与状态依据，不为每种搜索方式重建独立地图系统。
- **交互与变化响应**
    - 应对用户补充条件、调整目标，以及未找到目标、技能失败等情况，研究继续观察、重试、调整、求助或结束的判断。
    - 技能执行结束与任务目标达成分别判断，依据实际反馈确认结果。

### 4. 研究评价

- **技能调用质量与效率**：参照人工通过相同接口操作，分析技能选择、参数、次序、无效调用、耗时及结果；记录双方可用信息差异，不预设唯一正确流程。
- **Agent决策应对**：分析用户要求、环境或整机状态变化时的判断依据、响应内容及后续效果。
- **事件驱动运行健康性**：检查持续运行、任务停滞、事件积压或遗漏、过时决策、状态不一致及恢复表现，与模型判断问题分开分析。
- **环境认知响应与估计**：对照物体移动、遮挡、同类实例等真实记录，分析实例关联、位置估计、更新延迟及搜索影响；区分缺少有效观测与感知、推断或更新错误。
- **整机表现及改进效果**：记录重复运行、分段及整体成功失败分布、耗时和人工干预，分析各部分改善能否转化为整机收益。
- **首期内部推进**：模块验证 → 简化条件初步贯通 → 可重复闭环 → 条件变化、方案比较与实验改进。研究评价贯穿各步，中期不要求全部完成。

## 三、扩展：能力接入、服务拓展与应用条件演进

以下按与首期相同的结构汇总候选范围，便于后续选择代表性工作；不将全部候选同时列为结题承诺。扩展依据是能力、服务或应用条件发生变化，不是把首期尚待实现或完善的基础机制另划为后期功能。

### 1. 环境

- **地形与空间**
    - 扩展至更多房间、功能区域和更复杂家庭环境，物品放在更任意、更复杂的位置，结合感知、可达性和操作条件检验搜索及任务组织的复用。
    - 随感知与操作条件改善，研究超出早期地面放置条件的任务；实际支持面、高度与可达范围由设备和测试确定。
    - 条件成熟后探索非家居场景中的移动操作。
- **物体**
    - 丰富物品类别和实例，在首期已采用开放词汇技术的基础上，探索更多未预设目标的表示、关联、位置与状态维护，逐步减轻对预先列举物品集合的依赖。
    - 分别检验感知覆盖与操作能力，结合数据、调优和测试确定实际可用范围。
    - 同类实例与动态更新在首期已经研究，扩展时考察范围、复杂度及泛化，不将其误列为扩展阶段才有的功能。

### 2. 系统与平台

- **硬件方案**
    - 按任务需要研究底盘、机械臂、传感器和计算设备升级及适配，保留上层接口与任务组织的复用。
    - 候选包括深度相机、3D雷达、多相机、双臂和升降主体；若深度相机已在首期配备，扩展研究其增配或用途拓展，不重复视为首次接入。
    - 重新核对标定、视野、可达空间、控制条件和能力边界。
- **软件方案**
    - **技能接入与替换**：接入更多导航、视觉、抓取、放置、规划、具身模型和复合能力，比较不同实现的适配、替换与复用。
    - **模型应用优化**：按需要比较其他VLA、WAM或策略方案；开展多任务调优并关注旧能力保持、灾难性遗忘与实际能力范围。
    - **新增能力利用与复杂任务表现**：在首期已有的SKILL、调用组合、上下文、记忆、失败恢复和持续状态机制上，检验Agent能否利用新增技能支持新服务，以及更长流程、更多能力组合下出现的瓶颈；按实验结果改进既有机制。其他Agent分担部分工作另属可选探索。
    - **环境认知**：扩充物体与空间信息，按需要探索自动识别或推测区域用途，保留用户设置与修订入口。
    - **移动操作协同**：探索由相应技能接管底盘并协同机械臂控制，研究控制权交接与资源约束，同时保持定位与环境认知运行。
    - **部署适配**：随模型与平台变化调整计算分配和分布部署，检验接口、事件与状态机制的复用及运行代价。

### 3. 任务与服务

- **新服务类别**
    - 垃圾发现与处理、拖鞋归位、物品归位、整理和收纳等为已有候选，具体按技能和平台条件选择。
- **任务复杂度**
    - 探索多物品、更长流程及更多技能参与的任务组合，分析协调、恢复与持续运行。
    - 首期已具有多技能协作和变化响应；扩展关注新增能力及更复杂条件，不把基本协作和改指令响应推迟到此阶段。
- **用户移动与交付**
    - 探索跟踪用户移动，更新交付目标并调整返回或交付行动。
- **任务来源**
    - 除响应用户指令外，探索自主发现服务需要，例如发现拖鞋需要摆放整齐；具体触发、确认和执行机制尚待研究。

### 4. 研究评价

- **接入、替换与复用代价**：记录执行适配、数据调优、接口说明和上层程序改动，判断哪些机制可以复用。
- **Agent对新增能力的利用**：分析能力理解、选择、参数、组合和边界判断，区分新增能力本身不可用与Agent不会用、误用。
- **服务范围及复杂任务效果**：记录实际新增服务、任务结果、协调代价与新增失败模式，区分扩大物品范围、扩大区域与新增任务类别所支持的结论。
- **原有能力保持与稳定性**：开展旧任务回归，分析模型调优后的遗忘、资源及控制冲突、新模块对持续运行的影响。
- **平台与环境适配**：记录重新标定、调优及部署工作，分析上层复用与适配后的效果。

## 四、阶段拆分建议（供讨论，尚未定案）

首期按“模块可用与初步贯通—整机闭环—稳定改进与设计评价”推进，再在其基础上开展有代表性的扩展。阶段表示工作重心，环境推断、模型调优和实验记录可以并行推进。

| 建议时段 | 工作重心 | 适合检查的进展 |
|---|---|---|
| 2026年11月—2027年2月 | 核对平台配置，改善抓取数据与能力；搭建Agent常驻主程序、技能服务及环境查询原型，开展分模块与模拟事件测试 | 能独立调用和记录的关键能力；环境服务初步查询与更新；主程序接收执行事件并继续任务的运行记录；整机依赖与主要风险清楚 |
| 2027年3—5月，中期前 | 结合真实设备开展跨模块联调，争取在简化条件下贯通寻物取回链路；同时推进物体推断候选方法与模块实验 | 可展示的分段实机结果和初步系统运行；哪些环节已串联、哪些仍需人工衔接有明确记录；抓取、环境更新和Agent运行的初步数据；后续改进依据 |
| 2027年6—9月 | 完善首期闭环与异常应对，开展重复运行、条件变化和候选方案比较，依据结果调优 | 可重复的受控场景寻物取回；首期五方面评价逐步形成结果；实测能力边界、主要瓶颈与改进效果可说明 |
| 2027年10—12月 | 继续解决首期主要瓶颈，选择代表性能力接入或服务扩展，检查复用与旧任务保持 | 接入改动、新能力利用、任务表现和回归记录，能够区分首期改善与扩展效果 |
| 2028年1月—2/3月 | 完成必要补充实验，整理系统、数据和研究结论，准备结题 | 可复查的配置、代码、模型与数据说明、实验记录、演示及报告，完成范围与限制一致 |

中期建议以“关键模块可验证、系统已开始贯通、有真实实验依据及明确瓶颈”为核心，而非要求首期全部成熟。初步闭环应作为争取目标；是否列为中期明确承诺，还需根据平台集成、抓取改进和人员投入讨论。模拟服务能够支持接口和事件验证，但不能代替真实感知与执行效果。

扩展准备可提前开展，主要扩展实验应有可比较的首期版本。首期完善与扩展允许交叠，避免等待所有首期问题解决后才开始，也避免以新功能掩盖原有系统尚未稳定的问题。

## 五、下一步需要讨论的取舍

1. 中期系统贯通到哪一层次：简化条件下争取完整真机闭环，还是明确以分段实机与部分自动衔接为检查成果？需结合实际资源确定。
2. 首期闭环后，优先选择哪一种扩展作为架构价值的主要证据：新增或替换技能、支持新服务，或两者结合？
3. 团队人员、每周投入、设备与经费到位时间，以及假期可用条件，会怎样约束上述时间窗口？

阶段安排尚待讨论，任务次数、成功率阈值和扩展数量不在本轮凭空设定。
