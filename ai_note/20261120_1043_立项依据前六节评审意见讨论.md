# 立项依据前六节评审意见讨论

记录日期为 2026 年 11 月 20 日。本笔记保存对评审意见的判断、理由和待讨论事项，供逐条讨论与后续修订使用。以下内容均为讨论建议，涉及第七节的事项留待另议。

依据为[当前正文](../立项依据.md)、[11 月 18 日备份稿](../old_docs/20261118-1530-立项依据.md)、[正文思路](../正文思路.md)、[验证方案与评价指标](验证方案与评价指标.md)、[阶段安排讨论](20261117_2136_项目阶段安排讨论.md)和[分阶段基线与评价标准调研](../search/20261119_分阶段基线与评价标准调研.md)。

## 1. 第五节的寻物取回成功判据

- **评审意见**。补足首期闭环的判定依据，明确怎样确认指定实例、入篮和返回，也交代人工干预及分段结果。
- **建议采纳的理由**。Agent 报告完成、技能返回结束与物品实际取回是三个不同事件。整机评价需要可以复查的物理结果，才能将错取、抓取或放置失败、返回失败与运行异常区分开。
- **建议写法**。在第五节实验部分说明，完整成功按取回正确目标实例、确认入篮并到达该用例事先约定的返回范围判定。分段结果、人工干预及失败原因分别记录。预期成果交代原型及对应的验证记录。验证方式、重复次数和性能阈值可在预实验后确定。
- **已确认**。完整成功的判据已写入第五节“整机表现与调优”。每轮按用例约定的用户附近区域判定是否返回，分段结果与人工干预分别记录。用户位置的获取方式留到实验用例设计时确定。

## 2. 第五节的三组对照

- **环境认知**。以同一批观测或可比真机条件比较“类别与最近观测位置”基线和可利用历史证据、身份与位置候选的方案。回放可诊断关联、位置及更新误差，真机用例再看正确实例取回与错取。若要单独论证两类估计共享证据的收益，再用相同历史增加分别更新的对照。前一组检验整套环境信息的作用，后一组隔离联合更新的作用。
- **已确认环境认知评价口径**。正文先从响应与估计两方面说明评价目标，再交代同一观测记录下的最近观测基线。响应考察何时获得有效观测及何时更新地图，估计考察实例关联、位置估计的准确性和证据不足时的不确定性表达。共享证据的独立回放对照仍作为可选实验。
- **Agent 组织与恢复**。建议拟做一组小规模固定流程对照。预设流程应有合理的异常分支，双方共享可比观测、技能、执行预算和初始条件，在等价的任务节点设置失败或指令变化。重点考察任务完成、恢复和旧目标误执行。人工同接口操作继续用于诊断技能和接口实际支持的行为。运行调度故障与 Agent 判断偏差分别记录。
- **服务扩展**。冻结寻物取回版本，在相同整理用例中比较既有技能组合与接入或适配能力后的表现，再复跑同一批寻物任务。记录执行适配、能力说明与上层改动，并在实际可记录时统计适配或调优工作量。用这些材料分别回答能否完成新服务、复用了什么、原服务是否保持。
- **待讨论**。固定流程对照是否由“尝试比较”明确为拟开展的小规模实验，联合更新消融是否作为独立对照，以及正文需要交代到哪一层。公开基准继续按任务、本体和接口的匹配程度选用。公开任务的评分口径与本项目的完成判据分别维护。

## 3. 桌面物品整理的进入条件与备选

- **评审意见**。说明桌面整理的可达与放置条件，并明确首期入篮已有的能力及扩展需增加的能力。
- **建议采纳的理由**。桌面改变工作空间、视角和放置约束。先检验停靠后能否同时观测目标、抓取并到达目标放置位置，才能判断整理失败究竟来自平台条件、执行能力还是任务规划。首个预计扩展方向仍沿用现稿的桌面物品整理，第六节保留“在新条件下”的强调。
- **建议写法**。第五节简要写明桌面整理依赖观测、抓取和放置条件的预验证。可以用不同目的地检验 Agent 是否按要求选择放置位置，具体用例数量由设计需要确定。若桌面条件受限，可在已经验证的工作空间保留“按整理要求选择目的地并定点放置”作为备选。将已有技能组合复用与新增能力接入作为两类可能出现的实验结果，分别报告。
- **待讨论**。备选写到什么程度，以及何种差异算作新增执行能力。例如，首期入篮若只支持已知容器位置，整理可研究能否向技能传入不同的目的地并完成受约束放置。最终以实际接口与能力测试界定。

## 4. 第一、二节的需求推导与措辞

- **建议采纳的部分**。第一节补强两类变化与两项目标之间的关系。任务执行中用户要求、环境或结果变化，引出依据环境与执行反馈持续调整。用户提出当前能力难以支持的新服务，引出能力适配、接入与复用。两条关系比单独依赖生态分散的判断更能解释项目为何选择相应的机制。“强大能力体现”和第二节的“完备 Agent 层”可改用现有的具体职责表述。
- **范围与理由**。保留第一节已有的调研范围限定及“现有生态还不够集中”的判断。第三节的代表工作比较为这项判断提供具体依据。同一平台上的验证安排属于第五节的论证内容，可在开篇点明研究目标与价值。
- **待讨论**。如何融入现有背景段和五项目的，避免重复已有的任务变化例子。

## 5. 第三、四节的先例与设计贡献

- **第三节**。保留现有展开及 MAESTRO、HALO、RoboDojo、RobotAgentBench 的位置。MAESTRO 的相近任务、VLA 工具对照和工具库消融分别交代，第三节介绍已有结果和验证范围，给第四节提供比较依据。
- **第四节**。建议为每项创新保留一处最能解释设计取舍的比较。技能专家项说明能力边界、使用说明、执行适配与反馈怎样配套。环境认知项保留实例关联与位置推断相互提供线索、分别保留不确定性的论证。整体架构项说明持续更新的环境服务、事件驱动 Agent 层和异步技能执行如何分工，Agent 使用两类中间层能力，各层共同形成整套系统。
- **理由与待讨论**。技能封装、动态记忆和任务编排均有近邻先例。第四节需要说明具体设计组合预期产生什么作用，第五节说明怎样检查。待逐项选择比较对象与一句最有辨别度的差异表述，避免把整个研究现状再写一次。

## 6. 第六节的进度与第五节的分工

- **建议保留现有形式**。第六节继续采用时间列表，阶段工作和关键目标随条目交代。成功判据、对照方法、进入条件、备选路线和可提交材料继续由第五节展开。评审希望更容易检查阶段进展，可通过具体的工作目标回应。
- **阶段重点**。3—5 月以二维建图、地面物品等较简单的条件开展仿真验证与真机联调。6—9 月推进三维感知与建图在环境认知服务中的应用，完善三维环境中物体及其空间关系的表达与更新。10—12 月预计从桌面物品整理开始验证服务扩展。阶段文字体现工作重心，三维方案研究可以提前展开。

讨论顺序建议为成功判据、三组对照、桌面整理条件、第一与第二节表述、第四节近邻比较，最后检查第六节是否需要简短承接。
