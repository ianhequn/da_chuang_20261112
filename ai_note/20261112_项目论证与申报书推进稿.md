# 项目论证与申报书推进稿

> 用途：在正式扩写《立项依据.md》前，收敛项目逻辑、范围和论证依据。本稿供讨论和迭代，不替代申报书格式文件。

## 一、项目主张

### 暂定项目定位

面向家庭服务场景，探索一种融合现代 Agent、具身智能技能与环境语义地图的可扩展移动操作机器人技术架构，并通过家庭物品寻找与取回任务开展仿真和真实平台验证。

本项目以现有 Agent 引擎、具身模型、导航和感知技术为可组合能力，研究重点放在跨模块的系统架构、技能组织、环境状态支撑、事件驱动任务执行和工程化验证，不以训练新的具身基础模型或从零重做成熟底层算法为目标。

### 项目名称候选

**第一版确定：融合语义地图的 Agent 驱动具身移动操作机器人可扩展通用架构研究**

标题中“具身移动操作机器人”描述研究对象，不表示项目研究广义具身智能或训练具身模型；“融合语义地图”指在系统和任务层使用地图信息支持 Agent 决策；“可扩展通用架构”强调技能、模型、硬件和任务可替换、可扩展，具体范围由研究内容和验证实验界定。

## 二、问题背景与项目切入点

移动操作机器人需要同时处理环境理解、任务规划、底盘移动和机械臂操作。现有生态已分别提供 SLAM/Nav2、开放词汇和对象级语义建图、VLA 等具身模型、机械臂规划及 Agent 工具调用框架，但这些能力的接口、状态表达、任务生命周期和失败恢复通常分散在不同组件中。将单项能力放进机器人并不自动形成可持续运行的任务系统。

本项目的切入点是研究如何把这些现有能力组织为具有清晰职责边界和替换接口的系统：环境语义地图提供可查询、可更新的空间与物体线索；技能专家把导航、视觉搜索、具身抓取等能力封装为任务可调用单元；Agent 根据用户目标、地图信息、技能结果和环境事件持续编排长程任务；ROS 2 与硬件层承担机器人基础运行和确定性控制。

## 三、拟解决的核心问题

1. **异构机器人能力如何被统一组织和替换**：不同导航、感知、抓取和具身模型能力如何描述前置条件、输入输出、运行状态及失败结果，使上层任务流程不绑定某个模型或设备实现。
2. **Agent 如何依托环境状态完成长程任务编排**：如何将用户目标分解为可执行技能，并通过事件、技能反馈和记忆处理目标位置不确定、执行失败和重新搜索等情况。
3. **环境语义信息如何支持移动操作任务**：如何组合几何地图、简单区域语义和物体实例的概率性位置记录，为搜索顺序、目标确认和任务后更新提供依据。
4. **系统架构如何通过仿真到真实验证其有效性**：如何在 MuJoCo 仿真和第一代真实平台上建立可比较的任务闭环，并通过更换目标物品、区域或技能实现验证可扩展性。

## 四、总体架构与术语

```text
用户目标与交互
      ↓
Agent 任务规划与事件驱动运行时
      ↔ 家庭环境语义地图
      ↓
技能专家层：导航 / 视觉搜索 / 具身抓取 / 放置 / 其他技能
      ↓
ROS 2 支持层：定位、导航、传感器与设备接口
      ↓
移动底盘、机械臂、相机与控制器
```

- **Agent**：暂定使用 Pi Agent 作为引擎候选，负责自然语言目标理解、长程任务编排、工具调用、上下文和记忆；不直接承担电机级控制与安全闭环。
- **技能专家**：统一抽象机器人可调用能力。具身模型（例如 VLA 类模型）是技能专家的重要来源之一，也可以接入传统算法、运动规划器或专用服务；本项目研究其组织和调用方式，不训练新基础模型。
- **家庭环境语义地图**：机器人侧维护的空间与物体状态信息，不使用容易与具身模型中的“世界模型”混淆的简称。包括几何空间、区域标签、物体类别和实例、概率性位置、观察时间及置信度。
- **事件驱动运行时**：接收技能完成、失败、超时、环境变化和用户新指令等事件，决定是否继续、重试、改换候选位置、请求用户协助或结束任务。

## 五、语义地图范围

语义地图利用已有 SLAM、检测、分割、对象级建图和跟踪技术，不以提出新 SLAM 或全新开放词汇建图算法为目标。

1. **几何与空间**：采用成熟 SLAM/Nav2 地图和坐标关系，支持定位、可达区域和导航目标表达。
2. **区域用途**：先以用户标记或配置文件记录“厨房”“书房”等区域名称和对应范围，之后再考虑更完整的自动语义划分与地图管理。它是必要的系统信息，但不是首要算法研究难点。
3. **物体语义及实例位置**：记录类别、可用外观特征、最近观测区域/位置、时间、置信度和历史关联。第一年限定若干目标物品，采用概率性实例关联，输出候选位置和置信度，不承诺始终准确识别同一实例。

地图服务对 Agent 提供诸如“查询目标物品候选位置”“按区域列出近期观察到的物品”“记录一次新观测”等稳定接口。实现可先使用轻量数据结构或 JSON，再依据验证需求替换内部存储和感知组件。

## 六、首个验证场景与通用性边界

### 验证场景

第一代机器人验证有限目标集合上的家庭物品寻找与取回：地图保存若干物品的近期观测和候选位置；用户提出取回目标后，Agent 查询地图并选择搜索区域；机器人导航到区域、通过视觉技能寻找目标；具身抓取技能将目标放入篮子；机器人返回用户身边并更新物品位置和任务状态。

该场景集中验证环境状态、Agent 决策、多个技能协作、移动操作和任务恢复之间的闭环。使用篮子作为交付容器，可减少第一年对复杂递交动作和人机接触安全的依赖。

### 防止场景过拟合

- 物品、区域、搜索顺序和交付位置使用数据或任务参数表示，不写死在任务逻辑中；
- 任务编排调用能力接口，不直接绑定 SmolVLA、某种导航栈或某个感知模型；
- 通过替换目标物品、候选区域和至少一种技能实现进行复用测试；
- 垃圾识别、拖鞋归位、收纳及更复杂的家庭任务作为后续扩展方向。

## 七、研究内容与相互关系

1. **面向移动操作的技能专家接口与系统分层设计**：定义能力描述、调用生命周期、结果表达、取消和错误处理，明确 Agent、地图、技能、ROS 2 与硬件职责。
2. **面向 Agent 决策的家庭环境语义地图**：整合几何地图、用户标记区域和物体实例概率性位置，支持查询、更新和历史记录。
3. **基于 Agent 与事件驱动机制的长程任务编排**：研究如何根据用户指令、地图候选、技能结果和环境事件选择技能、调整计划、恢复失败并完成任务。
4. **MuJoCo 到真实平台的系统验证**：搭建模拟闭环后逐步接入真实移动底盘、视觉和 SmolVLA 六自由度机械臂控制，测试任务完成和模块替换能力。

四项内容的逻辑关系为：接口和分层提供系统骨架，语义地图提供环境状态，Agent 组织技能完成长程任务，仿真与真实实验检验整体方案。

## 八、创新点论证方向

以下是待用对比材料和实验结果支撑的论证方向，不应直接当作已经证明的结论：

1. **面向家庭移动操作的 Agent—技能专家协同架构**：将现代 Agent 的长程任务编排能力与可替换的具身模型及传统技能结合，使系统能力不被单一专家模型或固定任务流程限定。
2. **面向任务决策的家庭环境语义状态组织**：将几何空间、区域语义、物体实例候选位置和观测历史统一为 Agent 可查询和更新的信息接口，支持不确定物品位置下的搜索决策。
3. **可扩展架构的仿真到真实验证方法**：以统一任务和技能接口连接 MuJoCo 验证环境与真实移动操作平台，并通过目标、区域和技能变化测试架构复用性。

论证时应把“新颖的架构组织方式”和“验证证据”作为重点，不能仅以使用了 Agent、VLA 或语义地图本身作为创新依据。国内外现状调研还需确认相似工作，之后再决定创新点强度和措辞。

## 九、一年期里程碑草案

具体月份可按正式立项起止日期调整。每阶段要求有可演示、可检查的交付物，并设置真机进度风险下的替代路径。

| 阶段 | 主要工作 | 可验收交付物 |
|---|---|---|
| 第 1—2 月：需求与接口冻结 | 收敛任务范围；定义地图对象、技能接口、任务状态和事件；确认测试指标与安全边界 | 系统方案、接口说明、测试用例、可运行的模拟技能调用样例 |
| 第 3—5 月：仿真系统闭环 | 在 MuJoCo 场景中接入移动底盘/机械臂模型、有限物品和区域；实现地图查询、Agent 编排、异步技能执行及失败恢复 | 可重复运行的仿真演示；多物品、多区域测试记录 |
| 第 6—8 月：真实模块集成 | 完成真机底盘、定位导航、视觉搜索和机械臂抓取接口适配；先分别验收，再联调 | 各真实模块测试记录；受控环境下的部分或完整取回流程 |
| 第 9—10 月：闭环与扩展验证 | 完成真实“搜索—抓取入篮—返回”闭环；改变目标物品、区域或技能实现做复用测试 | 完整演示视频/日志；成功率、失败类型和扩展测试数据 |
| 第 11—12 月：总结与申报成果 | 修复主要问题，整理对比实验、架构文档、论文/报告和演示材料 | 项目总结、技术文档、实验数据及申报承诺成果 |

**风险替代路径**：若真机底盘或机械臂联调延迟，完成 MuJoCo 全流程并在真实平台分别验证导航与抓取子流程；申报目标应区分“核心验收”和“争取完成”，避免将硬件调整风险全部转化为项目失败。

## 十、评价指标草案

指标应围绕系统主张设计，优先采用可重复统计的任务级指标：

- 仿真和真实平台的端到端任务完成率；
- 物品候选位置 Top-k 命中率或搜索成功率；
- 语义地图更新前后的位置和实例关联质量；
- 技能调用成功率、任务恢复成功率和失败原因分布；
- 更换物品、区域或技能实现后的任务流程复用情况；
- 从仿真接口迁移至真实模块所需的适配工作量或接口改动范围。

当前不预设数值门槛。先设计实验协议、测试次数、基线和统计口径，再结合现有设备能力确定目标值。可以比较固定脚本流程与 Agent 事件驱动流程，也可以比较无历史地图线索与有概率位置线索时的搜索效率。

## 十一、研究现状调研任务

后续调研围绕申报论证需要，避免只罗列项目：

1. 家庭移动操作机器人及开源平台：比较硬件形态、任务范围、软件架构和真实场景能力；
2. Agent 与机器人技能调用：关注长程任务、多技能协调、异步执行、错误恢复和安全边界；
3. 开放词汇对象级语义建图与物体跟踪：关注已有能力、实例关联限制、长期状态维护和查询接口；
4. 仿真到真实移动操作：关注 MuJoCo 与 ROS 2/真实设备衔接及其适用范围；
5. 找出相近系统仍未解决的工程问题，并据此校准创新点，而非预先宣称“国内外空白”。

参考材料起点包括 ConceptGraphs、Kimera、RTAB-Map、Mobile ALOHA、TidyBot、OK-Robot、LeRobot 和 Pi Agent。引用时需要回到论文、官方文档和代码仓库核实版本与实际能力。

## 十二、需要继续共同决策的事项

1. 项目名称从三个候选中选择，并确认是否在标题中限定“家庭服务”；
2. 首个闭环的用户交付定义为“放入机器人携带的篮子并返回用户”，还是要求机器人把篮子/物品交到用户手边；
3. 第一年最低真实验证要求：必须完成完整真机闭环，还是允许“真机导航 + 真机抓取子流程”作为核心验收、完整联动作为争取目标；
4. 首批目标物品的数量、类别差异、摆放区域和环境复杂度；
5. Pi Agent、MuJoCo、SmolVLA 等具体实现是否写进申报书正文，或以候选实现为主、保留替换空间；
6. 团队人员分工、硬件条件、指导教师支持和预期成果清单；
7. 调研与基线测试后，为任务成功率、搜索效率和技能恢复率设定可信目标值。

| 申报书章节 | 主要输入 |
|---|---|
| （1）研究目的 | 项目主张、场景需求、核心问题和总体目标 |
| （2）研究内容 | 第七节四项研究内容及其依赖关系 |

| （5）技术路线、拟解决的问题及预期成果 | 总体架构、首个场景、研究问题、指标与交付物 |
| （6）项目研究进度安排 | 第九节里程碑，按正式起止日期校准 |
| （7）已有基础 | 现有 Nav2/URDF、真机进展、SmolVLA 概念验证、代码与团队条件 |

在第十一节调研、十二节关键决策和现有基础证据补齐前，先不把创新性结论、量化目标或真机交付承诺写成确定事实。

## 十四、后续推进任务与顺序

### 任务 1：冻结项目目标与边界

共同确认项目面向的问题、总体目标、首个验证闭环、系统通用性的定义，以及本项目不承担的算法和硬件研发范围。

**完成标志**：可以用一段话说明“项目要解决什么、通过什么系统方法解决、用什么验证”，并且项目目标与首个场景、研究内容和一年周期一致。

### 任务 2：把架构拆成研究内容和可交付模块

逐层确认 Agent、家庭环境语义地图、技能专家、ROS 2/硬件接口的职责、输入输出、依赖关系和风险。区分“采用的成熟组件”“本项目的集成与研究工作”“未来可扩展方向”。

**完成标志**：形成一张架构图和研究内容分解，每一项有明确输入、输出、负责人/依赖及验收方式。

### 任务 3：开展相关工作对照调研

从开源平台和论文中选取代表系统，按系统架构、Agent 使用方式、语义地图、具身技能、任务闭环和真实验证建立对比。重点找真实差异和未覆盖问题，不以罗列项目名称代替现状分析。

**完成标志**：有可追溯来源的对比表和现状综述提纲，可以说明本项目继承什么、组合方式有什么特点、仍有哪些限制。

### 任务 4：校准创新点和验证假设

将“Agent 驱动”“语义地图融合”“可扩展通用架构”分别变成可检验假设，设计基线、变量和指标。例如比较有无历史物品线索时的搜索效率，比较事件驱动编排与固定脚本对异常恢复的表现，并测试替换物品/区域/技能后的复用程度。

**完成标志**：每个创新点都有对照对象、实验步骤、数据指标和可能的负面结果解释。

### 任务 5：校准一年期技术路线、里程碑和风险预案

依据现有 Nav2/URDF、真机底盘进度和机械臂概念验证安排 MuJoCo、模块级真机验证、端到端联调和总结阶段。把最低验收目标与争取目标分开，明确设备、人员和时间风险的替代路径。

**完成标志**：每阶段有时间范围、前置条件、可展示交付物和未达成时的替代结果。

### 任务 6：补齐团队基础与资源条件

整理已有代码、平台、实验记录、指导资源、团队成员能力、设备和预算需求，并核验哪些陈述有实际证据支持。

**完成标志**：申报书“已有基础”和“条件保障”可用事实支撑，所有缺少条件都有解决方案或降级方案。

### 任务 7：按原七项格式扩写立项依据

将前六项工作结果映射到现有格式，先形成内容完整的初稿，再做逻辑、篇幅和申报语体修订。保持《立项依据.md》的章节骨架不变。

**完成标志**：七个章节相互一致，研究现状能支撑创新点，技术路线能支撑目标，进度能支撑预期成果，已有基础能支撑可行性。
