# 黑盒式项目技术讨论

> 本段引用块为本文件说明，用户手写，请勿删除。用户开启一个新会话，在有限信息下，尝试通过询问用户的方式讨论技术可行性，以了解技术路线，并在本文件写入完整但精炼的足以支撑项目的技术论断。

## 技术路线

### 1. 讨论依据与项目定位

本项目针对真实场景中多样化、非预设任务需求，研究具有一定通用性的机器人系统方案。当前调研判断是相关能力和应用方案较分散、生态不够集中；这属于项目背景判断，尚未在本会话中通过系统性行业调研独立验证。

系统从通用角度组织任务，不以若干预设任务类别定义整体架构。通用性一方面来自现代 Agent 的理解、记忆、推理判断、交流与长程任务组织能力，另一方面来自技能专家的接入、组合和替换。设计思路是将不同任务纳入统一的任务概念，由 Agent 将目标组织为可用技能能够执行的工作；技能集合能否覆盖任务需要是任务能否完成的重要因素。这里并不据此断言任意现实任务都已可解，或只要技能覆盖便必然成功；任务组合、状态依据和执行衔接仍需形成相应技术论证。

首期通过受控室内、有限物品集合下的寻物取回任务，检验架构下的系统闭环。后续接入新技能（包括不同具身模型等），验证扩展能力范围内的新任务支持。具体任务是检验通用设计的实例，不是对整体任务范围的永久限定；不同阶段的评价重点可以不同。本会话不以展开评估方案为主线。

机器人与用户交流是系统应有能力。项目后期扩展还考虑自主发现任务，例如发现拖鞋需要摆放整齐；该扩展的具体机制尚未展开。

本记录依据用户提供的申报书、架构草案及后续口述整理。草案可能包含非用户原写内容，均允许随后纠正；以用户后续澄清为准。助手的职责是通过询问了解已有设计，结合必要的网络核查，整理足以支撑技术可行性的机制、条件与证据，不替用户重新制定项目，也不将团队资源或执行能力评估作为主线。

### 2. 总体架构与职责

当前架构分为五个功能层：

| 功能层 | 主要职责 |
|---|---|
| Agent 层 | 理解用户目标、交流、维护任务上下文、组织长程任务、查询环境、调用技能并依据事件持续决策；不承担电机级控制及实时安全闭环。 |
| 环境语义地图层 | 统一维护空间、区域、物体实例、观测历史及相关不确定状态，提供查询与更新服务；在同一系统中处理概率性实例关联与位置推断。 |
| 技能专家层 | 封装导航、视觉搜索、具身操作、运动规划等任务能力，承接调用和执行；具体模型及算法运行由技能内部负责。 |
| 机器人支持层 | 通过 ROS 2、Python、设备 SDK、仿真等连接定位、导航、感知、规划与设备控制能力。 |
| 硬件层 | 提供移动平台、操作机构、传感器、执行器、计算设备和实时控制器。 |

胶水机制贯穿层间及层内封装，不单列为第六个功能层。技能既可访问环境服务，也可向其提交观测及确认后的执行结果；环境状态由环境服务维护。地图与技能分别通过相应接口使用机器人支持能力。Agent 不直接依赖底层地图数据库、具体模型或设备私有接口。

申报书中的六个研究板块分别为技能专家、环境语义地图、Agent 层、胶水通信、软硬件平台、仿真到现实调优与实验评估。研究板块划分与五层功能架构不是同一维度，不应混为一谈。

### 3. Agent 层：预计基于 Pi Agent

用户预计采用 Pi Agent。选型理由是其极简、先进、以“会话”为一等公民的特点；相较 LangChain 可能更适合本项目机器人场景，目前属于设计者的选型判断，尚未在本会话中开展对比核查。

用户提出的相关参考包括：RoboHarness 采用现代 Agent，使用 Codex/Claude Code 等，但具体设计与本项目不同；OpenClaw 使用 Pi Agent SDK。以上项目关系及 Pi SDK 能力目前均为用户提供信息，尚未独立联网核实，也不能直接作为本项目整机可行性的证明。

Agent 通过终端工具调用技能 CLI，结合相应 skill 理解能力范围和使用方法。Agent 层设有事件驱动主程序，接收执行相关事件并通知 Agent；Agent 也可通过 CLI 主动查询。

机器人通常以一个持续会话运行。通过 instruction 等提示词注入，指导 Agent 维护记忆文件，并使用支持 RAG 的向量数据库实现关键内容的长期记忆。设计将长期运行中的自动上下文压缩视为必然发生的过程，因此不把当前上下文作为关键内容的唯一保存位置。具体记忆内容、写入与检索机制，以及压缩后的恢复方式尚待展开，向量数据库产品尚未选定。

主会话管理小会话、使用专注于某些工作的 Agent 实例，是允许后续研究的扩展方向，不作为首期已经确定的多 Agent 设计。执行事件与当前会话、任务状态和记忆更新的具体关联仍待进一步了解。

### 4. 技能接入：封装程序、调度后端、异步 CLI 与 skill

以能够抓取小木块的 SmolVLA 为例，当前设计链条为：

```text
技能能力范围及 CLI 用法 → 编写配套 skill → Agent 理解能力与调用方法
Agent 终端工具 → 异步 CLI → 网络请求 → 技能专家层调度后端
→ 调用封装好的模型或程序 → 执行状态与结果
→ 相关事件送入 Agent 层事件驱动主程序 → 通知 Agent 继续决策
Agent 也可通过 CLI 主动查询执行情况
```

各部分职责如下：

- **封装程序**：承接具体模型、算法或机器人软件的调用，将能力实现置于技能内部。
- **调度后端**：接收网络请求并调用已封装程序；预计可能使用 FastAPI，框架尚未最终确定。后端还需处理技能部署在不同主机的情况，例如 VLA/WAM 使用独立推理服务器。具体路由、进程和部署组织方式尚未展开。
- **异步 CLI**：封装网络请求，为 Agent 终端工具提供命令行操作入口；同时支持主动查询。具体命令、返回格式及异步任务协议尚未确定。
- **配套 skill**：根据技能专家的实际能力范围编写，其中包含 CLI 使用方法。此处 skill 是面向 Agent 的能力与使用说明，须与提供执行能力的“技能专家”区分。
- **人工测试面板（可选）**：可以提供网页程序，供人工操控和单独测试技能的可用性与能力边界，不必把每次技能测试都绑定整机 Agent 任务。

这套分工给出了将不同执行实现接入 Agent 的技术路径：Agent 使用说明与 CLI，后端屏蔽具体程序调用及部分部署差异。能否保持上层任务组织复用，还需进一步明确技能描述、输入输出、任务状态与实现替换时的接口约束，并通过相应接入验证支撑。

### 5. 异步执行与事件驱动

寻物过程目前预期由 Agent 先向导航技能发送指令，到达后再组织寻找。寻找时，可以由 Agent 操作相机姿态，也可以调用预设查找动作（通常也封装为技能专家）；更先进的搜索方案属于项目研究内容。具体采用或组合哪些方式，依据后续实际情况决定，不预设整个寻找过程必须封装为单一技能，也不将当前举例固化为最终接口或算法。这里的 Agent 操作相机姿态不等于承担电机级实时控制，具体调用接口尚未展开。

系统采用任务请求与事件反馈结合的运行方式。根据已有架构草案，技能接口需要表达用途、输入输出、适用条件或前置条件、执行状态、结果、失败原因及取消方式；异步任务公共机制需关联提交、执行、查询、完成、失败、取消和超时等过程。

用户说明 Pi Agent SDK 自带事件驱动框架。最终复用 SDK 内置机制，还是使用主程序自身的事件系统，或如何衔接，需依据实际情况研究决定；不能提前断定 SDK 内部事件已能直接承担全部机器人外部任务事件。

事件来源及接入方式可以包括 HTTP 请求、UDP/TCP 监听、SSE、WebSocket、定时器等，具体按实际决定。这些是候选接入或传输方式，尚未选定统一协议；传输方式与任务状态、事件处理语义应分别明确。

用户新指令、技能完成或失败、环境变化等均可驱动后续决策。执行中事件如何进入会话、Agent 忙碌时如何处理、新要求如何作用于执行中任务，以及取消后的实际状态确认等，尚待继续了解设计。

### 6. 环境认知服务与平台衔接

环境认知服务按三个层次组织，以下名称为用户粗略描述，尚非正式术语定稿：

| 层次 | 当前设计与实现基础 |
|---|---|
| 几何 | 使用 SLAM 处理几何空间关系，可采用 2D 栅格地图、3D 点云地图等。用户已使用 slam-toolbox 的终身建图方案；后续可能使用 RTAB-Map 处理更复杂问题，并未确定必须迁移或必须采用 3D。 |
| 区域语义 | 表达区域及其用途，例如“房间 A 是厨房”。首期由用户设置即可；具体方案在几何与物体语义优先处理后再确定。后续可扩展为用户未设置时由机器人识别、猜测，直到用户设置，不把自动区域识别列为首期前提。 |
| 物体语义 | 重点是概率性物体实例关联与概率性物体位置推断，回答“物体可能在哪里，概率是多少”“当前物体 A1 是否是昨天的物体 A0，概率是多少”等问题，不要求很高的追踪精度。 |

用户提供的参考方案为 [ConceptGraphs](https://github.com/concept-graphs/concept-graphs) 与 [Kimera](https://github.com/MIT-SPARK/Kimera)。当前仅记录其作为设计参考，不表示已决定直接采用，也不表示本会话已核实其具体能力。

感知输入包括 RGB 相机、深度相机，也可能包括激光雷达。用户判断一般室内场景采用深度相机即可满足本项目精度需求，并指出 RTAB-Map 支持相关方案；具体适用条件及软件支持尚未在本会话独立核查。首期可能继续采用 2D 雷达与深度相机，并将物体放置在地面，以降低早期实现难度，使环境认知研究优先聚焦整体逻辑及几何、区域语义、物体语义三层组织的可行性。这是阶段性验证条件，不是整体架构仅支持地面物体的限制。

实例关联与位置推断是项目重点研究内容，尚未确定最终算法。用户不希望分别建设两套独立系统，但允许两个问题使用不同方法求解；应在同一环境认知服务中共享观测历史并组织推断。每次观测视为一帧，多帧形成历史数据，作为分析依据。“帧”的具体数据字段、坐标及跨传感器组织方式仍待研究。

用户列举的候选研究路线如下。此表保留探索范围，不将其视为全部必须采用的模块，也不据此声称各方法均能直接输出本项目所需概率：

| 方向 | 用户列举的方法或参考 |
|---|---|
| 贝叶斯滤波与随机有限集跟踪 | Kalman/EKF/UKF、粒子滤波、PHD/GM-PHD/GLMB |
| 数据关联、多假设跟踪与图优化 | Nearest Neighbor、Hungarian、JPDA、MHT、因子图/MAP、贝叶斯网络 |
| 深度跟踪与实例重识别 | DeepSORT、ByteTrack、BoT-SORT、ReID、Transformer、时空图网络 |
| 动态语义地图、场景图与时空记忆 | ConceptGraphs、3D/4D scene graphs、DynaMem、OpenIN、FARM、DAAAM |
| 先验、关系推断与学习式位置预测 | RNN/LSTM/Transformer、GNN、扩散式位置/轨迹预测、ECROM 类长期出现倾向 |
| 端到端视觉、视频与世界模型 | 时空 Transformer、视频模型、latent world model、神经场、NeRF/3D Gaussian |
| 视觉语言与具身模型 | VLM、VLA、开放词汇定位、具身问答、主动搜索、视觉记忆模型 |
| VLM/LLM/Agent 辅助推断 | 结合观测、地图、动作历史和用户陈述生成候选解释或位置假设，并用于回答用户；推测保留来源及“未确认”状态 |

研究可以从经典算法出发，也可以探索神经网络模型；具体选用或组合尚待深入研究。上表中的缩写、项目指代及适用性目前仅按用户列举记录，尚未逐项联网核查。

服务统一组织物体类别与实例、位置及状态、观测时间与来源。实例关联与位置推断在同一系统中处理，共享观测证据、状态表示与更新关系，并表达不确定性。Agent 与技能通过查询、观测提交和状态更新接口使用该服务。物体语义以面向任务的概率查询为目标，不额外加入高精度连续追踪要求。用户示例中的 0.71 仅用于说明返回形式，不是精度指标或已有测量结果；具体概率的定义、计算依据、观测处理与更新规则尚待询问。

平台工作包括底盘、机械臂、传感器、算力与控制器集成，ROS 2/SDK 适配，以及坐标变换、标定、时间同步和设备状态管理。仿真到现实工作包括模型与技能部署、按所选方案需要进行的数据采集和训练或微调，以及从单项能力到整机的逐步联调。具体实现路线仍需向用户询问。

### 7. 操作能力的应用、适配与调优路线

首期拟在已有 SmolVLA 抓取小木块概念验证基础上继续优化，包括改善相机布置、使用更好的数据集，以及优化运行过程中的整条链路。具体链路环节与调优方法尚未展开，不把这些预期改进写为已获得的效果。

用户提出 EVO-1 为另一候选，认为其也是较轻量的 VLA 模型，性能可能略好；扩展范围拟尝试 pi 系列、lingbot-VLA2.0 等系列模型。这里的 pi 系列是操作模型候选，不与 Agent 层的 Pi Agent 引擎混同。也可以试用 ACT；用户判断其难以满足任意物品抓取的期待。上述名称按用户提供记录，模型身份、版本、轻量程度、相对性能及泛化边界尚未在本会话联网核查，不据此作定论。

后续需要支持针对不同目标的执行方案，并研究已有 VLA/WAM 等成果在开放词汇物体任务上的应用。项目重点是已有模型与方案的应用、适配、调优和技能化接入，不是研发新模型。开放词汇物体任务的效果是需要进一步研究与核查的方向，不将候选模型等同于已经能够可靠抓取任意物品。

### 8. 现有证据与可行性论证边界

用户报告已实现：

1. SmolVLA 抓取小木块的仿真到真机概念验证。
2. ROS 2 Nav2 下发目标点并成功导航。

这些结果支持相应平台条件下的部分操作能力、导航能力及相关部署路径，不自动证明环境认知、Agent 编排、跨技能组合、分布式异步任务或整机闭环已完成。本会话未读取实验文件、代码或日志，不擅自补充未提供的成功率、场景范围和性能参数。

后续论证按“技术主张—实现机制—依赖条件—支撑证据—待验证项”组织：已实现、预计选型、候选实现和未知事项分别保留其身份。通过询问和必要联网核查补齐关键链条，发现缺口如实记录，不能预设所有主张已经成立。

## 待讨论与核查事项

本项目处于立项阶段，技术可行性论证应区分已确定的架构关系、具备实现路径的机制与拟开展的研究；不要求用户预先给出全部研究结果或最终算法。后续提问优先了解已有设计及其依据，避免反复追问已明确留待研究的实现细节。

1. 技能相关事件进入 Agent 会话和触发继续决策的具体方式，尤其 Agent 正在推理或执行工具时的处理。
2. 技能后端提交、执行、返回和主动查询的生命周期，以及任务标识和状态由谁维护。
3. 在共享逐帧观测历史的环境认知服务内，研究实例关联与位置推断的候选方法及组合；进一步明确概率含义、证据来源与更新关系，不拆成两套独立系统，不附加高精度追踪要求。
4. 根据回答定向核查 Pi Agent SDK 等相关官方资料；避免将 SDK 名称或其他项目采用关系替代关键机制验证。
5. 记忆文件与向量数据库各自存储哪些内容、何时写入和检索，以及上下文压缩后如何恢复关键内容。
