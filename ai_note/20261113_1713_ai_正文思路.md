# 申报书正文（立项依据）思路草稿

我希望整份申报书按照“为什么做——做什么——别人做到哪——我有什么不同——具体怎么做——难在哪里——最终交付什么——何时完成——凭什么能做”的逻辑展开。

这里记录的是各章节之间的思考方式和论证关系，不是对全文内容的压缩提纲。具体内容仍需要结合技术调研、项目边界、团队基础和后续讨论逐步形成。

## （1）研究目的

这一部分主要回答“为什么做”和“总体上准备研究什么”。

首先，需要对当前机器人技术发展作背景概括：随着移动机器人、具身模型、Agent、语义地图和相关软硬件生态不断发展，构建移动操作机器人所需的技术储备正在逐渐丰富；但从整体应用角度看，面向通用移动操作机器人的系统化、分层化工程方案仍然比较分散。

在此基础上，说明本项目的总体研究目的、项目目标和边界，回答项目准备研究哪些问题、哪些部分，以及为什么选择这些问题。团队技术认知和技术水平跟上具身智能与机器人技术的发展，提升实际工程落地、系统集成和具身技术调优能力，也可以作为项目的重要培养价值和预期收获，但不应取代项目本身的研究目标。

项目目标与边界可以展开说明，但正式申报书中需要控制篇幅，将重点放在“构建融合语义地图的 Agent 驱动具身移动操作机器人可扩展通用架构，并通过家居环境中的代表性任务进行验证”这一主线上。

## （2）研究内容

研究目的更多是在总体上说明项目瞄准的问题和目标；研究内容则应进一步说明，围绕这些目标，项目具体准备研究哪些部分。

这一部分需要讲清楚“研究什么”，但不必在这里展开所有具体实现步骤，也不应只是把软件模块名称逐项列出来。例如，可以研究如何将导航、视觉搜索、具身模型、运动规划等能力抽象成“技能专家”，为 Agent 提供统一、方便调用的接口；也可以研究如何在技能专家层中规范具身模型的能力描述、输入输出、任务状态和失败结果。

研究内容应该体现各部分之间的关系：通用分层架构提供系统骨架，技能专家提供可组合能力，语义地图提供环境状态，Agent 负责长程任务编排，胶水机制负责接口和事件连接，最后共同支撑任务闭环验证。

## （3）国内外研究现状和发展动态

这一部分与研究目的中的背景概括不同。研究目的中的背景是为了说明项目为什么值得做；这里则需要更具体、更真实、有来源地说明国内外相关技术已经发展到什么程度，以及已有方案采用了什么技术路线。

可以围绕以下方向展开调研：

- 已有移动操作机器人及其技术路线；
- 机器人分层架构、系统工程化和模块化接口；
- Agent 驱动的任务规划、工具调用、记忆和多技能协同；
- SLAM 建图、环境语义地图和物体实例跟踪；
- 各类具身控制方案，包括 VLA、视觉动作模型、世界模型及相关动作生成方法；
- 视觉模型与深度学习、强化学习、传统控制和运动规划的结合；
- 多技能专家的组织、路由和失败恢复。

具身控制方案还可以进一步关注 VLA、VA、WAM、WM 等不同方向，以及 JEPA 系列、预测与动作序列联合推理、视觉模型结合抓取和规划等有代表性的成果。但这些内容需要服务于本项目的系统论证，不能写成与项目主线无关的模型综述。

移动操作机器人方面，可以比较商业家居机器人、研究型平台和开源项目，重点考察它们是围绕某一产品任务、某一具身模型，还是围绕较通用的系统架构组织。最终需要形成的不是项目清单，而是一个判断：单项技术和模型已经提供了许多可用能力，但面向整体应用的分层组织、Agent 编排、环境状态和多技能协同仍然存在值得研究的空间。这个判断需要通过后续资料检索核实，正式写作时避免直接宣称“国内外没有类似方案”。

## （4）创新点与项目特色

创新点应当根据项目目标、现有技术现状和本项目的系统设计来凝练，而不是简单把使用到的技术名称列成创新点。

目前可以先用三个关键词概括：

- **通用性**：从通用移动操作机器人应用需求出发设计分层架构，而不是围绕某个具身模型、某项算法或某个特定任务构建系统；
- **Agent 驱动**：利用现代 Agent 的目标理解、工具调用、长程任务规划、记忆和事件响应能力，组织不同技能专家协同完成任务；
- **语义地图**：利用环境语义地图保存空间、区域、物体候选位置和历史状态，使 Agent 的决策能够基于持续更新的真实环境信息。

这三个关键词不是互相独立的功能堆叠，而是具有递进关系：通用架构提供能力组织骨架，Agent 驱动骨架完成长程任务编排，语义地图为 Agent 提供环境状态，三者结合后才使机器人具备面向真实场景需求的系统价值。

## （5）技术路线、拟解决的问题及预期成果

这一部分回答“具体怎么做”。需要说明整体架构如何连接、各部分技术起什么作用，以及项目将通过什么任务验证方案。

技术路线应包括完整任务闭环，例如：用户提出目标，Agent 理解任务并查询环境语义地图，选择和调用技能专家，机器人导航到候选区域并进行视觉搜索，具身抓取技能将目标放入篮子，机器人返回用户附近，最后根据事件结果更新任务状态和语义地图。

同时需要说明项目真正困难的地方，例如异构技能如何统一调用，Agent 如何利用环境状态进行持续决策，物品位置不确定时如何安排搜索，技能失败后如何调整任务，以及如何在仿真和真实平台中验证架构的可复用性。

最后说明预期成果，包括系统架构与接口设计、环境语义地图原型、Agent 多技能任务运行原型、仿真闭环、真实平台模块验证或完整闭环、实验数据、技术报告和演示材料等。

## （6）项目研究进度安排

这一部分说明项目如何在一年内完成。进度安排不应把调研、架构设计、原型开发和实验验证理解成完全割裂的阶段，因为它们之间存在持续反馈：技术调研会影响接口设计，原型验证会暴露架构问题，真实模块接入又会推动系统调整。

因此，进度安排应体现一个逐步收敛的过程：先同步推进总体方案和技术生态调研，再完成最小接口和原型，随后形成仿真任务闭环，逐步接入真实移动平台、视觉和机械臂模块，最后进行物品、区域或技能变化下的扩展验证，并整理项目成果。

## （7）已有基础

### 1. 与本项目有关的研究积累和已取得的成绩

- 已对机器人分层架构、Agent 层、技能专家、环境语义地图和胶水机制进行了可行路线探究与初步设计；
- 已具备第一版移动操作机器人硬件基础；
- 已建立较高可控性和较高效率的 MCU 控制固件及整体硬件搭建开发体系；
- 已完成 ROS 2/Nav2 导航仿真，并开展了真实平台上的基础导航验证；
- 已完成 SmolVLA 在真实六自由度机械臂上的控制概念验证；
- 已对 ConceptGraphs、Kimera、RTAB-Map、Mobile ALOHA、TidyBot、OK-Robot、LeRobot 和 Pi Agent 等相关技术路线进行初步调研。

### 2. 已具备的条件、尚缺少的条件及解决方法

已有条件包括硬件基础、MCU 固件开发能力、ROS 2/Nav2 仿真和导航基础、机械臂具身模型概念验证，以及可利用的开源技术生态。

目前仍缺少对部分前沿模型和系统的深入理解，团队成员的技术能力和研究倾向也存在差异。对此，可以通过分层分工、持续技术调研、模块化原型、阶段性交付和实验复盘逐步提升团队能力，并优先复用成熟组件，降低重复开发和技术风险。
