# 验证方案与评价指标

整理日期：2026-11-15。本文承接原《架构设计_temp.md》的验证任务与扩展原则，按后续讨论校准。它维护实验设计工作稿，不替代项目目标或研究内容；正文第五节给出申报表达，具体实验参数在本文件继续细化。

## 验证主场景

在受控室内环境和有限物品集合下，以寻找并取回物品为首期主场景：

用户提出目标 → 查询环境服务并选择候选区域 → 导航与视觉搜索 → 根据观测继续搜索、调整行动或请求帮助 → 抓取并放入篮子 → 返回用户附近 → 汇总结果并更新环境状态。

这一流程描述验证载体，不将系统限制为固定流程寻物机器人。抓取、放置和任务完成需有相应结果确认，不能用调用返回或夹爪释放代替物理结果。

## 一、首期阶段：体系运行与设计预期的检验

以受控室内环境、有限物品集合下的寻物取回为载体，评价已有能力的使用、持续响应、环境认知及整机协作。实验贯穿模型适配、模块验证、系统联调和闭环运行；闭环成功后继续开展重复实验、条件变化、方案比较及调优，不以一次成功代替效果评价。

| 评价方面 | 评价目的 | 观察与分析重点 |
|---|---|---|
| Agent 技能调用质量与效率 | 检验 Agent 能否依据任务与能力说明恰当调用已有技能 | 以人工通过相同接口操作为参照，比较技能选择、参数、调用次序、无效调用、耗时与结果，分析信息理解、能力说明及调用判断的影响 |
| Agent 决策与应对表现 | 检验 Agent 能否根据用户任务、环境状况与整机状态作出适当响应 | 在指令变化、目标未找到、技能失败等情况下，分析所用信息、响应内容，及继续、重试、调整、求助或终止的依据与后续效果 |
| 事件驱动运行机制的健康性 | 检验主程序能否持续承载 Agent，正确衔接事件、决策与物理执行 | 任务停滞、事件积压或遗漏、过时决策、状态不一致、重复执行、调度时序异常，以及持续运行与恢复表现 |
| 环境认知的响应与估计效果 | 检验物理变化能否被感知并适当反映到地图，比较候选方案 | 人工移动物体、遮挡、同类实例等条件下，对照真实记录分析实例关联、位置估计、更新延迟及不确定信息表达，并观察对搜索的影响 |
| 整机表现与改进效果 | 检验协作是否形成可重复闭环，局部改进是否改善整机表现 | 完整与分段成功率、耗时、干预、成功与失败分布；结合调优前后结果分析瓶颈、误差传播及各部分改善的作用 |

### 评价时的三个区分

- **人工参照与唯一答案**：人工操作不作为唯一正确流程。在相同接口、能力及可比条件下比较，记录双方可用信息的差异，允许多种合理做法，不直接把差异判为 Agent 错误。
- **决策适当性与运行健康性**：前者评价 Agent 的判断内容及行动效果，后者评价事件与执行的调度衔接。状态机或行为树的时序仅在采用相应机制时检查，不据此预设实现。
- **观测缺失与更新错误**：物体移动后未必立即可见，应记录变化、有效观测与状态更新的时间及条件，区分未获得有效观测、感知错误、关联或推断错误和更新异常，不要求不可见变化立即反映在地图中。

## 二、扩展阶段：能力接入与服务拓展的检验

预计从桌面物品整理开始验证服务扩展。以冻结的寻物取回版本实测已有技能在桌面整理中的覆盖范围，再按缺口适配或接入所需能力。记录执行适配、能力说明与上层改动，评价 Agent 的规划与技能调用、整理结果及原寻物取回任务的保持情况。

在首期体系基础上，依据进展选择扩展方向，评价接入和复用代价、新能力利用及服务范围的实际变化。以下为扩展评价范围，不将全部方向列为首期实验或本项目的全部交付承诺。

| 评价方面 | 核心问题 | 观察与分析重点 |
|---|---|---|
| 技能接入、替换与复用 | 新能力能否沿用已有体系接入 | 适配与调优工作、接口和说明修改、上层程序改动及组件复用 |
| Agent 对新增能力的使用 | 能否理解新能力并与原有能力适当组合 | 技能选择与参数、组合方式、能力边界判断，以及不会用、误用和协作失败的原因 |
| 服务范围与复杂任务表现 | 新能力实际支持了哪些新服务 | 新类别任务、更多技能组合及更长流程的结果、协调代价和新增失败模式 |
| 扩展后的稳定性与能力保持 | 是否影响原有系统 | 旧任务回归、资源及控制冲突、新增模块对持续运行的影响 |
| 平台与环境变化下的适配 | 哪些设计可以复用 | 重新标定、调优和适配工作量、上层复用及适配后的任务表现 |

首期任务本身需要多技能协作，不等同于扩展阶段持续接入更多技能、挑战复杂任务。两个阶段可以沿用部分指标，但评价重点及所支持的结论不同。

## 扩展与实验边界

物品、区域及技能实现变化分别支持不同层面的结论，不能合并为任意任务能力的证明。物品归位、整理等可作后续任务候选，具体纳入范围尚需按技能和平台条件确定。硬件升级通过适配保持上层接口，但仍需重新确认能力条件与任务表现。

仿真、模拟服务与真机承担不同检验任务；原“仿真先行”不作为全部工作的固定顺序。接口机制可用模拟服务测试，感知及物理执行需要相应仿真和真机实验，模型调优与整机验证相互反馈。

实验任务数、重复次数、对照版本、物品范围和验收阈值尚待确定，不将本工作稿写成已完成验证。
