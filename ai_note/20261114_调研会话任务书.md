## 二、项目当前主线与已讨论的决定

### 1. 面向的问题与总体目标

项目关注家居任务需求灵活多变与机器人预设服务范围之间的矛盾：希望机器人能够理解用户提出的不同目标，灵活组织感知、移动和操作能力，根据环境信息及执行反馈调整行动，并通过接入新技能持续拓宽服务范围。

这是一项面向实体家居机器人的系统研究与应用探索。分层架构是支撑上述能力的手段，不能将调研最终写成只讨论软件架构、接口或模块拼装。

任务组织不预先绑定单一类别，实际执行由可用技能、环境条件和平台能力支撑。“任意任务”表达的是任务组织的开放性追求，不能解释为已经能够完成任意家务，也不能据此删除对多样需求和跨任务扩展的关注。

### 2. 主要设计

- **Agent**：利用目标理解、工具调用、上下文和记忆能力组织长程任务，根据技能结果、环境变化及用户新要求持续决策；底层实时控制由执行模块负责。
- **技能专家**：将导航、视觉搜索、抓取、放置、规划等封装为可调用、可组合、可替换的能力。VLA、WAM 等具身模型是重要来源，此外还包含视觉模型、传统规划、强化学习策略、确定性程序及复合服务。
- **环境语义地图**：组织几何空间、房间/区域用途、物体信息与历史观测，提供查询和更新服务。物体语义同时包含**概率性实例关联与位置推断**：既要回答“现在的物体可能是之前哪一个”，也要回答“目标物体可能在哪里”。不用“World Model”称呼此服务，以免与具身世界模型混淆。
- **扩展设计**：探索技能、任务和硬件扩展时对已有上层组织机制的复用，不能直接假定新增一个技能就必然支持任意新任务。

### 3. 首期场景与范围

受控室内环境、有限物品集合下：用户提出取回目标 → 查询环境信息及候选区域 → 导航与视觉寻找 → 抓取入篮 → 返回用户 → 汇总结果并更新状态。

寻物取回是第一个验证场景，不能将整个项目缩减为专用寻物机器人。后续验证还应关注指令或执行条件变化下的任务调整，以及新增、替换技能后的能力与服务扩展。

项目基于现有技术生态进行应用、调优、封装、适配与系统研究，不以提出新的具身基础模型或从零研发 SLAM、导航、抓取基础算法为主任务。不要求覆盖全部家务或量产级长期自主运行。

### 4. 六个研究板块

1. 技能专家的构建、封装与应用。
2. 环境语义地图的整体设计与实现。
3. Agent 层事件驱动系统与能力接入。
4. 各层胶水与通信机制。
5. 机器人软硬件支撑平台的搭建与适配。
6. 模型与整机的仿真到现实全链路调优与应用。

这是按架构及跨层工作拆分的研究板块，具体范围见根目录《研究问题分解.md》。研究内容说明“研究什么”，技术路线进一步说明“具体如何做”。

## 四、重点调研任务

### 1. 优先比较相近的完整系统

围绕以下问题分析有代表性的国内外系统，而非只罗列技术与项目名称：

- 面向什么真实需求与任务，运行在什么机器人和环境上？
- 任务组织采用固定流程、显式规划、语言模型/Agent，还是其他机制？
- 用户能否提出不同目标、补充要求，系统如何处理失败和环境变化？
- 系统使用何种环境表示，是否维护物体实例、观测历史与不确定性？
- 执行能力由哪些模型或算法提供，能否接入、替换和组合？
- 已验证的是物品/区域变化、技能替换，还是新的任务类别？有哪些实验依据？
- 与本项目真正相近在哪里，哪些可以借鉴，哪些差异仍需进一步证实？

可从索引中的移动操作、语义地图、抓取等项目出发，并补充更直接相关的 Agent 机器人与多技能系统。不要将每个开源硬件平台都当成同一类型的竞争方案；区分硬件平台、模型、环境表示方法和完整系统。

### 2. 查证并校准背景判断

以下均是待检验判断，不是要求你证明的结论：

- 现有机器人是否主要围绕特定模型、任务类别或有限任务集合设计？适用于哪些系统，有哪些反例？
- 面向多样需求的灵活可扩展整体方案，究竟是缺少、分散、应用条件受限，还是已有充分先例？
- 现代 Agent 的理解、记忆与长程任务能力，在实体机器人上已有怎样的证据和限制？不能从软件工具调用能力直接推导出可靠机器人执行能力。
- Agent 机器人大脑的相关生态发展到什么程度？请采用可观察的系统、组件和验证情况描述，避免“生态不庞大”这类无明确标准的结论。
- 哪些问题已由相关工作解决，本项目更适合强调哪些应用探索、工程设计与验证贡献？

输出每项判断的支持证据、反例或限制，并建议申报书采用何种强度的表述。若调研推翻当前判断，明确指出并提出修改建议。

### 3. 按研究板块补充关键路线

| 板块 | 重点需要了解的内容 |
|---|---|
| 技能专家 | 已有模型与执行方案的能力边界、数据与设备要求，技能描述和封装方式，以及接入/替换的可行条件 |
| 语义地图 | 几何、区域、物体表示的衔接；跨观测实例关联、位置推断、历史与不确定性维护；哪些现成组件能承担哪些职责 |
| Agent 层 | 机器人任务运行时、异步技能与事件响应、任务上下文和记忆、失败后继续决策，以及引擎接入方式 |
| 胶水通信 | 跨框架与设备适配、任务生命周期、状态与事件传递、取消和异常恢复；按需求讨论候选机制，不提前冻结协议 |
| 支撑平台 | 定位、导航、感知、操作、设备控制与上层能力的适配关系，以及现有平台需要进一步确认的条件 |
| 仿真到现实 | 仿真验证、模型与策略调优、真实平台适配和整机联调；区分接口替换、系统协同和策略迁移的不同证据 |

每个板块说明已有基础、候选路线、可复用内容、需要自行完成的工作，以及关键依赖或风险。首轮达到支撑申报的初步方案深度即可，不要求编制完整实施设计。
