# 当前决策与申报推进

更新日期：2026-11-14。本文记录本轮讨论后的项目主线和推进状态，供后续会话接续；具体定义以根目录维护文件为准。历史讨论仍保留其原有语境。

## 一、当前决策

- **项目名称**：Agent 驱动的可扩展具身家居机器人。
- **面向的问题**：家居任务需求灵活多变，机器人服务范围受预设任务类别和固定流程约束。对现有系统的概括仍需调研校准。
- **总体目标**：围绕用户目标组织已有能力，根据环境信息和执行反馈持续调整任务，并通过接入、替换和组合技能扩展服务范围。任务组织不预先绑定单一类别，执行能力由技能、环境和平台条件决定。
- **技术主线**：Agent 组织任务，技能专家承载具身模型及其他执行方案，环境语义地图提供环境信息；胶水通信和软硬件平台支撑协同，通过模型与整机的仿真到现实调优落实应用。
- **首期验证**：有限物品和受控环境下的寻找、抓取入篮、返回用户。寻物是首个验证场景，整体项目面向多样任务需求与服务扩展。
- **物体语义**：同时保留概率性实例关联与位置推断，不简化成只有物体类别或位置记录。
- **研究项含义**：按整个机器人项目的工作板块拆分，大体依据架构并补充跨层工作。目前形成六项草案：技能专家、环境语义地图、Agent 层、胶水通信、软硬件支撑平台、模型与整机的仿真到现实调优。
- **文档职责**：《项目说明》采用“概况—背景与面向的问题—项目特色与创新—项目目标与边界”；《正文思路》说明写作逻辑，研究目的按“背景—问题—总体研究目的”展开；申报正文保留七项格式。

## 二、写作与论证要求

让评审先理解最终机器人及其用途，再理解问题、目标、研究内容、特色和实现依据。应用问题应从需求与服务能力的关系表达，技术设计说明如何回应它。研究内容说明各板块研究什么，技术路线进一步说明怎样落实。

创新与特色围绕通用性、Agent 驱动、语义地图及其协同凝练，并与相关工作比较。不能用“采用了某项技术”或“现有模块组合”直接代替贡献论证，也不预设相关研究不存在。

首期任务完成、执行条件变化后的任务调整、技能接入后的服务扩展分别需要相应证据。跨物品、跨区域复用与跨任务类别扩展应区别说明，不以一次寻物成功证明任意任务能力。

## 三、当前材料与下一步

项目定义、写作逻辑、架构和六项研究板块已有工作基础；申报正文仍是骨架，具体路线、相关工作对比及验证安排尚需补充。

1. **定向调研与参考代码核查**：围绕六项研究内容分析相近系统、候选技术、可复用部分及待开发工作。重点支持问题判断、技术可行性和特色比较，避免只列项目名或技术名。
2. **补充初步路线与验证设计**：明确各项实现思路、依赖和难点；设计首期闭环、任务调整和技能扩展的验证方式，确定真机交付范围。具体数值结合条件与试验再定。
3. **核对已有基础与条件**：区分已完成、正在调试和计划开展的内容，整理代码、硬件、实验记录、人员与资源条件；MuJoCo 倾向和候选 Agent 引擎不等于已具备实验基础。
4. **逐步形成正文**：先开展研究目的和研究内容写作；以调研反馈校准研究现状、创新特色与技术路线，再落实成果、进度和条件。无需等待所有实现细节确定，但未核实的事实和成果不写成定论。
5. **核对申报要求**：确认创新训练项目对应模板及实际系统的篇幅、格式和材料要求。

以上工作可以交叉推进，不构成全部设计结束后才能动笔的门槛。
