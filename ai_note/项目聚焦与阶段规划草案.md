# 项目聚焦与阶段规划草案

## 一、项目定位

本项目以家居环境中的移动操作任务为主要应用背景，重点探索如何将现有的导航、机械臂控制、视觉感知、语义地图和智能任务规划技术进行工程化组合，形成可扩展的分层系统。

项目重点是系统集成、接口设计、任务闭环和真实环境验证，不以训练新的具身基础模型、提出新的底层控制算法或替代已有成熟算法为主要研究目标。

项目中的 Agent、语义地图和技能接口应保持通用性，使系统能够从一个具体任务扩展到同类家庭任务，而不是为单一物品或单一房间编写固定流程。

## 二、核心问题

在已有导航仿真、URDF、真实底盘调整和 SmolVLA 单臂控制概念验证基础上，研究以下工程问题：

1. 如何把几何地图、房间与区域划分、物品语义及其位置状态组织成机器人可查询、可更新的环境语义地图；
2. 如何让任务规划模块根据用户目标、环境状态和技能能力，生成可执行的多步骤任务；
3. 如何通过统一接口连接导航、视觉定位、机械臂操作等现有能力，并处理异步执行、失败、取消和状态更新；
4. 如何在仿真到真实机器人的过程中验证系统的通用性、可靠性和扩展能力。

## 三、聚焦场景

项目第一代机器人首先聚焦于“家庭物品寻找与取回”这一代表性任务：

> 语义地图跟踪若干目标物品；用户下达指令后，Agent 在事件驱动下持续决策，机器人导航到候选区域并通过视觉寻找目标，使用 SmolVLA 控制机械臂将目标抓取到篮子中，再导航回用户身边，并更新物品状态。

该场景包含移动操作机器人的主要链路：用户交互、Agent 长程任务规划、语义地图查询、事件驱动决策、区域导航、目标识别、抓取执行、返回导航、任务反馈和地图更新。它是第一代机器人的低风险验证闭环，而不是系统能力的最终边界。

场景中的对象、房间和任务参数应采用可替换表示。例如“寻找水杯”可以替换为“寻找工具箱”或“寻找遥控器”，目标位置也可以从客厅扩展到厨房、书房等区域。系统通过物品类别、候选位置、空间关系和技能接口来保持通用性，避免把实现绑定在单一物品、固定房间或固定路径上。

垃圾发现、拖鞋归位、物品收纳和更复杂的家务任务作为同一框架下的后续任务类型，不作为第一代机器人首个闭环的交付承诺。

## 四、语义地图的最小实现与扩展方向

语义地图不直接等同于具身模型中的“世界模型”，而是面向机器人运行的环境信息管理模块。第一代系统至少需要实现三类信息：

1. **几何与空间**：地图坐标、可通行区域、房间和目标位置；
2. **区域划分**：房间、功能区域及其名称和边界。初期可以采用用户标记后保存为 JSON 等简单方式，后续再研究与几何地图、自动识别和持久化存储的整体设计；
3. **物体语义**：物体类别、实例、空间位置、观察时间和置信度，并支持多个同类物体的实例跟踪和状态更新。

语义地图的价值在于为 Agent 和技能专家提供稳定的环境查询与更新接口，使任务规划不必直接依赖点云、相机话题或某个感知算法的私有数据结构。

## 五、现有基础

- 已有 ROS 2、Nav2 导航仿真和 URDF；
- 真机移动平台正在调整；
- 已完成 SmolVLA 在真实六自由度机械臂上的单臂控制概念验证；
- 已形成 Agent、原子技能、语义地图、ROS 2 和硬件的分层架构草案；
- 已对 ConceptGraphs、Kimera、RTAB-Map 等语义地图和建图路线进行了初步调研；
- 已讨论 Agent 与技能服务之间的异步任务、事件和接口设计。

## 六、总体架构与拓展性

项目保留现有的分层架构：Agent 层、技能专家层、语义地图层、ROS 2 支持层和硬件层。第一代验证只选择有限的技能组合，但技能专家接口本身为导航、视觉定位、抓取、整理以及未来接入不同 VLA、WAM、ACT 或传统规划算法预留位置。

Agent 层暂定采用 Pi Agent 作为引擎，利用现代 Agent 的工具调用、长程任务规划、会话上下文和记忆能力，在事件驱动运行时中持续根据任务结果和环境变化作出下一步决策。Agent 不直接控制电机，而是通过稳定的技能接口调用导航、寻找、抓取和返回等能力。

这种设计使第一代机器人能够以有限目标集合和有限任务流程完成可行性验证，同时保留向第二代硬件、更丰富技能专家和更复杂家庭任务扩展的骨架。

## 七、一年期阶段路线

### 阶段一：需求收敛与系统接口设计

明确家庭物品寻找与取回任务的任务模型、物品和空间数据模型、技能接口、状态流转和评价指标，形成系统总体方案和最小可运行接口。

### 阶段二：MuJoCo 仿真闭环

在已有 Nav2 和 URDF 基础上，采用 MuJoCo 构建轻量仿真环境，接入模拟语义地图、模拟物品感知和模拟抓取技能，完成“用户指令—Agent 决策—导航—寻找—抓取入篮—返回—状态更新”的端到端闭环，并验证异常、取消和恢复流程。MuJoCo 主要用于机器人运动和任务流程验证，不以大规模强化学习训练为目标。

### 阶段三：第一代真实机器人闭环

逐步接入正在调整的真实移动底盘、真实视觉感知和已验证的 SmolVLA 六自由度机械臂控制能力，完成“寻找目标—抓取入篮—返回用户”的第一代真实机器人闭环，分析定位误差、感知误差、抓取失败和通信延迟对任务的影响。

### 阶段四：通用性与第二代扩展准备

在多个物品、多个区域和多种任务参数下进行测试，验证系统是否能通过替换目标物品、位置和技能组合复用同一套框架；在条件允许时扩展到物品归位或简单整理任务，并总结第一代硬件限制，为第二代机器人硬件升级和更多技能接入提供依据。

### 阶段五：系统总结与成果整理

整理系统架构、接口规范、实验数据和失败案例，完成项目总结、论文或技术报告、演示系统及申报书中承诺的成果材料。

## 八、项目边界

本项目不把以下内容作为主要研究目标：

- 训练新的 VLA、WAM、ACT 或其他具身基础模型；
- 从零研究新的 SLAM、导航、抓取或运动规划算法；
- 在一年内完成覆盖所有家务任务的通用机器人；
- 过早承诺完整量产级硬件、长期自主运行和全场景可靠性。

这些技术可以作为外部能力或候选模块接入，并在系统验证中评估其适用性。

## 九、项目成功标准

项目应至少能够展示：

1. 一个可查询和更新的家庭环境语义地图，至少覆盖几何空间、区域划分和物体实例状态；
2. 一个能够调用多个技能专家的 Agent 任务规划与事件驱动执行流程；
3. 一个基于 MuJoCo 的仿真寻找、抓取入篮和返回闭环；
4. 一个由真实移动平台、视觉和 SmolVLA 机械臂控制参与的第一代机器人验证环节；
5. 在多个物品或区域变化下仍可复用的接口、任务流程和扩展骨架；
6. 对第一代硬件限制和第二代升级方向的实验分析。
