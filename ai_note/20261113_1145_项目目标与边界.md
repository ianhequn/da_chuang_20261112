# 项目目标与边界

> 项目名称：融合语义地图的 Agent 驱动具身移动操作机器人可扩展通用架构研究
>
> 文档用途：统一项目规划、技术推进和立项申报书中的目标与范围表述。

## 一、项目总体定位

本项目面向移动操作机器人在真实环境中的工程化落地问题，研究如何利用现有机器人技术生态，将 Agent、环境语义地图、具身模型及其他机器人技能、机器人软件支持能力和硬件平台组织成职责清晰、接口稳定、便于替换和扩展的通用技术架构。

项目以家居环境为主要应用背景和首要验证场景。家居环境中的物品寻找与取回任务具有空间结构、物体状态不确定、多步骤移动操作和持续任务决策等特点，能够集中体现系统架构的主要能力。项目并不把任务逻辑绑定于某一房间、某一类物品或某一套具身模型，而是通过可配置的环境、物体、任务和技能表示，验证架构的复用与扩展能力。

本项目的核心价值不在于孤立地提出某一种新模型或新算法，而在于探索如何让已有的先进技术在统一的机器人系统中协同工作，使通用移动操作机器人的构想具备可实现、可验证和可持续扩展的工程基础。在设计、实现和验证过程中，团队将进一步接触并掌握相关技术的使用方法、内部机制和工程调优问题。

## 二、总体目标

构建一套融合环境语义地图、Agent 长程任务编排和可替换机器人技能的具身移动操作机器人系统架构，并通过仿真环境和第一代真实移动操作平台验证其任务闭环能力、模块协同能力和基本扩展能力。

具体目标包括：

1. 建立分层的机器人系统架构，明确 Agent、环境语义地图、技能专家、机器人支持层和硬件层的职责与接口关系；
2. 建立面向任务决策的环境语义地图，管理几何空间、区域用途、物体语义、候选位置、观测历史和概率性实例关联；
3. 建立技能专家的统一调用方式，使导航、视觉搜索、具身抓取、运动规划等能力能够作为可替换模块被 Agent 组织和调用；
4. 建立事件驱动的任务运行流程，使 Agent 能根据用户目标、地图信息、技能结果和环境变化持续推进、调整或恢复长程任务；
5. 在轻量仿真和真实平台上验证从环境查询、任务规划、移动搜索、抓取入篮到返回用户的完整流程，并分析系统的成功条件、失败类型和扩展能力。

## 三、研究对象边界

本项目研究对象是**机器人系统的通用工程化架构及其验证方法**，主要包括：

- Agent 与机器人任务运行时的组织方式；
- 环境语义地图的数据组织、查询、更新和任务接口；
- 技能专家的能力描述、调用生命周期、状态反馈和错误处理；
- 各层之间的胶水机制、异步任务和事件传递；
- 仿真组件、软件模块、真实设备之间的适配与替换；
- 由上述模块构成的移动操作任务闭环及其评价方法。

项目会使用和分析导航、视觉、具身模型、运动规划、仿真和硬件控制等技术，并根据系统需要进行配置、适配和工程调优。相关技术的内部机制研究服务于系统集成和性能验证，不单独扩大为新的基础算法研究课题。

## 四、技术范围边界

### 1. 环境语义地图

第一阶段实现以下内容：

- 基于成熟 SLAM 或地图系统的几何空间表达；
- 通过用户标记或配置方式记录房间、区域等用途信息；
- 记录有限目标物品的类别、实例特征、观测位置、时间和置信度；
- 根据历史观测和当前感知结果进行概率性实例关联与候选位置推断；
- 向 Agent 和技能专家提供查询、观测记录、状态更新和历史信息接口。

项目不以重新提出 SLAM、开放词汇检测、实例分割或多目标跟踪的基础算法为目标，而是研究如何将这些能力组织成面向任务的环境信息服务。

### 2. Agent 与任务编排

Agent 负责自然语言目标理解、任务拆解、技能调用、事件响应、上下文维护和必要的记忆管理。Agent 不直接承担电机级控制、实时安全闭环和底层硬件保护；这些职责由技能执行层、机器人支持层和硬件控制层负责。

### 3. 技能专家

具身模型可以作为技能专家的重要实现来源，也可以接入传统运动规划、视觉模型、确定性程序或多个模块组成的服务。第一阶段优先验证导航、视觉搜索、具身抓取入篮和返回等技能的协同调用。技能接口应允许未来替换具体模型、算法和设备。

### 4. 支持层、硬件层与胶水机制

支持层可以使用 ROS 2、Python 生态、设备 SDK、仿真框架及其他基础软件，不预先限定为单一中间件。硬件层包含移动平台、操作机构、传感器、执行器、计算设备、控制器、通信设备及其他机器人组成部分。胶水机制贯穿层间连接、层内封装和工具适配，负责将地图和技能封装为上层可调用能力，并处理异步任务、状态转换和事件传递。

## 五、首年验证边界

项目为一年期创新训练项目。首年以有限物品集合和受控室内环境完成一个清晰、可重复的验证闭环：

```text
用户提出物品取回目标
→ Agent 查询环境语义地图并选择候选区域
→ 机器人导航到目标区域并进行视觉搜索
→ 具身抓取技能将目标放入机器人携带的篮子
→ 机器人返回用户附近
→ Agent 汇总任务结果，地图更新物品状态
```

首年核心验收内容包括：

1. 可查询和更新的环境语义地图最小实现；
2. Agent 调用多个技能专家的事件驱动任务流程；
3. 基于 MuJoCo 或其他合适仿真环境的完整流程验证；
4. 真实平台上的导航、视觉或机械臂模块验证，并根据设备进度完成尽可能完整的真实闭环；
5. 在更换若干物品、区域或技能参数后，任务流程和接口仍可复用的验证；
6. 对任务成功率、候选位置命中情况、技能失败和恢复情况进行记录与分析。

完整真机闭环是项目的重要目标；若硬件调试进度造成联调延迟，仿真全流程和真实平台上的关键模块验证仍应作为可交付的替代路径，避免项目成果完全依赖单一硬件节点。

## 六、通用性与扩展边界

项目的“通用架构”主要指：

- 任务逻辑不绑定单一物品和固定房间；
- Agent 通过稳定接口调用技能，不绑定某个具身模型；
- 语义地图能够支持不同区域、物体集合和观测记录；
- 仿真模块和真实模块可以在接口层替换；
- 新增技能、任务类型或硬件时，尽量不修改上层核心任务逻辑。

首年不承诺覆盖全部家庭家务，也不承诺量产级长期自主运行。垃圾发现、拖鞋归位、物品收纳、更复杂的多物体任务、更多具身模型和第二代硬件升级，作为在本架构上继续扩展的方向。

## 七、项目成功的判断标准

项目成功不只取决于机器人是否完成一次演示，还应同时满足以下条件：

- 系统能够展示清晰的分层职责和可调用接口；
- 环境语义地图能够为任务提供实际可用的物品位置线索；
- Agent 能根据技能结果和环境事件推进或调整任务；
- 仿真和真实模块能够围绕同一任务接口逐步接入；
- 更换物品、区域或技能实现后，不需要重写整套任务逻辑；
- 项目能够总结真实运行中的失败模式、工程限制和后续升级方向。
