 Abstract 
 Vision-language-action (VLA) models are effective robot action executors, but they remain limited on long-horizon tasks due to the dual burden of extended closed-loop planning and diverse physical operations. We therefore propose VLAs-as-Tools , a strategy that distributes this burden across a high-level vision language model (VLM) agent for temporal reasoning and a family of specialized VLA tools for diverse local physical operations. The VLM handles scene analysis, global planning, and recovery, while each VLA tool executes a bounded subtask. To tightly couple agent planning with VLA tool execution in long-horizon tasks, we introduce a VLA tool-family interface that exposes explicit tool selection and in-execution progress feedback, enabling efficient event-triggered agent replanning without continuous agent polling. To obtain diverse specialized VLA tools that faithfully follow agent invocations, we further propose Tool-Aligned Post-Training (TAPT), which constructs invocation-aligned training units for instruction following and adopts tool-family residual adapters for efficient tool specialization. Across five simulated benchmarks, VLAs-as-Tools improves the success rate of π 0.5 \pi_{0.5} by 8.9 percentage points on average and enhances invocation fidelity by 15.0 points in Non-biased Rate. On three real-world Franka tasks, it improves success rate from 16.7% to 58.3% under matched data and compute. Code will be released. 
 1 Introduction 
 Recent end-to-end vision-language-action (VLA) models, including OpenVLA-OFT and GR00T N1.6, have advanced general-purpose robot control and cross-embodiment generalization  ( Kim et al., 2025 ; NVIDIA GEAR Team, 2025 ) . Yet they are typically deployed as single embodied controllers, requiring one policy to interpret goals, perceive scenes, predict actions, and coordinate multi-step execution. This setting is difficult for current VLAs: long-horizon tasks require decomposition, progress tracking, failure recovery, and skill composition, while embodied data remains limited and model scale still constrains planning and understanding. As a result, VLAs provide powerful language-conditioned robot-control capabilities, but remain limited as standalone long-horizon agents. 
 There are two routes toward long-horizon embodied tasks. One direction keeps planning inside end-to-end VLA policies, where models such as π 0.5 \pi_{0.5} introduce semantic subtask prediction and task-level planning tokens within the VLA backbone  ( Physical Intelligence et al., 2025 ) . Another direction, represented by SayCan and Code as Policies, adopts an agentic formulation in which language models select skills, compose programs, or invoke robot APIs  ( Ahn et al., 2022 ; Liang et al., 2022 ) . This follows the successful paradigm of digital agents, where high-capacity LLMs handle goal decomposition, state tracking, replanning, and error recovery, while tools provide bounded, observable, and reliable execution interfaces  ( Yao et al., 2022 ; Schick et al., 2023 ; Yang et al., 2024 ) . However, existing embodied tools are often manually specified and task-specific, giving them weaker physical execution capabilities than modern VLAs. This leaves embodied AI with a complementary gap: end-to-end VLAs provide stronger physical execution but weaker long-horizon reasoning, whereas existing embodied agents provide stronger planning but rely on weaker physical tools. 
 Figure 1: VLAs-as-Tools closes the complementary gap between end-to-end VLAs, which execute well but reason poorly over long horizons, and agent systems, which plan well but rely on weak rigid skills. It couples a planning VLM with TAPT-specialized VLA tools through explicit tool calls, progress feedback, and event-triggered replanning for reliable long-horizon execution. 
 As illustrated in Figure  1 , we propose VLAs-as-Tools , a strategy for solving long-horizon embodied tasks by enabling a planning-capable VLM agent to invoke bounded VLA executions as physical tools. This strategy addresses the limitations of individual VLAs by distributing the burden across time length and task breadth: the VLM extends execution over long horizons through planning, state tracking, and recovery, while multiple specialized VLA tools cover diverse bounded subtasks. Each VLA therefore operates within a focused execution scope, where it can be efficiently adapted from task-specific demonstrations and reliably map visual-language inputs to continuous robot actions. However, standalone VLAs are not readily tool-usable, since their execution can be biased by scene priors, demonstration regularities, or visual context rather than the invoked instruction  ( Zhang et al., 2026b ; Fang et al., 2026 ) , and task-specific adaptation can degrade pretrained semantic understanding and generalization  ( Hancock et al., 2025 ; Liu et al., 2026 ) . Thus, realizing VLAs-as-Tools requires addressing two core challenges: how to make VLAs callable and reliable physical tools, and how to integrate them effectively into an embodied agentic system. 
 We address these two challenges with two complementary components. To make VLAs tool-usable, we introduce Tool-Aligned Post-Training (TAPT), which pairs bounded subtasks with precise language instructions so that each VLA tool learns a clear correspondence between the agent’s invocation and the intended physical behavior, and adopts tool-family residual adapters to parameter-efficiently create many specialized VLA tools on a shared backbone while mitigating degradation of pretrained semantic generalization. To integrate these tools into the agentic system, we design a VLA tool-family interface with two typed message sets: agent-to-tool invocations that specify bounded subtasks and route them to the appropriate VLA tool, and tool-to-agent feedback that returns in-execution state signals. The former grounds planned subtask sequences in the correct physical executor, while the latter exposes timely intervention points, enabling low-frequency but responsive replanning. 
 We evaluate three VLA backbones—OpenVLA, OpenVLA-OFT, and π 0.5 \pi_{0.5} —on six benchmarks: LIBERO-Long, RoboTwin-SA, CALVIN, RoboMemArena, RoboLab-120, and LIBERO-IF, plus three real-world Franka tasks. Across the five simulated task-success benchmarks with directly matched π 0.5 \pi_{0.5} baselines, VLAs-as-Tools improves average success by 8.9 points. It also improves invocation fidelity by 15.0 points in Non-biased Rate and raises real-world macro-average success from 16.7% to 58.3%. 
 2 Related Work 
 VLA Tool Interfaces for Agentic Embodied Control. 
 Recent progress in embodied foundation models has been driven by Vision-Language-Action (VLA) policies, which map visual observations and language instructions to robot actions with large pretrained vision-language backbones  ( Brohan and others, 2023 ; Octo Model Team et al., 2024 ; Kim et al., 2024 ; Black et al., 2024 ; Physical Intelligence et al., 2025 ) . While these models achieve strong full-task performance, studies show that VLAs do not always ground their behavior in the language command, instead following visual priors and training-set regularities  ( Jang et al., 2022 ; Mees et al., 2022 ; Glossop et al., 2025 ; Fei et al., 2025 ) ; counterfactual evaluations further show visual cues overriding the specified instruction  ( Fang et al., 2026 ) . This makes standalone VLAs unreliable as agentic execution interfaces, where the planner needs each invocation to have stable, instruction-faithful semantics that can be monitored and composed. We address this by aligning VLA post-training with the agent’s invocation interface, using subtask-centric data, invocation-aligned training, and tool-family residual adapters to bind each command and tool-family label to a bounded execution behavior. 
 Embodied Agentic Systems 
 Recent embodied AI advances have increasingly focused on agentic systems, particularly in language-conditioned and long-horizon tasks  ( Salimpour et al., 2025 ; Liang et al., 2025 ) . Hierarchical embodied systems commonly address such tasks by decomposing high-level goals into task-level decisions and executable low-level skills  ( Ahn et al., 2022 ; Huang et al., 2022 ; Belkhale et al., 2024 ; Shi et al., 2025 ) , but they often rely on hand-engineered skills, affordance models, latent options
or jointly trained executors. Recent systems further scale this paradigm with learned skill libraries and agentic execution loops: AtomicVLA builds a planning-and-execution framework around atomic skill abstractions and skill-guided expert specialization  ( Zhang et al., 2026a ) , while RoboClaw uses a VLM-driven controller to orchestrate learned policy primitives for long-horizon tasks and autonomous data collection  ( Li et al., 2026 ) . These works validate skill decomposition and policy composition but their low-level skills are often system-internal primitives rather than explicit agent-visible tool invocations. In contrast, we expose the VLA as a reusable embodied tool whose agent-visible invocations pair bounded language instructions with tool-family labels, enabling more inspectable and composable execution.

 This section formalizes the VLAs-as-tools strategy: a VLA is not used as a monolithic long-horizon policy, but as a family of bounded, callable executors inside an embodied agentic control loop. This formalization turns long-horizon robot control into repeated bounded tool invocations, where the key methodological question is how to construct a VLA tool family 𝒯 \mathcal{T} whose members can be reliably invoked, monitored, and composed by the high-level agent.

 4 Methods 
 We instantiate the formal strategy above with two concrete design choices. First, we make a VLA callable through a VLA tool-family interface: the agent selects a tool family, provides a scene-grounded local instruction, and invokes the VLA for a bounded execution window. The VLA tool is therefore not a standalone task policy, but a bounded executor that receives an agent-specified invocation and returns progress feedback. Second, we train the VLA to follow this interface through Tool-Aligned Post-Training (TAPT), which aligns the training data, adapter structure, and optimization objectives with the same invocation unit used at test time. 
 4.1 Bidirectional Agent–Tool Interaction via a VLA Tool-Family Interface 
 Section  3 formulates the agent–tool interface as
 ℐ = ( 𝒞 , ℛ ) \mathcal{I}=(\mathcal{C},\mathcal{R}) . We instantiate this interface
for VLAs-as-tools through two typed message sets:
 𝒞 \mathcal{C} contains invocation messages sent by the high-level agent to a selected VLA
tool, and ℛ \mathcal{R} contains feedback messages returned by the tool for monitoring. 
 4.1.1 Invocation Messages 𝒞 \mathcal{C} 
 Each VLA tool call has two fields: a tool-family label and a scene-grounded instruction. The tool-family label g k ∈ 𝒢 g_{k}\in\mathcal{G} , such as reach , grasp , or pull , selects one callable member from the VLA tool family 𝒯 = { T g } g ∈ 𝒢 \mathcal{T}=\{T_{g}\}_{g\in\mathcal{G}} . The taxonomy 𝒢 \mathcal{G} is data-driven: following primitive-level formulations  ( Chen et al., 2025 ) , it separates free-space motion from contact interaction, yielding 11 families on DROID, 7 of which are used in each of LIBERO and RoboTwin (Appendix  C ). The instruction z k ∈ 𝒵 z_{k}\in\mathcal{Z} then grounds the selected tool family in the current scene by specifying the object, relation, and desired local effect. Together, these two fields form the invocation message c k = ( g k , z k ) c_{k}=(g_{k},z_{k}) , so 𝒞 = 𝒢 × 𝒵 \mathcal{C}=\mathcal{G}\times\mathcal{Z} . 
 This factorization makes the agent’s request inspectable. The tool-family label g k g_{k} selects the tool family, while z k z_{k} grounds that tool family in the current scene. This is useful because visually similar instructions may require different tool families: grasp , pull , and push can involve overlapping objects but differ in action distributions and termination conditions. The explicit tool-family label also gives TAPT a stable signal for organizing data and parameters, around tool-family specialization. 
 4.1.2 Feedback Messages ℛ \mathcal{R} 
 Feedback messages specify what the selected VLA tool reports while it is executing an invocation. We use a continuous progress signal p t ∈ [ 0 , 1 ] p_{t}\in[0,1] as the main feedback message, where values near 0 0 indicate little progress and values near 1 1 indicate that the current invocation is nearly complete. This signal is local to the bounded call c k = ( g k , z k ) c_{k}=(g_{k},z_{k}) : it measures progress on the selected tool invocation, not success of the full long-horizon task.
Progress feedback is useful because the agent needs timely information before a subtask fully succeeds or fails. Repeatedly querying a large VLM to inspect execution is costly, while a binary completion signal can delay recovery. In contrast, a tool-side progress signal exposes intermediate execution states, such as stagnation or deviation, without requiring the agent to reason over every low-level action. In the interface, temporal progress is stored in the progress chunk, while a threshold-based monitor determines whether to advance, replan, or continue the current invocation.
The VLA predicts progress with an auxiliary head p ^ t = ψ ω ​ ( b t ) \hat{p}_{t}=\psi_{\omega}(b_{t}) attached to the backbone feature b t b_{t} , with supervision described in Section  4.2 and implementation details in Appendix  A . 
 4.2 Improving VLA Tool Usability with Tool-Aligned Post-Training 
 Building on the VLA tool-family interface in Section  4.1 , this section describes how we train a base VLA to behave like a reliable callable tool. TAPT follows the same pipeline as the agent–tool loop. First, it rewrites both imitation and reinforcement-learning supervision around bounded invocations: demonstrations are segmented into invocation-labeled action windows, and RL rollouts are initialized and rewarded at the same subtask level. Second, it makes the tool-family label executable by routing each invocation through tool-family residual adapters on top of a shared VLA backbone. Third, it post-trains the resulting model to both execute the requested local behavior and predict progress feedback for that invocation. Standard downstream SFT and RL are then used as optimization settings for adapting and evaluating the same invocation-aligned tool family. 
 4.2.1 Invocation-Aligned Training Units 
 TAPT first rewrites imitation learning around the unit the agent calls at inference time. Instead of training only on full-task trajectories, we segment demonstrations into bounded windows and annotate each window with an invocation c = ( g , z ) c=(g,z) , where g ∈ 𝒢 g\in\mathcal{G} identifies the tool family and z ∈ 𝒵 z\in\mathcal{Z} describes the local scene effect. Each imitation unit is x IL = ( o 1 : T , z , g , a 1 : T , p 1 : T ⋆ ) x_{\mathrm{IL}}=(o_{1:T},z,g,a_{1:T},p_{1:T}^{\star}) , where o 1 : T o_{1:T} and a 1 : T a_{1:T} are the observations and actions inside the window, and p 1 : T ⋆ p_{1:T}^{\star} is a progress target or proxy. Segments are obtained from task annotations, state changes, contact events, and automatic multimodal labeling; the labeler assigns g g using operational definitions based on contact pattern, force direction, and object motion. Detailed in Appendix  B . 
 The same invocation view is used for reinforcement learning. For each call ( g , z ) (g,z) , we build a bounded subtask rollout rather than starting from the original full-task initial state. The rollout starts from states where that invocation should begin, obtained from demonstration boundaries or successful executions of preceding subtasks. It is evaluated with a local completion predicate ψ z , g ​ ( s ) \psi_{z,g}(s) , such as contact, containment, relative pose, joint displacement, or object-on-surface relations. The rollout receives reward 1 1 if this predicate becomes true within horizon H H , and 0 0 otherwise; the episode ends when the predicate is satisfied or the horizon is reached. 
 Thus IL and RL share the same target: reliable execution of the current bounded invocation. IL teaches the actions and progress for a call, while RL tests whether the same call can be completed from states where the agent would invoke it. 
 4.2.2 Tool-Family Residual Parameterization 
 The tool-family label g g should control the VLA’s execution path, not merely appear as an extra language token. Tool families such as grasping, releasing, pulling, and rotating may share the same scene context, but they require different action distributions, termination conditions, and progress semantics. We therefore implement the VLA tool family with a shared pretrained backbone and deterministic tool-family residual adapters selected by g g . 
 Concretely, let f Θ f_{\Theta} be a pretrained VLA backbone. For each selected linear layer W ∈ ℝ d out × d in W\in\mathbb{R}^{d_{\mathrm{out}}\times d_{\mathrm{in}}} , we add a bank of low-rank residual adapters { Δ ​ W g } g ∈ 𝒢 \{\Delta W_{g}\}_{g\in\mathcal{G}} , with one adapter per tool family: 
 Δ ​ W g = B g ​ A g , rank ⁡ ( Δ ​ W g ) ≤ r ≪ min ⁡ ( d in , d out ) . \Delta W_{g}=B_{g}A_{g},\qquad\mathrm{rank}(\Delta W_{g})\leq r\ll\min(d_{\mathrm{in}},d_{\mathrm{out}}). 
 (4) 
 Given hidden activation x x and selected family g g , the adapted layer computes y = W ​ x + Δ ​ W g ​ x y=Wx+\Delta W_{g}x . Thus g g deterministically routes the call to a lightweight LoRA residual  ( Hu et al., 2021 ) . 
 At inference time, the agent provides c k = ( g k , z k ) c_{k}=(g_{k},z_{k}) . The selected residual path remains active for the duration of the bounded invocation, and actions are produced as 
 a t ∼ π θ , ϕ g k ( ⋅ ∣ o t , z k , h t ) , a_{t}\sim\pi_{\theta,\phi_{g_{k}}}(\cdot\mid o_{t},z_{k},h_{t}), 
 (5) 
 where ϕ g k \phi_{g_{k}} denotes the residual-adapter parameters for family g k g_{k} . The same backbone features are also used by the progress head defined in Section  4.1 . The adapters give each tool family a distinct execution path while preserving shared visual-language representations. Because each adapter is low-rank, adding tool families introduces only a small parameter overhead. A new family can also be added by training only its adapter while freezing the backbone and prior adapters, which retains previously learned skills far better than end-to-end sequential fine-tuning (Appendix  C.2 ).

 TAPT post-trains the parameterization above on a broad invocation-aligned corpus 𝒟 mid inv \mathcal{D}_{\mathrm{mid}}^{\mathrm{inv}} before benchmark-specific adaptation. The goal is to establish reusable semantics for the interface call c = ( g , z ) c=(g,z) : g g selects an execution path, z z grounds that path in the scene, and the progress target teaches the feedback signal returned to the agent.

 5 Experiment 
 5.1 Experimental Setup 
 Our experiments ask whether VLAs-as-tools improves long-horizon performance in simulation and the real world, whether TAPT makes VLA execution more faithful to agent invocations, and which components drive the gains; Section  5.8 points to further analyses in the appendix. 
 We evaluate our method mainly with two representative VLA backbones, OpenVLA-OFT and π 0.5 \pi_{0.5} , and include OpenVLA as an additional supervised-adaptation baseline when useful  ( Kim et al., 2024 ; Kim et al., 2025 ; Physical Intelligence et al., 2025 ) . Experiments are conducted on LIBERO  ( Liu et al., 2023 ) , RoboTwin  ( Mu et al., 2025 ) , and CALVIN  ( Mees et al., 2021 ) , with additional long-horizon evaluation on RoboMemArena  ( Lei et al., 2026 ) and RoboLab-120  ( Yang et al., 2026 ) . For LIBERO, we use LIBERO-Long to highlight performance on long-horizon tasks. Since our data-splitting pipeline targets single-arm manipulation, RoboTwin evaluation uses 8 single-arm-executable tasks with a Franka embodiment, denoted RoboTwin-SA; the task list and selection rule are provided in Appendix  G . For CALVIN, we use CALVIN_D with an 80%/20% train-test episode split, treating it as a complementary testbed with existing subtask-level structure. TAPT includes two invocation-aligned (IA) stages: IA Post-train , an intermediate post-training stage on DROID-split, and IA SFT , downstream supervised adaptation on benchmark-specific datasets such as LIBERO-Long-split and RoboTwin-split. The “-split” suffix denotes demonstrations processed by our data-splitting pipeline into invocation-aligned subtasks. In the IL training of both OpenVLA-OFT and π 0.5 \pi_{0.5} , IA Post-train is conducted for 1 epoch; during IA SFT, LIBERO is trained for 150K/30K steps and RoboTwin for 60K/30K steps, respectively, with batch sizes of 8/256 following the official configurations. All RL experiments are implemented with RLinf, with implementation details provided in Appendix  D .  Supervised downstream adaptation. 
 We first evaluate imitation-learning adaptation when downstream demonstrations are available. Table  1 compares three deployment modes: a standalone SFT-trained VLA, a standard SFT-trained VLA with a direct planner, and our TAPT-trained VLA with the VLA tool-family interface. Deployment mode denotes how the trained VLA is used at evaluation time: Standalone executes the VLA as a single task policy, Direct planner lets a high-level planner periodically issue language instructions, and the VLA tool-family interface establishes a tightly coupled bidirectional interaction between the agent planner and VLA tools. The results show that simply placing a standard SFT policy inside an agent loop is insufficient: on LIBERO-Long, direct planner deployment changes performance by − 0.2 -0.2 , − 11.8 -11.8 , and − 12.0 -12.0 points for OpenVLA, OpenVLA-OFT, and π 0.5 \pi_{0.5} , respectively. In contrast, TAPT with the VLA tool-family interface consistently improves over the corresponding standalone SFT baselines, with gains of up to + 5.2 +5.2 points on LIBERO-Long and + 31.87 +31.87 points on RoboTwin-SA. These results indicate that the main benefit does not come from wrapping a VLA with a planner alone, but from making the VLA executor tool-aligned and reliable under agent–tool interaction.

 6 Conclusion 
 We presented VLAs-as-Tools , a framework that treats VLA models as callable, specialized executors under a planning-capable multimodal agent. By separating high-level decomposition, progress monitoring, and recovery from bounded robot-control execution, the framework makes VLA policies more composable for long-horizon embodied tasks. We further introduced Tool-Aligned Post-Training to improve invocation fidelity and specialize VLA tools without discarding their pretrained semantic capabilities. Experiments in simulation and on a real Franka robot show gains in task success, instruction alignment, few-shot adaptation, and planner robustness. The real-world study covers one robot, one camera, and three tabletop tasks, and primitives absent from pretraining and adaptation data still require new demonstrations; broader settings remain future work.

 Appendix A Progress Supervision and Feedback 
 Supervision and prediction. 
 For each bounded subtask invocation, we supervise a scalar progress signal using a normalized temporal proxy. For an automatically segmented execution window of length T T , the frame-level target is p t ⋆ = ( t − 1 ) / ( T − 1 ) p_{t}^{\star}=(t-1)/(T-1) , increasing linearly from 0 0 at the first frame to 1 1 at the last. The progress head pools the final-layer backbone feature and passes it through a lightweight D → → → 1 D\!\rightarrow\!1024\!\rightarrow\!256\!\rightarrow\!1 MLP followed by a sigmoid. It is jointly optimized with the action objective using mean-squared error and λ prog = 0.1 \lambda_{\mathrm{prog}}=0.1 . At runtime, each 2 Hz VLA inference jointly predicts an action chunk and its aligned progress feedback, requiring no separate perception pass or model call. 
 Runtime semantics and control. 
 Progress is local to the currently active subtask invocation rather than a global task-completion percentage. The VLM planner instead maintains global execution state from the plan, current observations, completed calls, and execution history. This separation avoids requiring the low-level executor to infer an ambiguous global completion state while exposing intervention points before failure or timeout. A runtime monitor combines a completion threshold with consecutive-sample smoothing and lookback-based progress gains to decide whether to continue the current call, advance to the next tool, or invoke replanning after stagnation. Figure  6 illustrates these outcomes for the same pick invocation: progress crosses the completion threshold after a successful grasp but plateaus when the grasp is missed. Because supervision comes from temporal position within segmented windows, the prediction is a learned temporal completion proxy correlated with physical execution state, not a perfectly calibrated estimate of semantic task completion. 
 Figure 6: Local progress feedback for the same bounded pick invocation. In the successful rollout (top), predicted progress rises as the grasp develops and crosses the completion threshold τ = 0.90 \tau=0.90 , triggering a transition to the next tool. In the failed rollout (bottom), the missed grasp causes progress to plateau, allowing the runtime monitor to identify stagnation and request replanning. 
 Appendix B Automatic Labeling Pipeline 
 We convert raw robot trajectories into invocation-aligned training examples in three stages: global video understanding, state-change-based segmentation, and definition-conditioned tool-family labeling. Unlike trajectory-level captioning used in large robot datasets  ( Walke et al., 2023 ; Khazatsky et al., 2024 ; Open X-Embodiment Collaboration et al., 2023 ) , our pipeline assigns each bounded segment an operational label defined by its contact pattern, motion, physical effect, and termination condition. Figure  7 summarizes the resulting clips, labels, and normalized progress annotations. 
 Figure 7: 
Visualization of the automatic labeling pipeline output. Raw robot trajectories are segmented into bounded manipulation clips and assigned invocation-aligned tool-family labels with normalized progress annotations, providing structured examples for Tool-Aligned Post-Training and downstream split adaptation.
 Global video understanding. 
 For each trajectory, a multimodal model summarizes the manipulated objects, task intent, spatial relations, and major contact events. This global context disambiguates short local clips during segmentation and labeling. 
 State-change-based segmentation. 
 We split trajectories at gripper open–close transitions and motion changes. Gripper transitions provide explicit boundaries for grasp and release, while relative translational and angular velocities between the end-effector and object provide supporting cues for push, pull, flip, rotate, insert, press, and strike. These cues propose boundaries but do not determine labels by themselves. 
 Definition-conditioned tool-family labeling. 
 For each candidate segment, the model receives the local video, global summary, state-change cues, and the operational definitions in Table  6 . It selects the family that best matches the observed contact, motion direction, object displacement, and termination condition. 
 Table 6: Operational definitions used by the automatic labeling pipeline. Arguments indicate the manipulated object, target object or target position, and geometric parameter when applicable. 
 Tool family 
 Definition 
 reach(obj) 
 The arm moves toward the object while the gripper state remains unchanged. The segment ends before grasping, contact-driven translation, or another object-changing interaction begins. 
 grasp(obj) 
 The gripper closes on the object after the end-effector is positioned around it, establishing a stable hold. The segment ends when the gripper closure completes and the object moves with the end-effector. 
 move(pos, obj2) 
 The arm translates toward a target position while the gripper state remains unchanged. Here obj2 denotes the reference object or target area and pos denotes the target position relative to it. 
 release(obj) 
 The gripper opens to detach the held object at its current location. The segment ends when the gripper is open and the object no longer moves with the end-effector. 
 flip(obj, angle) 
 The robot rotates the object, typically around a horizontal axis, so that its vertical orientation is inverted or the opposite side is exposed. 
 rotate(obj, angle) 
 The robot adjusts the object’s 3D pose or orientation without vertical inversion, or manipulates an articulated mechanism through a rotational joint. 
 push(obj, pos) 
 The end-effector contacts the object and translates while applying forward force, causing the object to move toward the target position. The action ends when object motion stops and contact is released. 
 pull(obj, pos) 
 The end-effector establishes a pulling contact and translates backward, causing the object to move toward the target position. 
 insert(obj1, obj2) 
 obj1 is aligned with an opening, slot, or receptacle of obj2 , then translated along the insertion axis until it is partially or fully seated. 
 press(obj)

 C.2 Incremental Tool-Family Expansion 
 We distinguish recombinations of existing primitives from genuinely new physical primitives. If a task can be expressed as a new sequence of registered families, the high-level planner can solve it by composing existing tools with scene-grounded instructions. However, if it requires a primitive absent from both the pretrained VLA and the adaptation data, no data-driven VLA, whether end-to-end or tool-based, can be expected to execute it reliably zero-shot. This is a general coverage limit of data-driven robot policies  ( Yuan and others, 2026 ) , not of our taxonomy. 
 VLAs-as-Tools becomes advantageous once demonstrations of the new primitive become available. Instead of updating the full policy, we add a lightweight family-specific adapter while freezing the shared backbone and all prior adapters. This isolates the update, reduces interference with existing families, and avoids data replay. We test this property in a three-stage LIBERO-Long experiment:

 3.

 At Stages 2 and 3, the backbone and prior adapters stay frozen, with no data replay. We compare this modular strategy with end-to-end sequential fine-tuning, which updates the shared policy whenever a new primitive is added. We report five metrics: S2 New , the success of the new pull family after Stage 2; S2 Ret. , the retention of the five Stage 1 families; S3 New , the success of the new push family after Stage 3; S3 Ret. , the retention of all previously learned families; and Final , the LIBERO-Long success rate with all seven families.

 Reset-state pool refresh. 
 The choice of 𝒮 z , g 0 \mathcal{S}^{0}_{z,g} is important for composing independently trained subtask policies.
In the first round of subtask RL, we collect reset states using the initial policy or demonstration boundaries.
This provides valid states for training individual subtasks, but it can become stale after policy improvement: once a preceding subtask policy is updated, it may end with different gripper poses, object contacts, approach directions, or small object displacements than those in the original pool.
Consequently, a downstream subtask may be trained on a reset distribution that no longer matches the states produced by the learned composed policy.
In our experiments, this mismatch can make individually improved subtasks compose worse, sometimes reducing full-task success. 
 To reduce this distribution shift, we refresh the reset-state pools after one round of subtask RL.
We deploy the trained tool-family subtask policy, save boundary states whenever the preceding invocation succeeds, and use these refreshed states as 𝒮 z , g 0 \mathcal{S}^{0}_{z,g} for the next round of subtask training.
The refreshed pool therefore matches the state distribution induced by the current composed policy, improving the handoff between neighboring invocations.
Empirically, this refresh step recovers full-task performance gains that are not obtained from stale initial-policy pools alone.

 Appendix F Real-World Evaluation Details 
 Robot and sensing setup. 
 We use a Franka Research 3 robot and a single Intel RealSense D435 RGB-D camera, with no wrist-mounted camera. The camera is placed opposite the robot and angled downward to cover an approximately 40 × 40 40\times 40  cm workspace on a white tabletop against a black background. 
 Training protocol. 
 Human experts collect 30 demonstrations per task using a 3D mouse, producing three task-specific datasets. For each task, the fine-tuned π 0.5 \pi_{0.5} baseline and VLAs-as-Tools are trained separately on the same 30 demonstrations for 30K steps using eight A100 GPUs. Both methods run inference on a single NVIDIA RTX 4090. Thus, the comparison controls the real-robot data, training budget, and inference hardware. 
 Evaluation protocol. 
 Each method is evaluated over 20 rollouts per task. We pre-sample and physically mark 20 randomized initial object configurations, and use the same configurations for both methods. Object positions vary within the camera view while preserving the approximate left-to-right ordering required by each task. The maximum execution time is 60 seconds for Simple and Conditioned and 120 seconds for Long. Success is determined using the task-specific completion criteria below. 
 Simple. 
 Red and yellow cubes are placed in front of the robot, with two bowls farther away. The robot must place the red cube into the left bowl and then the yellow cube into the right bowl. A rollout succeeds only if both cubes remain stably inside their designated bowls. This task evaluates multi-stage decomposition and execution stability. 
 Conditioned. 
 Red and yellow cubes are initially placed on the left and right. The robot must stack the left red cube on the right yellow cube, remove it to restore the initial layout, and then stack the right yellow cube on the left red cube. The scene therefore returns to a visually similar state while requiring a different subsequent action. A rollout succeeds only if both stacks are completed stably. This task evaluates instruction following and resistance to scene-conditioned visual shortcuts. 
 Long. 
 Blue, red, and yellow cubes are placed from left to right, with two bowls farther away. The robot must (1) stack blue on red; (2) move the left bowl to the blue cube’s original position; (3) place blue into that bowl; (4) stack yellow on red; (5) move the right bowl to the yellow cube’s original position; and (6) place yellow into the right bowl. The task comprises 24 sequential tool invocations. A rollout succeeds only if both bowls reach their designated positions and the blue and yellow cubes remain stably inside them. This task evaluates extended planning, tool composition, and recovery. 
 Figure 8: Conditioned-task rollouts. After the layout is restored, the repeated observation leaves the fine-tuned VLA without an explicit task-stage cue. VLAs-as-Tools tracks progress in the high-level agent and issues the correct stage-specific VLA invocation. 
 Figure  8 illustrates the largest real-world gain: the monolithic baseline repeats the wrong stage after the scene recurs, whereas the agent remembers the completed prefix and instructs the VLA to execute the opposite stack. 
 Appendix G Evaluation Protocol Details 
 This appendix summarizes the evaluation protocol used for the task-level success rates reported in the main experiments. Unless otherwise specified, all methods compared within the same benchmark use the same held-out tasks, initial-state files, rollout horizons, random seeds, and success predicates. Success rate is computed as the fraction of evaluation episodes that satisfy the benchmark-defined task predicate before timeout.
The trial counts for individual benchmarks are specified below. 
 LIBERO-Long. 
 For task-level success evaluation, each policy is evaluated over 50 trials per task from the held-out LIBERO-Long initial states and is counted as successful if the native LIBERO task predicate is satisfied within the simulator’s standard rollout horizon. The same task split and initial-state set are used for standalone VLA policies, direct-planner deployment, and VLA tool-family interface deployment. 
 RoboTwin-SA. 
 Because our demonstration-splitting pipeline targets single-arm manipulation, we evaluate on RoboTwin-SA (Single-Arm), the subset of 8 RoboTwin tasks that can be executed with a single Franka arm. A task is included if its successful demonstrations do not require bimanual coordination and can be segmented into the tool-family invocation types used in our interface. The selected tasks are: 
 adjust_bottle ,
 click_alarmclock ,
 move_stapler_pad ,
 press_stapler ,
 beat_block_hammer ,
 click_bell ,
 place_empty_cup ,
 place_shoe .
 RoboTwin-SA evaluations are configured for 20 trials per task, or 160 planned rollouts per configuration. Success is measured by the benchmark task predicate at the end of each rollout or when the task terminates successfully. 
 CALVIN. 
 For CALVIN, we use CALVIN_D and split episodes into 80% training and 20% testing. The evaluation follows the benchmark’s native subtask structure: a rollout is successful if it completes the required long-horizon instruction sequence under CALVIN’s state-based success checks. In the RL experiments, the native subtask annotations are also used to define invocation-aligned resets and rewards, which lets us evaluate the proposed strategy without relying on our own split construction. 
 RoboMemArena. 
 RoboMemArena  ( Lei et al., 2026 ) contains 26 long-horizon manipulation tasks that test temporal memory through multi-object counting, occlusion, ordered execution, and transferring; its trajectories average more than 1,000 environment steps. We evaluate all 26 simulated tasks with 10 seeded rollouts per task and a maximum horizon of 2,500 steps, using the same initial seeds and budget for the standard π 0.5 \pi_{0.5} baseline and VLAs-as-Tools . Full-task success requires every reference stage of an episode to be completed, while partial progress is the mean fraction of required stages completed before termination. We report both metrics averaged over all 260 episodes. 
 LIBERO-IF. 
 LIBERO-Instruction Following (LIBERO-IF) evaluates invocation fidelity rather than only task success. Drawing on the counterfactual evaluation of LIBERO-CF  ( Fang et al., 2026 ) , we build our own instruction-following benchmark tailored to our agent–tool setting, where the high-level plan is fixed and only the invoked VLA executor varies. Specifically, we construct 10 counterfactual tasks from LIBERO-10 layouts by modifying the requested goal while keeping the scene visually close to a familiar source task. We report Faithful Rate, the fraction of rollouts satisfying the active counterfactual goal, and Non-biased Rate, defined as 100 − Biased Rate 100-\text{Biased Rate} , where Biased Rate measures whether the rollout also satisfies the paired source LIBERO-10 goal during a post-success continuation window. The continuation window length is 100. 
 RoboLab-120. 
 RoboLab-120  ( Yang et al., 2026 ) contains 120 manipulation tasks organized along three competency axes (visual, relational, and procedural) across three difficulty levels, testing generalization beyond the training distribution. All tasks use the benchmark’s default language instructions. We evaluate all 120 tasks with 5 seeds per task and a maximum horizon of 2,500 steps, using the same initial seeds and budget for the standard π 0.5 \pi_{0.5} baseline and VLAs-as-Tools . Full-task success requires the benchmark task predicate to be satisfied before termination, while partial progress is the mean fraction of required subtasks completed. We report both metrics averaged over all 600 episodes.
