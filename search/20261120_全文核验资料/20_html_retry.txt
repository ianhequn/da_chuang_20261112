 Retrospective Open-Vocabulary Memory for Long-Term Object Search 
 Jiaming Wang
 Zhiwei Xue
 Chen Jizhuo
 Peng Shiqi
 Harold Soh
 Affiliation:  National University of Singapore
 Abstract 
 Long-term object search requires learning where objects usually appear from repeated but uneven observations of a changing environment. We formulate retrospective open-vocabulary memory as probabilistic inference from censored observations, where the key idea is to reason with evidence per opportunity : a detection or non-detection should influence belief only in proportion to the robot’s opportunity to observe the corresponding location. We introduce Ecrom , which uses this principle to estimate long-term prevalence for concepts specified only at query time and converts the resulting belief directly into an active-search prior. To evaluate this problem, we introduce a controlled long-term benchmark in ten HM3D homes that independently varies object placement and observation opportunity across repeated traversals. Ecrom improves support-level AP on held-out queries by 4.5 points and search SPL by 4.2 points over the strongest competing memory in each metric. The benchmark, dataset, and code will be open-sourced. Project page: https://jiaming.im/ecrom/ .

 1 Introduction 
 Object search is a core capability of embodied AI. Existing approaches learn category-level search priors for unseen environments  ( Chaplot et al., 2020 ; Ramakrishnan et al., 2022 ) , ground open-vocabulary queries in spatial maps  ( Huang et al., 2023 ; Gu et al., 2024 ) , or reuse a map across multiple goals  ( Khanna et al., 2024 ) . These settings largely assume that objects are static or that the latest observation represents their current location. 
 Real environments are different. Frequently used objects such as keys, tools, and mugs move repeatedly, yet often follow stable routines. A robot deployed over weeks or months therefore should not only remember where an object was last seen, but learn where it usually occurs . Such a memory can guide future search and support retrospective open-vocabulary queries even for concepts specified only after the observations were recorded. 
 The key challenge is that repeated observations are highly uneven. Visiting a room does not imply observing every surface within it: the camera may face elsewhere, a surface may be occluded, or only part of it may be visible. Consequently, detection counts or visit frequencies confound object occurrence with observation frequency. A detection or non-detection should instead affect belief according to the robot’s opportunity to observe the corresponding location. Figure  1 illustrates this distinction: two surfaces can produce the same number of detections yet imply very different long-term prevalence because they were observed with different frequency. 
 Existing long-term memories primarily retrieve historical observations  ( Hu et al., 2026 ) , maintain the latest scene state  ( Liu et al., 2025 ) , represent temporal scene histories  ( Gorlo et al., 2026 ) , or predict the future state of established object–receptacle relations  ( Saavedra-Ruiz et al., 2026 ) . Our goal is different: to estimate the long-term prevalence of an arbitrarily specified concept while explicitly accounting for whether each past episode provided a meaningful chance to observe each location. 
 We introduce Ecrom ( Exposure-Calibrated Retrospective Open-Vocabulary Memory ), a query-independent long-term visual memory based on evidence per opportunity . Repeated RGB-D traversals are organized into a sparse atlas of surface supports. For each support j j and episode e e , the memory stores its geometric observation opportunity c j ​ e ∈ [ 0 , 1 ] c_{je}\in[0,1] . At query time, open-vocabulary detector responses are converted into calibrated likelihood-ratio evidence and combined with these opportunities through a censored observation model to infer the long-term prevalence θ j q \theta_{j}^{q} of concept q q . The resulting belief is used directly as a prior for active search. 
 Our contributions are: 
 • 
 a formulation of retrospective open-vocabulary memory as censored inference over long-term object prevalence, explicitly separating semantic evidence from observation opportunity; 
 • 
 Ecrom , a sparse query-independent memory that estimates prevalence for concepts specified only at query time and converts it directly into an active-search prior; 
 • 
 LOOP-Bench, a controlled long-term benchmark in ten realistic homes where object occurrence and observation opportunity vary independently; and 
 • 
 experiments showing improved distribution estimation and active search over counting, retrieval-, latest-state-, and PredictiveGraphs-style memories, including deployment on a physical robot. 
 2 Related Work 
 Object search and navigation. 
 Object-goal navigation and semantic exploration learn category-level priors or object probability maps for searching unseen environments  ( Chaplot et al., 2020 ; Ramakrishnan et al., 2022 ; Wang and Soh, 2023 ; Wang and Soh, 2024 ) , while open-vocabulary maps and 3D scene graphs such as VLMaps  ( Huang et al., 2023 ) and ConceptGraphs  ( Gu et al., 2024 ) ground language queries in a spatial map. These approaches primarily reason about where an object is , whereas we use repeated observations of a changing environment to estimate where it usually occurs . 
 Spatio-temporal memory. 
 Recent memories explicitly represent changes over time. DynaMem  ( Liu et al., 2025 ) and DovSG  ( Yan et al., 2025 ) update an open-vocabulary 3D map or scene graph to the latest observed state; DAAAM represents historical states in a hierarchical 4D scene graph  ( Gorlo et al., 2026 ) ; and retrieval-based approaches such as RAVEN  ( Hu et al., 2026 ) , STAR  ( Chen et al., 2026 ) , and ObsGraph  ( Lee et al., 2026 ) preserve and retrieve informative past observations. FreMEn  ( Krajník et al., 2017 ) learns periodic patterns in the probability of predefined binary states, such as whether a map cell is occupied, and PredictiveGraphs  ( Saavedra-Ruiz et al., 2026 ) goes further by attaching probabilistic temporal filters to object–receptacle relations, modeling persistence, emergence, detector misses, and missing observations to predict future relation states. These memories retrieve past observations, maintain the current state, or predict how predefined states and established relations evolve; none estimates the long-term prevalence of a concept specified after the fact while accounting for whether each episode could observe each location. 
 Benchmarks for object search and scene change. 
 ObjectNav  ( Batra et al., 2020 ) , including its version in procedurally generated ProcTHOR houses  ( Deitke et al., 2022 ) , evaluates object search in static, single-episode environments, while GOAT-Bench  ( Khanna et al., 2024 ) reuses a map across multiple goals but does not move objects between them. RIO  ( Wald et al., 2019 ) records repeated scans of changing indoor scenes to evaluate re-localizing objects that moved, not learning where they usually occur. LOOP-Bench instead repeatedly samples object locations from hidden distributions while independently varying robot trajectories and viewpoints, creating uneven observation opportunity. Queries are specified only after the history is recorded, and evaluation measures both recovery of the long-term occurrence distribution and its use for active search. 
 3 Problem Setup 
 We record episodes (traversals) e ∈ { 1 , … , E } e\in\{1,\ldots,E\} , each containing a stream of RGB-D frames, odometry, and timestamps. Our goal is to build a query-independent memory ℳ \mathcal{M} that can later infer where an arbitrarily specified object is likely to occur and use this prior to search efficiently, rather than exploring the environment from scratch. We organize this history as a place–view atlas built on the CROSS keyframe graph  ( Wang et al., 2026 ) . Its sparse topological structure tolerates changes between sessions, such as moved objects, without fusing all observations into one static metric map. On the keyframe graph, we group nearby keyframes into graph-connected places a a and bin their viewing directions into canonical view directions ψ \psi , yielding executable place–view pairs, or views, u = ( a , ψ ) u=(a,\psi) . The stored depth is voxelized into surface supports j ∈ 𝒥 j\in\mathcal{J} , where each support owns a set of surface voxels 𝒮 j \mathcal{S}_{j} . A support is a fixed-size, class-agnostic geometric patch of up-facing surface ( 0.5 × 0.5 0.5\times 0.5  m per height band; Appendix  E ). Thus, a view u u specifies where the robot can look , while j j specifies where an object may occur . After mapping, the user supplies arbitrary text q q .  Each recorded episode should change the belief about a support according to two separate sources of information, semantic evidence and observation opportunity : the memory must distinguish a genuine non-detection from a support that was never meaningfully observed, while keeping graded detector evidence rather than a binary hit. We derive an observation model that separates the two and use the resulting posterior as the search prior (Figure  2 ).

 Opportunity.

 the fraction of the support’s voxels that returned depth in episode e e within the detection range; supports contain only up-facing voxels between 0.12 0.12  m and 1.5 1.5  m above the floor, so the floor is never a support. Given a text query q q , OWLv2  ( Minderer et al., 2023 ) scores the stored RGB frames. We define r j ​ e r_{je} as the maximum localized detector score assigned to support j j in episode e e , avoiding repeated evidence from adjacent frames; a support with no localized detection in episode e e has r j ​ e = 0 r_{je}=0 .

 4.4 From memory to active search 
 For a unique target, we normalize the posterior prevalence estimates into search weights over supports, b j ∝ θ ^ j q b_{j}\propto\hat{\theta}_{j}^{q} , and use them directly for active search. A single placement can lie within 45 cm of several adjacent supports, so these weights rank where to look rather than forming a distribution over mutually exclusive locations. For a category, the θ ^ j q \hat{\theta}_{j}^{q} remain independent occurrence probabilities. 
 Search actions are the executable views u = ( a , ψ ) u=(a,\psi) introduced in Section  3 . From the robot’s current node cur \mathrm{cur} , executing view u u incurs cost C G ​ ( cur , u ) + d 0 C_{G}(\mathrm{cur},u)+d_{0} , where C G C_{G} is shortest-path travel distance and d 0 > 0 d_{0}>0 accounts for acquiring an observation. A view may expose several supports; c j ​ ( u ) c_{j}(u) denotes the opportunity to observe support j j from that view. We greedily choose the view that exposes the most current search weight per unit cost: 
 u ⋆ = arg ⁡ max u ⁡ ∑ j b j ​ c j ​ ( u ) C G ​ ( cur , u ) + d 0 . u^{\star}=\arg\max_{u}\frac{\sum_{j}b_{j}c_{j}(u)}{C_{G}(\mathrm{cur},u)+d_{0}}. 
 (7) 
 After executing a view, the search terminates if the detector fires and verification confirms the target (in simulation, at least 500 target pixels are visible in the view; on the robot, an operator confirms it). Otherwise, the failed look provides negative evidence for the supports that were exposed. Let p det p_{\mathrm{det}} be the probability that a visible target is successfully detected and verified, estimated from the calibration objects (Appendix  E.1 ). We update 
 b j ′ ∝ b j ​ ( 1 − p det ​ c j ​ ( u ) ) . b^{\prime}_{j}\propto b_{j}\bigl(1-p_{\mathrm{det}}c_{j}(u)\bigr). 
 (8) 
 Thus, a failed look strongly discounts well-observed supports, weakly discounts partially observed supports, and leaves unobserved supports unchanged. A detector trigger rejected by verification is treated as an unsuccessful look and therefore never raises the weight of the supports it exposed. 
 If the weights form a distribution over exclusive locations and view costs are fixed and order independent, ordering views by exposed probability per unit cost minimizes expected discovery cost (Appendix  B ; Kadane, 1971 ; Stone, 1975 ). We therefore use this criterion as a greedy heuristic, recomputing it after every observation to account for shared placements across adjacent supports and the robot’s changing, position-dependent travel costs. 
 5 LOOP-Bench: Long-Term Object Occurrence Prediction 
 We introduce LOOP-Bench ( L ong-Term O bject O ccurrence P rediction), a controlled benchmark that tests whether a robot can infer where an object usually occurs from repeated, uneven observations. It contains ten HM3D-Semantics homes  ( Ramakrishnan et al., 2021 ; Yadav et al., 2023 ) , where objects are repeatedly placed from hidden long-term distributions while routes and viewpoints are sampled independently, separating prevalence from observation opportunity (Figure  4 ). 
 Each home contains 20 past mapping traversals, giving 200 across the benchmark; each traversal provides RGB-D frames with a per-frame odometry pose in one common frame per home, from which a method may build any map. Each home has eight objects: five are evaluation queries, giving 50 queries in total, and three are calibration objects that are used only to select parameters and are excluded from evaluation. For each query, we evaluate both recovery of its ground-truth spatial occurrence distribution and closed-loop active search. Active search uses three independently sampled test placements per query, resulting in 150 search trials; because some placement distributions include an absent outcome, the object is not in the home in 22 of them. Full benchmark construction and evaluation details are provided in Appendix  D . 
 Figure 4: Benchmark examples from five houses, rendered in the benchmark simulator. For every traversal each object is placed on a receptacle drawn from a hidden distribution and settled by physics; routes and gaze are sampled independently of the placements, so an object’s presence cannot cause the camera to look at it.

 6.1 Setup 
 For each of the 50 LOOP-Bench queries, we build each method’s memory from the 20 mapping traversals of its house and evaluate its predictions on the shared surface supports. We derive two ground truths from the hidden placement distribution π \pi : a 15 cm footprint allocates each placement to supports, giving the occurrence probabilities g j g_{j} used for ranking, and θ j ∗ = ∑ k π k ​ m j ​ k \theta_{j}^{\ast}=\sum_{k}\pi_{k}m_{jk} is the probability that the object rests within 45 cm of support j j ( m j ​ k = 1 m_{jk}=1 when placement k k does), the prevalence of Eq.  1 (Appendix  D ). 
 We report AP, Top-5 mass, AUROC and Bernoulli NLL, averaged over the 50 queries. AP measures whether supports where the object actually occurs ( y j = 𝟏 [ g j > 0 ] y_{j}=\mathbf{1}[g_{j}>0] ) are ranked ahead of those where it never occurs. Top-5 mass measures how much of the true occurrence probability lies in the five highest-ranked supports. AUROC is the probability that a support with y j = 1 y_{j}=1 is scored above one with y j = 0 y_{j}=0 . These three metrics depend only on the order of the scores and measure whether a memory ranks first the supports where the object physically rests.  6.3 Results 
 Table  1 shows that Ecrom gives the best long-term occurrence estimate on all four distribution metrics, raising AP from .171 for the strongest baseline to .216. Detection count and visit frequency perform worse because they confound occurrence with observation frequency; visit frequency is the weaker of the two because the visit denominator carries little information about the object. Dividing detections by opportunity instead of visits improves every ranking metric and gives the best AP among the baselines, but without a prior this count assigns zero prevalence to every exposed support without a detection, so its Bernoulli NLL is worse than the constant prior of Coverage (.0773 against .0357). RAVEN-style retrieval and DynaMem-style memory emphasize strong historical observations or the latest state rather than long-term prevalence. PredictiveGraphs-style filtering is the strongest baseline in Bernoulli NLL and in search, but it models the persistence and emergence of already detected object–support relations rather than aggregating repeated evidence into long-term prevalence. Supports with weak or missed detections therefore receive little probability mass, and recurring locations are harder to recover: Ecrom ranks the true supports clearly better (AUROC .760 against .659, with paired intervals for AP, Top-5 and AUROC that exclude zero), while the two methods are close in Bernoulli NLL (Table  6 ). 
 These gains carry over to active search. Ecrom reaches .587 SR and .381 SPL, ahead of PredictiveGraphs-style memory (.533 and .339), the strongest baseline, although the paired intervals against it include zero (Table  6 ); Coverage without memory succeeds in only a quarter of trials. 
 6.4 Ablations 
 The lower block of Table  1 isolates the two main components of Ecrom . To test whether explicitly modeling observation opportunity is necessary, Ecrom without exposure term sets c j ​ e = 1 c_{je}=1 for every support in every traversal while keeping the same semantic evidence, likelihood ratio and posterior inference. Every distribution and search metric degrades; AP drops from .216 to .191 and SR from .587 to .520. A non-detection on a partially observed or unobserved support is now treated as if the support had been fully inspected, producing overly strong negative evidence: the prevalences of this variant sum to 2.32 per query, less than half of the true 4.76, whereas those of Ecrom sum to 5.10. The gain from the exposure term depends on how well the true supports were observed. When the queries are split into thirds by the opportunity summed over their true supports, the AP gain is + .057 +.057 for the least observed third and vanishes for the best observed third (Table  9 ). Averaged over all queries the gain is therefore diluted, and its paired intervals include zero for every metric except Bernoulli NLL (Table  6 ). 
 To separate missing observations from partial ones, Ecrom with binary exposure uses 𝟏 [ c j ​ e > 0 ] \mathbf{1}[c_{je}>0] : it still ignores traversals that never observed the support, but treats every partial observation as a full inspection. It recovers part of the gap and matches Ecrom ’s Bernoulli NLL, but ranks supports worse (AUROC .733 against .760) and searches less successfully, so fractional opportunity mainly sharpens the ranking of supports.

Together, these ablations show that Ecrom benefits from modeling both how well a support was observed and how strong the semantic evidence was .

 Results. 
 The real-robot results in Table  2 follow the same trend as simulation. Ecrom succeeds in 14 of 15 trials, against 10 for detection count and 11 for PredictiveGraphs-style memory, and reduces mean travel from about 29 m to 19.4 m and the number of inspected views from about nine to 4.7, so the prior focuses search on fewer, more promising locations.

 8 Limitations 
 Our observation model makes two approximations. First, the exposure c j ​ e c_{je} is a heuristic geometric proxy for the probability that a present object is observable: it equates observing half of a patch with a one-in-two chance of seeing the object, whereas this chance also depends on where on or near the patch the object rests, its size, the viewing distance and angle, and occlusion. Second, one likelihood ratio is shared by all queries, view counts and exposure levels, although weak responses carry more negative evidence when many views observed a support (Appendix  E.1 ). A learned visibility model and a likelihood ratio conditioned on the observation process are directions for future work. Supports are geometric patches without receptacle semantics, which could add prior structure when observations are sparse. We also assume a stationary prevalence, whereas routines may change over longer deployments. Finally, the planner is greedy rather than optimizing the full route. 
 9 Conclusion 
 We introduced Ecrom , a retrospective open-vocabulary memory that estimates where objects usually occur from repeated, uneven observations. By separating semantic evidence from observation opportunity, Ecrom gives better long-term prevalence estimates and more effective search priors, in simulation and on a real robot, and the ablations show that both opportunity weighting and graded detector evidence contribute.

 Appendix B Motivation for the Probability-per-Cost Index 
 The index rule of Eq.  7 is motivated by a simplified search problem in which it is exactly optimal. We state that problem, give the classical interchange argument  ( Kadane, 1971 ; Stone, 1975 ) , and then discuss which of its assumptions our navigation setting violates. In our setting the rule is therefore a greedy heuristic rather than an optimal policy; we use it for its simplicity and leave a globally optimal search planner to future work. 
 Simplified setting. 
 Views u ∈ 𝒰 u\in\mathcal{U} are executed at most once; view u u has a fixed cost C u > 0 C_{u}>0 that does not depend on the order of execution, the weights b j b_{j} form a distribution over mutually exclusive target locations, and a single inspection of u u discovers the target with probability ρ u = p det ​ ∑ j b j ​ c j ​ ( u ) \rho_{u}=p_{\mathrm{det}}\sum_{j}b_{j}c_{j}(u) evaluated at the initial belief, independently across views. A false alarm does not end the search and therefore does not enter ρ u \rho_{u} . A schedule σ = ( u 1 , u 2 , … ) \sigma=(u_{1},u_{2},\dots) has expected cost until detection J ⁡ ( σ ) = ∑ t ≥ 1 C u t ​ ∏ s < t ( 1 − ρ u s ) J(\sigma)=\sum_{t\geq 1}C_{u_{t}}\prod_{s<t}(1-\rho_{u_{s}}) . 
 Proposition 3 (Index rule) . 
 Under the simplified setting, the schedule that sorts views by decreasing ρ u / C u \rho_{u}/C_{u} minimizes J J , and since ρ u = p det ​ ∑ j b j ​ c j ​ ( u ) \rho_{u}=p_{\mathrm{det}}\sum_{j}b_{j}c_{j}(u) with p det p_{\mathrm{det}} common to all views, this is the order of Eq.  7 . 
 Proof. Take a schedule in which view a a immediately precedes view b b with ρ a / C a < ρ b / C b \rho_{a}/C_{a}<\rho_{b}/C_{b} , and let P P be the probability of reaching this pair undetected. Swapping them changes J J only through the terms P ⁡ [ C a + ( 1 − ρ a ) ​ C b ] P[C_{a}+(1-\rho_{a})C_{b}] versus P ⁡ [ C b + ( 1 − ρ b ) ​ C a ] P[C_{b}+(1-\rho_{b})C_{a}] ; their difference is P ⁡ ( ρ b ​ C a − ρ a ​ C b ) = P ​ C a ​ C b ​ ( ρ b / C b − ρ a / C a ) > 0 P(\rho_{b}C_{a}-\rho_{a}C_{b})=P\,C_{a}C_{b}\,(\rho_{b}/C_{b}-\rho_{a}/C_{a})>0 , so the swap strictly lowers J J . Repeated exchanges sort the schedule and no further exchange improves it. □ \square 
 What the navigation setting violates. 
 Four assumptions fail in Section  4.4 . First, a single placement can lie within 45 cm of several adjacent supports, so the normalized prevalences b j b_{j} are search weights rather than a distribution over exclusive locations, and p det ​ ∑ j b j ​ c j ​ ( u ) p_{\mathrm{det}}\sum_{j}b_{j}c_{j}(u) is not the probability that view u u finds the target. Second, the cost C ⁡ ( cur , u ) = C G ​ ( cur , u ) + d 0 C(\mathrm{cur},u)=C_{G}(\mathrm{cur},u)+d_{0} depends on the robot’s current node, so view costs are not order independent. Third, a view exposes several supports at once, so detection probabilities of different views are coupled through the shared belief and the update of Eq.  8 changes the ratios ρ u / C u \rho_{u}/C_{u} of the remaining views after every observation. Fourth, a detection is followed by verification, and a rejected trigger costs the verification without ending the search. For these reasons we use ρ u / C u \rho_{u}/C_{u} as a greedy heuristic, recomputed from the current weights and current position after every executed view, rather than as a precomputed schedule.

 Appendix D Benchmark Construction Details 
 We construct the benchmark in Habitat  ( Savva et al., 2019 ) using ten HM3D-Semantics homes. Each home contains 16–33 valid receptacle locations, including tables, desks, counters, islands, shelves, cabinets, nightstands, dressers, sofas, beds, benches, and stools. Each home receives eight household objects selected from screened Google Scanned Objects  ( Downs et al., 2022 ) , 80 object–home pairs in total, of which three per home serve as calibration objects and five as evaluation queries (below). 
 Placement distributions. 
 Each object is assigned a hidden distribution over valid receptacles, covering unimodal, bimodal, near-uniform, and rare/absent routines. Before every traversal, its location is sampled independently from this distribution and the object is settled using the simulator’s physics. Placement is therefore independent across episodes conditioned on the object’s long-term distribution. 
 Support-level ground truth. 
 For distribution evaluation, we represent each annotated placement location k k by a horizontal disc of radius 15 cm centered at its receptacle-top position. We sample the disc on a 2 cm grid and assign each sample to the support owning the nearest mapped surface voxel within 10 cm horizontally and 25 cm vertically. Let n j ​ k n_{jk} be the number of samples assigned to support j j and define A j ​ k = n j ​ k / ∑ ℓ n ℓ ​ k A_{jk}=n_{jk}/\sum_{\ell}n_{\ell k} for a footprint with at least one assigned sample; otherwise its column is zero. Given the query’s hidden placement probabilities π k \pi_{k} , its support mass is w j ∗ = ∑ k A j ​ k ​ π k w_{j}^{\ast}=\sum_{k}A_{jk}\pi_{k} . This fixed footprint model splits placement mass across patch boundaries in proportion to the observed footprint area.  Footprint sensitivity. 
 With footprint radii of 10 cm and 20 cm instead of 15 cm, Ecrom still has the highest AP (.199 and .239), Top-5 (.369 and .360) and AUROC (.767 and .759) of all rows of Table  1 . 
 Observation process. 
 Observation is generated independently of object placement. Every traversal starts at the dock, moves with discrete simulator actions, and returns to the dock. Each home’s 20 traversals mix 3–9 broad routes with 11–17 local patrols (200 traversals, 79,741 RGB-D frames and 9.01 km in total). On a broad route, rooms are entered with a fixed per-house probability of .25, .5, or .8; within entered rooms, the route covers a random 45–75% of candidate stations, and 40–70% of visited stations are traversed without stopping. Camera behavior ranges from broad sweeps to sparse or single glances, with occasional close receptacle inspections from 1.5–3 m. A local patrol is a short loop of at most 35 m that visits two of the four stations nearest the dock and scans by turning in place. Consequently, the same support may be fully observed, partially observed, or missed entirely across different traversals. 
 This independence is deliberate: whether an object is present cannot cause the robot to visit or look toward its location. The benchmark can therefore measure whether a memory correctly separates object prevalence from sensing frequency. 
 Splits and evaluation protocol. 
 Each home contains 20 mapping traversals and three in-distribution test traversals; the benchmark additionally provides two test traversals per home whose placement distributions are shifted, which are released with the benchmark but not used in this paper. Three objects per home are used only to select detector, calibration, and prior parameters; the remaining five are held out, resulting in 50 evaluation queries. Queries are supplied only after the mapping history has been recorded. All memories are built from the 20 mapping traversals. The distribution metrics compare each memory against the known placement distribution of the query. Each of the three test traversals contains one placement of every object sampled from that distribution, and each such placement is one search trial, so every query has exactly three trials and the 50 queries give the 150 trials of Table  1 . 
 Every method receives the same RGB-D streams and per-frame poses in a common coordinate frame and may construct its own metric or topological memory; for a fair comparison, our experiments give every memory the same supports and localized detections (Appendix  C ). Ground-truth object placements and receptacle annotations are withheld from the memory methods and used only for calibration on the designated objects and for evaluation. Distribution estimation is evaluated on the shared surface supports with footprint-based ground truth (Section  6 ), while active search uses the same simulator, detector, travel budget, and starting state across methods. 
 Appendix E Representation and Implementation Details 
 The CROSS keyframe graph  ( Wang et al., 2026 ) supplies graph topology, metric edge costs, and multi-session frame poses. Farthest-point seeding in graph distance followed by multi-source assignment creates connected places; each place has eight yaw bins, and these place–view nodes are the candidate actions and the cost structure of the search. A support is a 0.5 × 0.5 0.5\times 0.5  m patch (per 0.5 m height band) of 10 cm up-facing depth voxels observed at least twice within 3 m, built from the stored keyframe depth in the odometry frame of the traversals; c j ​ e c_{je} is the fraction of the patch’s voxels with a depth return in traversal e e within the detection range. Detector regions are lifted to 3D and assigned when their point lies within 45 cm of reliable surface voxels. The score likelihood ratio Λ \Lambda is fitted once on the calibration objects (Appendix  E.1 ): 13 histogram bins over the score with Laplace smoothing, pool-adjacent-violators monotonicity and a clipped log ratio | log ⁡ Λ | ≤ 6 |\log\Lambda|\leq 6 . The posterior of Eq.  6 is integrated on a composite grid of 400 nodes, 200 log-spaced on ( 10 − 9 , 0.05 ) (10^{-9},0.05) and 200 uniform on [ 0.05 , 1 ) [0.05,1) , each node carrying the prior mass of its cell. This matters: the sparse Beta prior has an integrable singularity at zero that a uniform midpoint grid resolves poorly (with Beta ⁡ ( .05 , 8 ) \operatorname{Beta}(.05,8) the no-evidence posterior mean on a uniform 400-point grid is .026 .026 against the exact .0062 .0062 , so every never-observed support would carry about four times too much belief), whereas the composite grid reproduces the exact conjugate Beta–Bernoulli means and intervals. The prior Beta ⁡ ( α 0 , β 0 ) = Beta ⁡ ( .05 , 8 ) \operatorname{Beta}(\alpha_{0},\beta_{0})=\operatorname{Beta}(.05,8) is selected on the calibration objects under this quadrature by held-out presence AP subject to the held-out Bernoulli NLL staying within 5% of its minimum. The planner’s acquisition cost in Eq.  7 is d 0 = 3 d_{0}=3  m, selected on the calibration objects from { 1 , 3 } \{1,3\}  m; travel costs C G C_{G} are shortest-path distances in the place graph, and a candidate view is admissible only while the budget still allows reaching it. 
 Runtime. 
 Query time is dominated by open-vocabulary detection. All results in the paper score every stored frame with OWLv2, which takes 80 s per query on an NVIDIA GeForce RTX 5090 (1,719 stored frames per home on average, scored at 22.6 frames per second); given the detector evidence, the posterior takes 12 ms per query and the index planner 0.6 ms per search step. Detection can be made faster by first retrieving the frames most similar to the query with SigLIP  ( Zhai et al., 2023 ) and scoring only those with OWLv2. A frame that the detector did not process is then censored: it contributes no evidence, and the opportunity c j ​ e c_{je} of every cell is recomputed from the depth of the processed frames only, so an unprocessed frame is neither a non-detection nor an observation. This trades accuracy for speed. Scoring half of each home’s frames halves the query time to 40 s and lowers AP from .216 to .191 and SR from .587 to .533; scoring a fixed 400 frames takes 19 s but lowers SR to .480, and about half of this loss comes from the largest home, where the retrieved frames leave most surfaces with little opportunity. 
 Degenerate cases. 
 A support with no localized detection in an episode has r j ​ e = 0 r_{je}=0 , never a missing value, and is evaluated by Λ ⁡ ( 0 ) \Lambda(0) ; a support with ∑ e c j ​ e = 0 \sum_{e}c_{je}=0 keeps its prior mean under Ecrom and its binary-exposure and binary-sensor variants, whereas the no-exposure variant sets c j ​ e = 1 c_{je}=1 for every support in every traversal; an all-zero score vector ties every support in the ranking metrics; the visit-frequency score is zero when ∑ e v j ​ e = 0 \sum_{e}v_{je}=0 . During search the 120 120  m budget counts forward motion in 0.2 0.2  m steps, rotations are free, and the acquisition cost d 0 d_{0} enters only the index.

 Likelihood ratio on the robot. 
 The robot has no simulator labels, so a single Λ \Lambda is fitted on its own stored keyframes of the mapping traversals, pooled over the labeled prompts. For each prompt, a score-stratified sample of about 120 keyframes (every keyframe scoring above .10 .10 , capped at 60, plus a random subset of the low-score keyframes) is labeled visible or not visible by a vision–language model (OpenAI GPT-6 via the Codex CLI, model gpt-6-astra , default decoding) with the prompt “This is a photo taken by a robot’s camera. Is there {query} visible in this image? It may be small or partly occluded, but must be identifiable as {query}. Answer with exactly one word: yes or no.” Each keyframe carries the inverse sampling weight of its score bin, and the weighted class histograms are shrunk towards the simulation histograms with n 0 = 20 n_{0}=20 pseudo-counts per class before pool-adjacent-violators and clipping. 
 Detection model of the online update. 
 A live look is summarized by verified discovery, Y = 𝟏 [ r ≥ τ ] ⋅ 𝟏 [ verified ] Y=\mathbf{1}[r\geq\tau]\cdot\mathbf{1}[\text{verified}] with τ = .25 \tau=.25 , and its rate given a visible target, p det = ℙ ⁡ ( Y = 1 ∣ visible ) p_{\mathrm{det}}=\mathbb{P}(Y{=}1\mid\text{visible}) , is estimated per stored keyframe on the calibration objects of each house: the fraction of keyframes in which the object is visible (at least 50 pixels within the detection range) that would have ended the search, i.e., in which the detector fires and the verification criterion (at least 500 target pixels) holds; it ranges from .05, the floor of the estimate, to .73 across houses. The robot instead uses the raw detector event with the detector rates of its VLM-labeled keyframes (Appendix  G ). A verified discovery cannot occur when the target is not visible, so the update has no false-alarm term. Applying the full
 Λ ⁡ ( r ) \Lambda(r) of the memory to every live frame is not equivalent:
 Λ \Lambda describes the maximum score of a traversal, not a single look. 
 Beta prior. 
 α 0 \alpha_{0} and β 0 \beta_{0} are selected on the calibration objects by
two-fold cross-validation over their mapping traversals, maximizing
held-out presence AP subject to the held-out Bernoulli NLL staying within
5% of its minimum, which gives Beta ⁡ ( .05 , 8 ) \operatorname{Beta}(.05,8) (prior mean about
 .0062 .0062 : a named object occupies a given surface patch in roughly one
traversal in 161). The exact values matter little. The prior is weak, so
the evidence of repeatedly observed supports dominates it, and it mainly
sets the belief of supports with little or no evidence, which stay at the
prior mean. What it must encode is only that a particular surface rarely
holds a particular object, α 0 ≪ β 0 \alpha_{0}\ll\beta_{0} . This is why the robot,
which has no presence labels to select the prior, can keep the
benchmark’s values.
