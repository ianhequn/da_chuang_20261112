## 一、结论与阅读口径

**项目方向有现实技术基础，但不能以“现有机器人基本都是固定流程”“缺少 Agent、技能与语义地图结合的整体方案”作为未经限定的立论。** SayCan、Inner Monologue、Hi Robot、RoboOS 系列，以及近期 Harness VLA、CaP-X，已覆盖语言目标理解、能力组合、环境反馈、记忆和部分任务调整。它们构成需要正面比较的先例。[S01](#s01)、[S02](#s02)、[S08](#s08)、[S09](#s09)、[S10](#s10)、[S14](#s14)、[S15](#s15)、[S16](#s16)

**更适合本项目的定位是：在明确的实体平台与受控家居条件下，研究异构技能接入、带历史和不确定性的环境信息、事件驱动任务调整之间的协同，并用可重复实验检验复用和服务扩展。** 这是本轮分析建议，不是已证明的新颖性结论。尤其“跨观测实例关联”“目标位置推断”需要分别定义和评价，不能用同一置信分数混代。

下文采用四种证据标记：

- **【来源】**论文或官方文档明确说明；实验结果均为作者报告，本轮没有复现。

- **【拟议】**本项目建议采用的设计、措辞或实验。
- **【待核】**尚未找到足够证据，不能解读成相关系统没有该能力。

## 二、领域图景：哪些对象应当比较

| 对象层次 | 代表入口 | 对本项目的作用 | 不宜据此得出的结论 |
|---|---|---|---|
| 完整移动操作系统 | HomeRobot、OK-Robot、DynaMem | 研究感知、定位、导航、抓取怎样形成真实任务闭环 | 开放词汇寻物不等于开放任务组织 |
| 语言／Agent 组织的机器人系统 | SayCan、Inner Monologue、Hi Robot、RoboOS、Harness VLA | 比较任务拆解、反馈、记忆、技能组合和可扩展组织 | 有高层推理不等于任意任务可靠执行 |
| 环境表示与记忆方法 | ConceptGraphs、ECROM、MessyMem | 比较对象表示、历史更新、交互经验、候选位置推断 | 有场景图不等于有长期实例身份或校准概率 |
| 执行模型与基础技能 | SmolVLA、AnyGrasp、OpenWAM | 为局部操作提供候选能力 | 模型基准成绩不等于本机整机成功率 |
| 平台与工具链 | Mobile ALOHA、XLeRobot、LeKiwi、Nav2 等 | 借鉴硬件、数据采集、设备适配和基础运行能力 | 硬件平台不能直接作为同层次的 Agent 系统反例 |

上述分类依据各项目明确的研究对象；具体来源见第七节及配套稿。Mobile ALOHA 同时包含硬件和策略研究，不能只当作开源机械结构，也不能据复杂演示推导其具备开放语言任务运行时。[S03–S07、S11–S13；配套稿 T01–T08]

|---|---|---|---|
| SayCan，2022 [S01](#s01) | 移动操作机器人执行真实室内长程自然语言指令 | 语言模型评价步骤相关性，技能价值函数提供物理可行性约束；执行依赖预训练技能 | 已验证长程语言目标执行；本轮未确认任意运行中追加要求的完整接口 |
| Inner Monologue，2022 [S02](#s02) | 仿真及真实桌面任务、真实厨房移动操作 | 将成功检测、场景描述和人类交互反馈转换成语言，持续更新计划 | 明确研究闭环反馈；直接反驳“语言规划机器人只能一次性输出固定流程”的概括 |
| TidyBot，2023 [S03](#s03) | 家居整理，真实移动操作平台 | 从少量示例概括用户收纳偏好，再结合感知、规划和操作 | 可向未见物品迁移偏好；验证仍围绕整理需求，不能据此推导任意家务 |
| HomeRobot，2023／2024 [S04](#s04) | 在新家居环境中找到开放词汇目标并放到指定承载面；仿真和 Stretch | 将任务定义为 OVMM，提供强化学习及启发式基线和真机软件栈 | 有跨物品、跨环境与仿真到现实证据；不是开放任务类别研究的充分证据 |
| OK-Robot，2024 [S05](#s05) | 10 个真实家庭的语言条件取放 | 组合视觉语言定位、导航和抓取模块，任务层聚焦 pick-and-drop | 无需额外训练即可组合现有能力；不据此认定已支持任意追加要求或技能扩展 |
| DynaMem，2024／2025 [S06](#s06) | 环境中物体移动、出现、消失时的开放词汇取放；Stretch SE3 | 在线更新三维时空语义记忆，定位查询、探索与操作衔接 | 可寻找记忆中没有的物体并更新环境状态；与本项目动态寻物直接相关 |

| Hi Robot，2025 [S08](#s08) | 清桌、制作三明治、购物；单臂、双臂、双臂移动平台 | 高层视觉语言推理与低层动作分层 | 明确处理复杂要求和执行中用户反馈，是“需求变化响应”的强相关先例 |
| RoboOS，2025 [S09](#s09) | 跨本体、多机器人协作 | RoboBrain 高层决策、模块化技能库、实时共享记忆及边云协同 | 包含规划、调度和纠错设计；模块化大脑—技能—记忆组织已存在国内直接先例 |
| RoboOS-NeXT，2025 [S10](#s10) | 餐厅、超市、家庭多机器人任务 | STEM 统一空间几何、时间事件与本体信息，支撑记忆检索、调度和执行 | 研究任务分配、状态同步和故障恢复；定量实验与真机演示须分开解释 |
| Harness VLA，2026 [S14](#s14) | 桌面、厨房及双臂操作；仿真与双 Franka 真机展示 | 冻结 VLA 作为可重试接触原语，与固定解析原语、记忆和编码 Agent 组合 | 验证目标重绑定、布局扰动、抓取恢复及新任务组合；不依赖扩大技能库解释全部提升 |

### 3.2 环境信息、扩展范围和证据边界

“未核实”表示本轮所读资料不足，不能写成“不具备”。不同论文的成功率不可直接排序，任务、环境、硬件、干预和统计单位不同。

| 系统 | 环境信息／记忆 | 已验证范围及必要限制 | 对本项目的直接借鉴或差距 |
|---|---|---|---|
| SayCan／Inner Monologue [S01](#s01)、[S02](#s02) | 技能可行性与语言反馈；长期对象数据库未核实 | 真机长程任务及闭环反馈，不是无边界任务集 | 能力前置条件和执行反馈应进入高层决策 |
| TidyBot [S03](#s03) | 用户偏好摘要；长期实例身份维护未核实 | 未见物品偏好预测 91.2%，真实场景归位物品比例 85.0%；两者口径不同 | 区分用户偏好记忆、任务记忆、环境物体状态 |
| HomeRobot [S04](#s04) | 为 OVMM 服务的感知与导航信息；概率身份未核实 | 提供仿真及真机基线，报告真机任务成功率 20% | 采用完整任务和分阶段指标；不将旧基准数字当作当前能力上限 |
| OK-Robot [S05](#s05) | 预扫描环境及语言目标定位 | 论文报告总体成功率 58.5%，更整洁环境 82%；官方部署依赖扫描、校准和特定硬件 | 说明模块集成价值，也暴露环境准备与设备适配成本 |
| DynaMem [S06](#s06) | 在线更新点云记忆，支持 VLM／开放词汇特征查询 | 3 个真实场景、9 个离线场景；非静止物体取放平均成功率 70%，不能称为 12 个真机家庭 | 动态记忆是已有路线；身份多假设和长期位置概率需另查／另做 |
| Mobile ALOHA [S07](#s07) | 核心为示教与策略学习，不以长期语义记忆为主线 | 论文使用每任务 50 次示教；不能写成所有任务无需示教 | 新技能所需数据、设备配置和调优成本必须计入扩展成本 |
| Hi Robot [S08](#s08) | 高层视觉、语言和用户反馈 | 多类任务及三个平台；外部技能任意替换和长期身份概率未核实 | 项目不能把“能听懂追加要求”单独作为新颖性依据 |
| RoboOS／NeXT [S09](#s09)、[S10](#s10) | 共享状态进一步发展为 STEM | RoboOS 的模型评测与协作演示不同；NeXT IV-A 明确大规模定量评测采用抽去物理不确定性的 mock setting，真机为定性案例 | 应正面比较架构重叠，同时保留真机系统可靠性与具体需求验证空间 |
| Harness VLA [S14](#s14) | 任务执行轨迹、成功规则与失败模型 | 仿真定量与双 Franka 展示分开；真机重置、成功判断有人工参与；新增组合不等于任意新技能 | “冻结模型＋原语＋Agent”已有强先例，应研究本机可复用边界 |
| CaP-X [S15](#s15) | 多轮执行反馈、视觉差分与自动技能合成 | 编码 Agent 表现随人为抽象变化；不是充分自主的家居长期部署证明 | 比较工具抽象质量与反馈机制，不能只比较所选大模型 |

### 3.3 环境记忆方面必须补充的近期工作

**ConceptGraphs [S11](#s11)**提供开放词汇对象与关系图、多视角融合及下游语言规划，是表示与建图参考，不能当作完整家居服务系统。本地核查显示其主关联路径采用相似度与确定匹配，细节见配套稿 L01。

**MessyMem [S12](#s12)**将三维对象／位置图与交互得到的属性、结果和视觉观测关联，研究跨任务复用经验。论文报告连续 25 项任务、超过 3 小时的仿真实验及真机验证；其中 80.0% 是该仿真设置的 task progress，不能改写为真机整任务成功率。它说明“环境状态＋历史经验”的方向也已有直接先例。

**ECROM [S13](#s13)**从不均匀观测中估计物体常出现的支持区域，以“观察机会”约束正负证据，构建主动搜索先验。其 v2 第 7 节还有 Stretch 3 办公场景实验：5 个查询物体、每个 3 次摆放，共 15 次／方法，20 个视点预算，检测后由操作员确认。该工作与“目标可能在哪里”直接重叠；但长期出现频率、当前所在位置和同类实例身份是不同变量，不能互相替代。论文的可见性近似和长期频率平稳性也有限制。

【拟议】可用于讨论的背景段落：

> 家居服务需要机器人响应不同目标，并在用户要求及环境状态变化时调整执行。已有研究已将语言模型、环境表示和多种执行能力结合，探索开放词汇移动操作、长程任务规划和反馈驱动的任务调整。然而，这些能力的有效范围仍与技能库、训练数据、机器人本体及实验环境密切相关。本项目拟面向受控室内平台，研究异构技能、环境语义信息和 Agent 持续决策之间的协同，通过任务闭环、条件变化与技能扩展实验检验其应用可行性及复用边界。

## 五、项目价值主张如何保留与补强

### 5.1 已有工作的重叠

Agent／语言模型负责高层组织、底层执行实时控制，已有长期先例；模块化技能和共享记忆也已有国内系统。环境图支撑查询与规划、历史交互影响后续任务、动态搜索与位置先验均已有相关方法。因此，“通用性、Agent 驱动、语义地图”适合作为设计特色方向，尚不能直接作为研究新颖性的充分证明。[S01](#s01)、[S02](#s02)、[S09](#s09)、[S10](#s10)、[S11](#s11)、[S12](#s12)、[S13](#s13)、[S14](#s14)、[S15](#s15)

### 5.2 建议保留的应用探索与工程贡献

下列均为【拟议】，成立与否取决于后续实现和实验：

1. **面向具体家居平台的协同方案。** 明确支持哪些对象、区域、任务和反馈，说明选择现成组件后仍需解决的感知—导航—操作衔接问题。
2. **实例关联与位置推断共同支撑任务。** 将同类物体身份歧义、物体移动、历史过期和有观测机会的未检出纳入服务，考察对搜索和取回的实际影响。不能仅因同时出现两个模块就宣称方法创新。
3. **事件驱动的任务调整。** 比较预设任务执行与反馈后持续决策，记录成功、额外步骤、响应延迟和恢复代价，说明高层组织机制的实际价值。
4. **有成本证据的扩展。** 在新增／替换技能前后记录接口、描述、适配器、上层代码和任务变化，回答哪些复用有效、哪些必须修改。

若这些实验只证明“用现成技术在自有平台上跑通”，应诚实定位为应用与系统工程成果。若拟提出方法贡献，需要进一步明确相对先例的具体机制差异、对照和消融，不能靠项目标题提升表述强度。

### 5.3 不应预先承诺的结论

不承诺任意家务、任意硬件零成本接入、无训练适配所有物体、长期自主运行或首次／领先；这些都超出当前平台证据与一年期边界。另一方面，也不应把项目缩为专用寻物器：首期取回闭环之外，应保留用户条件变化及至少一个实质服务扩展验证。

## 六、申报论证顺序与下一步决定

建议研究现状正文按以下顺序组织，而不是按模型名堆叠：

1. **实体移动操作的已有基础和集成难度：**HomeRobot、OK-Robot、Mobile ALOHA [S04](#s04)、[S05](#s05)、[S07](#s07)。
2. **从语言规划到闭环、多技能与用户反馈：**SayCan、Inner Monologue、Hi Robot，并对照国内 RoboOS 系列 [S01](#s01)、[S02](#s02)、[S08](#s08)、[S09](#s09)、[S10](#s10)。
3. **环境表示从静态对象图发展到动态与长期经验：**ConceptGraphs、DynaMem、MessyMem、ECROM [S06](#s06)、[S11](#s11)、[S12](#s12)、[S13](#s13)。
4. **近期 Agent 与具身策略协同及其限制：**Harness VLA、CaP-X、Cracking Mobile Manipulation [S14](#s14)、[S15](#s15)、[S16](#s16)。
5. **落到项目：**说明已有工作可以复用什么，本项目在何种平台条件下检验任务调整、语义推断和能力扩展，不宣称相关工作空白。

**下一轮优先作出四个具体决定：**

- 确定真机能力范围：抓取高度、物品重量／尺寸、RGB-D 条件、篮子位置，以及算力与链路。
- 选择首个可比较的抓取基线，并明确是否有适配本机的 SmolVLA 数据／权重。
- 选择一个同类物体身份歧义场景和一个位置变化场景，确定所估计变量与标注方式。
- 选择一个新增技能后才成立的服务任务，以及一个仅替换技能实现的任务，分别验证扩展和可替换性。

技术方案和建议实验详见配套稿。本轮不冻结模型、协议和引擎，不设缺少实测依据的成功率目标。

## 八、仍待核查的问题

1. 当前硬件、Nav2 真机与 SmolVLA 概念验证的准确完成范围、实验日志、设备配置和代码版本；规划文档中的陈述不是独立实验证据。
2. 各系统长期同类实例身份的定量评价和跨日重识别证据；本轮没有据“未见说明”作缺失判断。
3. RoboOS-NeXT 的具体代码公开范围、RPent 对本机硬件与 pi 引擎的适配成本；开源框架入口不代表直接可运行。
4. 最终采用模型的检查点、动作定义、数据需求、推理时延、可使用权重与具体版本；本轮只达到候选路线深度。
5. ECROM 等位置频率先验与本项目“当前实例可能位置”的结合方式；需进一步明确随机变量和观察条件。
6. 新增技能后可支持的服务范围及上层修改量；在实验前保持研究目标表述，不写成已实现优势。
