## 一、结论与阅读口径

**项目创新主线是从通用机器人应用需求出发进行分层设计、利用现代 Agent 能力驱动、融合语义地图支撑真实需求。** 相关研究已分别探索 Agent 任务组织、多 Agent 操作、异构技能编排、技能演进、环境记忆和家居移动操作。ManiAgent、OWMM-Agent、REAL、RoboHarness、ASPIRE、SHAPER 等均是与项目设计直接相关的先例，需比较它们的整体目标、层间关系、环境认知、技能扩展方式和验证场景。[S19](#s19)、[S25](#s25)、[S26](#s26)、[S27](#s27)、[S37](#s37) 后续补查的 MAESTRO、VLAs-as-Tools、URAI 等进一步覆盖多步工具与具身模型工具化，见 S29–S35。DAAAM 与 Surprise-Gated Robot Episodic Memory 又证明 4D 观测记忆可支持 Agent 历史问答：前者保存实体描述历史和观测时间线，后者选择性保存显著事件片段。二者均未将 Agent 猜测与观测事实分型、记录依据并随新证据修订。当前只能在这些明确边界下比较方案与接入方式，不把项目数量当成生态普查或领域空白证明。

项目的具体研究落点是：在明确的实体平台与受控家居条件下，研究异构技能、统一环境认知和 Agent 事件驱动任务组织如何协同，使机器人围绕不同用户目标组织能力、依据环境与执行反馈调整行动，并让新技能更容易接入、调优和复用。概率性实例关联与位置推断由同一环境认知服务统一维护。

## 二、领域图景：哪些对象应当比较

| 对象层次 | 代表入口 | 对本项目的作用 | 不宜据此得出的结论 |
|---|---|---|---|
| 完整移动操作系统 | HomeRobot、OK-Robot、DynaMem | 研究感知、定位、导航、抓取怎样形成真实任务闭环 | 开放词汇寻物不等于开放任务组织 |
| 语言／Agent 组织的机器人系统 | SayCan、Inner Monologue、Hi Robot、RoboOS、REAL、Harness VLA | 比较任务拆解、反馈、记忆、技能组合和可扩展组织 | 有高层推理不等于任意任务可靠执行 |
| 环境表示与记忆方法 | ConceptGraphs、OpenIN、FARM、ECROM、MessyMem | 比较对象表示、动态载体关系、持久对象记忆、交互经验和候选位置 | 有对象记忆不等于动态位置概率已经校准 |
| 家居任务仿真与基准 | BEHAVIOR-1K、RoboCasa365、REAL-Bench | 研究任务多样性、可重复比较和数据规模 | 仿真任务数不等于真实机器人完成任务数，也不表明采用了可插拔 Agent |
| 执行模型与基础技能 | SmolVLA、AnyGrasp、OpenWAM | 为局部操作提供候选能力 | 模型基准成绩不等于本机整机成功率 |
| 平台与工具链 | Mobile ALOHA、XLeRobot、LeKiwi、Nav2 等 | 借鉴硬件、数据采集、设备适配和基础运行能力 | 硬件平台不能直接作为同层次的 Agent 系统反例 |

上述分类依据各项目明确的研究对象；具体来源见第七节及配套稿。Mobile ALOHA 同时包含硬件和策略研究，不能只当作开源机械结构，也不能据复杂演示推导其具备开放语言任务运行时。[S03–S07、S11–S13；配套稿 T01–T08]

### 3.3 环境记忆方面必须补充的近期工作

**ConceptGraphs [S11](#s11)**提供开放词汇对象与关系图、多视角融合及下游语言规划，是表示与建图参考，不能当作完整家居服务系统。本地核查显示其主关联路径采用相似度与确定匹配，细节见配套稿 L01。

**MessyMem [S12](#s12)**将三维对象／位置图与交互得到的属性、结果和视觉观测关联，研究跨任务复用经验。论文报告连续 25 项任务、超过 3 小时的仿真实验及真机验证；其中 80.0% 是该仿真设置的 task progress，不能改写为真机整任务成功率。它说明“环境状态＋历史经验”的方向也已有直接先例。

**ECROM [S13](#s13)**从不均匀观测中估计物体常出现的支持区域，以“观察机会”约束正负证据，构建主动搜索先验。其 v2 第 7 节还有 Stretch 3 办公场景实验：5 个查询物体、每个 3 次摆放，共 15 次／方法，20 个视点预算，检测后由操作员确认。该工作与“目标可能在哪里”直接重叠；但长期出现频率、当前所在位置和同类实例身份是不同变量，不能互相替代。论文的可见性近似和长期频率平稳性也有限制。

**DAAAM [S38](#s38)**与 **Surprise-Gated Robot Episodic Memory [S39](#s39)**是本次针对“记录历史并由 Agent 回答”补查到的直接先例。DAAAM 用视觉跟踪和几何融合把跨帧对象片段合并为 4D 场景图实体，保留每个实体的自然语言描述历史及观测起止时间；Agent 工具可检索对象、位置、区域和时间线。惊讶门控方法在同一 4D 场景图上选择性附加带时间/位姿的视觉片段，供 Agent 按问题检索。两者分别侧重持续对象状态/描述历史与值得保存的具体片段，均在 CODa 记录数据上的时空 QA 评测。它们足以否定“机器人没有基于历史回答空间/时间问题”的说法，但不覆盖本项目更具体的认知状态问题：Agent 自己生成的猜测如何与视觉观测、用户陈述、任务推断区分；回答如何引用其依据、时间和未确认状态；新观测如何支持、削弱或撤销旧猜测。该差异目前是经来源比对后的研究问题候选，不是已证明的领域空白。

**OpenIN [S21](#s21)**是中国团队关于动态家居实例导航的直接工作：离线开放词汇实例图加入家具载体及物体承载关系，机器人在导航中更新载体状态，并按相似度、导航成本和载体常识搜索被移动的目标。主要长序列实验在 Habitat，论文另报告真机部署。它使“在家居里找会移动的特定日用品”本身也不能写成空白；但其关系更新和启发式导航排序，不等同跨观测实例身份与已校准的位置概率。

**FARM [S20](#s20)**将目标记忆路线推进到在线、持久对象级空间记忆：以带几何和视觉语言证据的对象实体执行跨视角关联，再把关系查询解析为目标、锚点及软关系谓词；论文报告 67 个场景、44k 查询和 Spot 上的在线闭环导航。证据需准确区分：论文基准映射评测使用 RTX 5090，VLM 服务使用 RTX PRO 6000；真实部署在 Jetson Thor 上，真机部分是关系查询导航展示，不是全套家务任务成功率。作者明确承认空间谓词手工指定且未校准。因此，项目不能宣称“首次具备对象级历史记忆、实例关联或关系位置检索”；更窄且待实证的问题是如何把动态家居物体状态、观察机会与任务动作事件结合，显式维持身份／位置候选不确定性，并证明其改善取回任务。

**RoboCasa365 [S22](#s22)**提供另一个重要反例：仿真基准包含 365 项任务、2,500 个厨房场景和 220 项移动操作任务，并以遥操作及合成示教数据比较多任务与 lifelong-learning 策略。它还在固定 DROID Panda 工作台报告四项真实桌面任务上的 sim-and-real co-training；该实验不是移动底盘家居闭环或在线 Agent 技能扩展。它表明“扩展到多任务”不应未经限定地写成空白，申报需区分单策略多任务泛化、在线技能组织和实体跨任务服务。

**REAL [S19](#s19)**是本轮发现的强相关完整系统，必须作为项目定位的直接比较对象。它在仿真中以无 oracle 感知 API 的视觉工具链主动搜索，在有歧义时向模拟用户询问；执行接口用 MCP 连接环境和技能，真机使用专用 pi0.5 操作策略。论文报告 241 个仿真任务实例以及 ARX LIFT2 上 60 次真机任务、总体成功率 78.3%；该数据是作者报告，任务和平台条件不可与本项目直接排名。尤其重要的是，REAL 自己列出边界：当前任务主要是跨 receptacle 重排，不含更丰富的时序子任务或空间关系目标；模拟用户不覆盖真实用户在执行中引入新目标的全部情况。它没有证明本项目所有方向都已完成，但使“把 Agent、地图、技能接成完整机器人系统”不再足以作为有区别的贡献主张。

**RoboHarness [S25](#s25)**把独立开发的 VLA、WAM、RL 与 TAMP policy 封装为 Agent skills，由 coding agent 根据能力描述拆解任务、路由策略并进行跨策略交接；其 skills 并非都只是低层原语。Evolution Skills 还按执行反馈调整策略和编排、更新能力卡及 TAMP 逻辑表示。其真机试验主要是结构搭建，和家居移动服务的范围不同，但它已覆盖异构技能编排与技能演进。

**MAESTRO [S29](#s29)**是目前检索到与项目“Agent 调用多步技能工具”最接近的系统之一。它使用 VLM coding agent，通过策划的感知、规划、控制工具库生成程序；harness 明确把多步感知—动作过程包装为可调用工具，并采用 plan-act-replan 和执行反馈。它还评估多种移动操作任务。由此可见，“我们的技能是短程任务而非原语”本身不足以构成差异，MAESTRO 已包含多步 callable tools；更应比较 Agent 的运行方式、工具由谁创建维护、跨任务的环境状态表示，以及整体系统服务目标和验证范围。

**URAI [S31](#s31)**让 programming agent 创建、修订可复用或任务专用工具，再由 execution agent 在观察和反馈间调用；单次工具可以执行完整多阶段运动。**VLAs-as-Tools [S30](#s30)**则直接把专用 VLA 作为 Agent 可选用的有界子任务工具，并用执行进度触发重规划。这两项都与项目“将具身模型和其他能力封装为技能专家供 Agent 组织”的设计直接相关，应纳入创新对比。

**RAX [S32](#s32)**和 **OpenRUA [S33](#s33)**代表另两种相邻路线：前者让 coding agent 在线探索并生成完整感知—规划—控制程序，验证后复用；后者让 coding agent 直接通过终端使用 ROS 2 原生接口，减少定制抽象。它们不是同一种技能服务架构，但说明“通用 Agent 如何获得和组织机器人能力”已有多条活跃路线。

这些工作共同表明，项目不宜仅以“Agent＋技能工具”或“多步任务封装”作为创新点。可继续论证的核心应是：从通用机器人应用需求出发，如何将现代 Agent、异构能力、统一家居环境认知与底层平台组织为可扩展分层系统，并让新增能力更容易适配和复用。其创新程度需要对照 MAESTRO、URAI、VLAs-as-Tools、RoboHarness 等近似工作后再判断。

**ASPIRE [S26](#s26)**把技能扩展推进到 agentic code-as-policy 和持续增长的技能库：执行引擎按感知、规划、抓取、控制等 primitive 提供逐步反馈，coding agent 修复机器人程序、把成功修复沉淀为程序技能，并经 coordinator 向后续任务迁移。论文在 LIBERO-Pro、RoboSuite 和 BEHAVIOR-1K 上验证长程技能组合；BEHAVIOR-1K 含 `navigate-and-pick-up-soda-can/radio` 家居移动操作任务，作者报告相对基线最高提升 32%。作者将 Franka 仿真技能迁移到 YAM 双臂机器人三项真机任务（苏打罐抓取、碗放盘、抽屉推拉）；真机编码 Agent 面对不同本体及 API 自主调试。论文还报告固定工具下的在线技能学习：三次连续 Rubik 魔方机器人交互中，Agent 通过文本技能与上下文积累提高操作效率。它使“Agent 从执行经验中积累技能并扩展后续任务”也不能作为空白；与独立技能服务注册／带语义前置条件的替换仍需比较接口契约和运行时生命周期，但不能忽略已有的跨 API code-as-policy 迁移证据。

ASPIRE 在仿真中采用固定 primitive API，而真机跨本体迁移则由 coding agent 调试并改写到 YAM API。代码式策略跨 API 适配已有先例；仍需与持久技能服务契约（能力声明、前置条件、取消与事件状态）区分，并比较其服务生命周期与扩展代价。

**SHAPER [S27](#s27)**研究另一类模型外演化：保持 planner、executor 和 action interface 冻结，在 VLABench 与 ESI-Bench 的仿真 rollout 上联合优化程序化文本技能和 Python context harness。它说明固定动作接口上的技能提示和上下文可以持续改进；论文没有报告真机部署或新增低层执行器注册。与 ASPIRE 的程序技能生成和 RoboHarness 的异构政策库／Evolution Skills 不同，SHAPER 改变 planner 指导和上下文，不扩充执行器动作接口。这些系统共同表明“技能学习／积累／上下文进化”已有多类先例，项目需精确定义研究对象是可执行技能服务、提示抽象、策略生成还是系统级外部能力扩展。

**RHO [S28](#s28)**提供重要负向案例：coding agent 在 RoboCasa 家居任务中根据失败诊断修复代码／技能，research agent 搜索并安装外部感知、规划模型；物理仿真器在写入前对修改做测试门控。123 轮中系统发现遗漏的主动视角搜索能力并加入模型，但目标“把芥末和蛋黄酱放到冰箱最上层”最终 0 次成功。作者诊断三类系统问题：感知模型能分割架子却不理解“最上层”关系；长技能链失败集中在早期，后续技能很少被测试；Agent 会优化 evaluator 的错误指标，弱测试与误导性记忆使活动无法转化为进步。论文明确这是单系统长程案例，不是对照实验。**RHO 证明自动发现技能和安装外部模型已有先例，也说明能力增长和局部测试通过不能证明目标服务有效。**本项目应报告端到端目标、各执行阶段的可达测试覆盖、技能实际调用率、评测器校验和跨场景回归。

**RHO [S28](#s28)**提供重要负向案例：coding agent 在 RoboCasa 家居任务中根据失败诊断修复代码／技能，research agent 搜索并安装外部感知、规划模型；物理仿真器在写入前执行修改门控。123 轮中系统发现了 active-view search 等遗漏能力并增加了八个外部模型，但目标“将芥末和蛋黄酱放在冰箱顶层”始终 0 次成功；作者将长期失败归于 coding agent 的失败原因表征、可修改范围与测试／评估门控限制。论文明确是一套系统的长程案例，不是有控制组的普遍性评估。**因此它既证明外部模型／技能自动扩展已有先例，也证明新增工具或通过局部模拟测试并不等于目标服务可用。**对本项目而言，技能扩展需以端到端目标成功、技能是否被正确触发、独立场景回归和错误评估器防护衡量，而不是只计已接入模型数。

**2026 BEHAVIOR 挑战策略 [S24](#s24)**作为近期仿真侧证据，覆盖 100 项家庭任务、每项 20 个私有测试实例；论文报告该方法完整任务成功率 41.2%。它以任务组划分和技能专用 LoRA 适配器及路由获得多任务性能，说明当前一个可行方向仍是预定义任务组内训练／选择专门策略。它是挑战策略与仿真 benchmark，不是具备开放技能服务或真实用户交互的完整家庭 Agent；完整任务成功率也不同于中间子目标进度。

## 五、项目价值主张如何保留与补强

### 5.1 已有工作的重叠

Agent 高层组织、异构技能编排、技能演进、环境记忆和家居移动操作分别已有研究，RoboHarness 与 REAL 是需要重点比较的系统先例。[S01](#s01)、[S02](#s02)、[S09](#s09)、[S10](#s10)、[S11](#s11)、[S12](#s12)、[S13](#s13)、[S14](#s14)、[S15](#s15)、[S19](#s19)、[S20](#s20)、[S21](#s21)、[S25](#s25)、[S26](#s26)、[S28](#s28) 这些工作说明相关组成方向已有积累；项目价值主张是从通用机器人应用需求出发，将分层设计、现代 Agent 驱动与语义地图融合为一套面向真实需求的整体方案，并论证其相对现有框架的特点。

### 5.2 建议保留的应用探索与工程贡献

下列均为【拟议】，成立与否取决于后续实现和实验：

1. **整体系统设计是项目创新论证的主线。** 项目从通用机器人应用需求出发进行分层设计，由现代 Agent 驱动任务组织，并融合语义地图支撑真实需求。REAL、RoboHarness、MAESTRO、URAI 和 VLAs-as-Tools 都是重要近似先例，覆盖家居移动操作 Agent、异构策略编排、多步 callable tools、可复用 task-specific tools 和 VLA 工具化等方向。正文应比较整体目标、Agent 运行方式、技能/tool 粒度及生成方式、环境信息作用和验证范围，再说明本项目的具体系统设计及家居应用价值。
2. **概率性动态实例／位置状态可能形成更具体的研究问题，但非无先例。** FARM 有持久对象实体、视点证据和跨视角关联；OpenIN 有载体关系变化；ECROM 有机会感知的位置先验；REAL 有当前任务中的视觉 ID 与探索图。可研究如何融合动作事件、历史观测和观察机会，区分实例身份、当前区域与长期先验，并评价校准及任务收益。必须先与这些工作逐项对照，不能宣称“语义地图不支持历史／动态物体”。
3. **家居工具集之外的真实能力扩展。** RoboHarness 已覆盖能力路由、技能记忆、状态交接、按执行结果更新策略／编排，以及学习新 TAMP 逻辑表示；REAL 则在固定家居工具接口中完成多任务组合。若主张扩展性，需定义外部独立技能接入相对 RoboHarness 自进化的差别，并比较新增／替换技能前后的可支持服务、数据依赖、适配成本、可靠性和旧任务回归。仅增加注册 API 并不能构成区别。
4. **处理真实用户执行中改变目标。** REAL 也明确其模拟用户有边界，真实用户可能中途引入新目标。项目可设计运行中改目标与物理任务取消／确认实验，但需与普通语言澄清区分，并记录动作安全、完成状态和恢复代价。

技能专家封装是连接现有技术生态的基础工作，创新论证落在它如何融入整体分层设计、由 Agent 按用户目标调用，并让不同能力更容易适配、组合和复用。系统设计的价值由整体组织方式、服务目标及应用验证共同说明。

### 5.3 不应预先承诺的结论

首期以寻物取回闭环验证整体设计，并进一步考察用户条件变化和新技能接入后的服务拓展。项目范围与验收成果应结合一年周期和实际平台条件确定；更广泛的任务、物品和平台拓展作为后续方向。

**下一轮优先深入四个调研问题：**

**S26 — ASPIRE.** Lu 等，v1 标题为 *ASPIRE: Agentic Skill Programming through Iterative Robot Exploration*；v2 标题为 *ASPIRE: Agentic /Skills Discovery for Robotics*。[arXiv v2](https://arxiv.org/abs/2607.00272v2)，首发 2026-06-30，v2 修订 2026-10-20；[官方 NVIDIA 项目页](https://research.nvidia.com/labs/gear/aspire/)、[官方代码仓库](https://github.com/NVlabs/ASPIRE)。本轮核对论文 §2、§3.2–3.7、§5、附录 D/G 和仓库 README。程序以固定仿真 perception/geometry/motion API 编写；agent 暴露逐 primitive 输入/输出、状态和多模态 traces，按失败诊断写修复，经 debug seeds 与独立 verifier 验证，再将含 failure signature、适用条件、修复策略/代码草案的经验保存为 in-context skills。BEHAVIOR-1K 是两项移动操作任务，并分别报告导航和任务成功；家庭长程结果的统计单位和 API 范围受限。YAM 三项“仿真迁移”并非控制策略直接部署：coding agent 将仿真发现的技能作为上下文，在不同本体、感知、标定和控制 API 上重新编程/调试；论文 Table 1 给出技能指导后苏打罐成功率从 13/20 提升到 19/20、抽屉推拉从 0/20 到 11/20、碗放盘两边均 20/20。另在一个 YAM 平台、一个 GPT-6 Astra session 的三次顺序 episode 演示 Rubik 学习，首轮未解出，随后两轮用 39 分钟和 77 分钟完成；不等于广泛服务评估。仓库当前 README 标注 v1.0，提供仿真与真实机器人操作指引；其 Quick Start 对算力/受限权重和 real-robot 独立准备有要求。此工作有力证明 code-as-policy 的修复技能学习和跨任务/跨 API 指导已有先例。

<a id="s27"></a>
**S27 — SHAPER.** Wang 等，*Self-Evolving Embodied Agents via Skill-Harness Evolution*。[arXiv v1](https://arxiv.org/abs/2608.11350v1)，首发 2026-08-11。定位：摘要、§3 的冻结 planner／executor、程序化文本技能与 Python context harness 联合进化，以及 VLABench／ESI-Bench 实验。执行 action interface 固定；结果支持仿真里的 planner context 和可复用 guidance 持续演化，不支持真机部署或新增低层执行器注册的主张。

<a id="s28"></a>
**S28 — RHO.** Wang，*What Stops Recursive Self-Improvement in Robotics? Lessons from 123 Rounds of Agentic Skill Discovery*。[arXiv v1](https://arxiv.org/abs/2609.31760v1)，首发 2026-09-30；[HTML 正文](https://arxiv.org/html/2609.31760v1)。定位：§3 的 PandaOmni／RoboCasa、§4 的外部模型搜索／安装和 123 轮过程、§5 的检测错误／技能链测试盲区／错误进度指标、§6 的建议。Simulation-only single-system long-run report；最终目标为 0/123 成功。作者目标为识别调味品并将其放到冰箱最上层。它不是总体机器人 Agent 失败率的估计，但直接提示新增工具、修改测试和学习进度的评估风险。

<a id="s29"></a>
**S29 — MAESTRO.** Shi 等，*MAESTRO: Orchestrating Robotics Modules with Coding Agents for Zero-Shot Generalist Robots*。[arXiv v3](https://arxiv.org/abs/2511.00917v3)，v1 首发 2025-11-02，最新 v3 于 2026-11-01 提交；页面注明 CoRL 2026 接收并扩充实验。[项目页](https://maestro-robot.github.io/)。定位：摘要、§3 的 curated tool library 与 orchestration harness、§4 的桌面及移动操作评测、§5 的消融和局限。核心证据：VLM coding agent 使用感知／规划／控制工具生成程序，harness 把多步感知—动作过程包装成 callable tools，以 plan-act-replan 和执行反馈闭环；作者报告移动操作任务且不调用 VLA tool。该工作直接覆盖“多步任务作为 Agent 工具”的抽象，需重点比较 Agent 运行形态、工具库维护、环境状态和家居服务目标。

<a id="s30"></a>
**S30 — VLAs-as-Tools.** Lei 等，*Towards Long-horizon Embodied Agents with Tool-Aligned Vision-Language-Action Models*。[arXiv v2](https://arxiv.org/abs/2605.13119v2)，2026-05-13 首发、2026-10-12 修订。定位：摘要与实验章节。高层 VLM 负责全局规划与恢复，专用 VLA 工具执行有界子任务并回报进度；论文提出 Tool-Aligned Post-Training，报告五项仿真基准和三项 Franka 真机任务。它直接说明“具身模型作为 Agent 可调用技能”已有相关研究；但研究焦点是 VLA 工具对齐训练，不等同完整家居机器人系统。

<a id="s31"></a>
**S31 — URAI.** Ge 等，*Make Code as Policy Great Again: Frontier Agents Write, Call, and Evolve Robot Tools*。[arXiv](https://arxiv.org/abs/2609.39018)，2026-09-30 提交。定位：摘要与系统图。Programming agent 从任务意图编写可复用或任务专用工具并根据反馈修订；execution agent 根据观察调用这些工具，每次调用执行完整多阶段动作后回到 Agent。作者报告五项 RoboDojo 仿真任务及七项 AgileX 双臂真机任务。它比“原语路由”更接近短程任务/tool 抽象，应作为直接先例比较。

<a id="s32"></a>
**S32 — RAX.** Huang 等，*Scaling Online Exploration for Robot Agents*。[arXiv](https://arxiv.org/abs/2610.22496)，2026-10-15 提交；[官方项目页](https://robot-agent-exploration.com/)及[代码仓库](https://github.com/robot-agent-exploration/rax)。定位：摘要与系统概述。Coding agent 使用原始感知和控制工具在线探索，生成完整感知—规划—控制程序，并通过验证技能在后续任务复用；论文覆盖单臂、双臂、移动和人形平台。该路线把探索出的完整程序固化复用，区别于运行时 Agent 从预先维护的技能服务中选择。

<a id="s33"></a>
**S33 — OpenRUA.** Chu 等，*OpenRUA: Robot-Use Agents Are Zero-Shot Visuomotor Policies*。[arXiv](https://arxiv.org/abs/2610.02459)，2026-10-01 提交。定位：摘要和官方代码入口。以终端访问原生 ROS 2 接口，不提供定制 primitive harness，让 coding agent 自行编写感知和控制程序。它是低抽象度的对照路线，说明“Agent 直接编程机器人”也是新近探索方向；不等同可插拔 task-skill service architecture。

<a id="s34"></a>
**S34 — uni-robot-agent.** Yuan 等，*Democratizing Robot-Use Agents: A Unified Harness with Open Models*。[arXiv v2](https://arxiv.org/abs/2611.01560v2)，2026-11-01 首发、2026-11-03 修订。定位：摘要与框架部分。为开放权重模型提供统一 robot-use harness，作者报告 RoboDojo 评测及 19 项真实任务。属于截至 2026-11-14 的近期 Robot-Use Agent 框架；其任务结果不直接代表开放家居长程服务能力。

<a id="s35"></a>
**S35 — RobotAgentBench.** Mao 等，*RobotAgentBench: Towards Open-world Robot Autonomy*。[arXiv](https://arxiv.org/abs/2610.34649)，2026-10-26 提交。定位：摘要和 benchmark task structure。它是评测基准而非机器人框架，划分 90 项 atomic、18 项 short-horizon、8 项 long-horizon household task 和 4 项 open-ended scenario，并比较机器人 Agent 架构。可用于理解近期领域如何划分任务尺度，不可把基准覆盖数等同任何一个系统的执行能力。

<a id="s36"></a>
**S36 — OWMM-Agent.** Chen 等，*OWMM-Agent: Open World Mobile Manipulation With Multi-modal Agentic Data Synthesis*。[arXiv v2](https://arxiv.org/abs/2506.04217v2)，2025-06-04 首发、2025-06-21 修订；仓库 README 标注 NeurIPS 2025 接收。[官方论文/数据/模型仓库](https://github.com/HHYHRHY/OWMM-Agent)，页面列出论文、数据集、模型及仿真评测代码。定位：论文 §3.1–3.3 的任务定义、预映射输入及 VLM→规划器执行链，§5.2 的仿真 episode 表格，§5.3 的 Fetch 真机评估，附录 B 的预映射、吸盘末端和跨本体限制。仿真任务要求将新物品从一个 receptacle 移到另一个，假定预映射相机位姿图与 2D 占据图；严格距离阈值下完整任务成功率 21.90%，宽松阈值下 51.52%。真机部分是实验室 Fetch 上 30 条指令的 action-generation 评估，27/30 成功，不能改写为 90% 端到端完成率。仓库提供数据生成、标注、单步和仿真评估流程；未据仓库首页推断可直接部署的完整真机运行时。此工作使“Agent 驱动的开放世界移动操作尚无直接先例”不成立；更合适的比较是它的预映射和任务边界、专用 VLM/固定规划器链，与本项目拟议的持续环境状态服务、事件驱动 Agent 和可扩展技能服务之间的差别。

<a id="s37"></a>
**S37 — ManiAgent.** Yang 等，*ManiAgent: An Agentic Framework for General Robotic Manipulation*。[arXiv v2](https://arxiv.org/abs/2510.11660v2)，2025-10-13 首发、2025-10-14 修订；[论文 HTML](https://arxiv.org/html/2510.11660v2)、[官方项目页](https://yi-yang929.github.io/ManiAgent/)、[官方仓库](https://github.com/yi-yang929/mani-agent)。本轮核对论文 §III–IV 和仓库 README。系统将任务分给场景感知、增量推理/子任务分解、物体定位/抓取姿态和控制 Agent；控制 Agent 以语言模型根据目标坐标与抓取候选生成笛卡尔动作序列，并缓存已完成子任务的参数化序列。SimplerEnv 的 BridgeTable 四项任务每项 24 次、跨 3 个随机种子；GPT-5 结果平均 86.8%。WidowX-250s、双 RealSense D435 的八项真实桌面任务每项 6 次；Claude-4-sonnet/Grok-4 平均 95.8%，GPT-5 为 93.8%。不将其写为移动家居系统：论文的 prompt 仅示范抓放、拖动和旋转少量动作，未提供持续语义地图或移动底盘验证。官方仓库称当前公开仿真部署中的 controller、object detector、grasper 等代码，reasoner 及其他部分仍在整理；配置要求分离 Agent/AnyGrasp/SimplerEnv 环境并建议 16GB 以上显存。此工作直接削弱“多 Agent 操作系统缺乏先例”的说法，但对本项目整机服务目标仍有明确边界。

<a id="s38"></a>
**S38 — DAAAM.** Gorlo、Schmid、Carlone，*Describe Anything Anywhere At Any Moment*。[arXiv v1 正文](https://arxiv.org/html/2512.00565v1)，首发 2025-11-29；[项目页](https://mit-spark.github.io/DAAAM/)，[官方代码](https://github.com/MIT-SPARK/DAAAM)。本轮核对 §3、§4.1–4.4、附录 B。Fast-SAM 分割与 BoT-SORT 图像轨迹形成 object fragments，Khronos 将片段提升到 3D 并估计动态位置；后台 4D 场景图做全局 reconciliation，合并跨时间片段并把每次生成的描述及活动窗口时间戳追加为实体 history。Agent 可用 `semantic_search`、半径、区域与轨迹工具检索描述、位置及 observation timeline。NaVQA 包含 210 个问答样本，短/中/长平均记忆时长 1.2/4.4/12.3 分钟；论文指出其空间标注以观察视点代替对象位置，于是构建 OC-NaVQA 并对 CODa 全序列评估，最长 35.8 分钟；SG3D 任务 grounding 为半合成 HM3D。实验统一使用 GT poses，属于记录序列 memory QA/任务 grounding，不是在线家庭用户交互部署。作者报告在 CODa/RTX 5090 设定达到几何管线 10Hz，但 DAM 描述有约 9.2 秒批次延迟；还承认 OOD 对象描述会 hallucinate/趋于常见对象、实体描述 history 可能无限增长。DAAAM 明确支持 Agent 根据 observation history 进行时空回答，故项目不应声称该能力没有先例；论文没有将 Agent 推测另存为有来源、状态和更新链的记录。

<a id="s39"></a>
**S39 — Surprise-Gated Robot Episodic Memory.** Gorlo 等，*Worth Remembering: Surprise-Gated Robot Episodic Memory*。[arXiv v3 正文](https://arxiv.org/html/2606.03787v3)，首发 2026-06-02、v3 修订 2026-06-06；[论文 HTML](https://arxiv.org/html/2606.03787v3)。本轮核对 §2–5。该方法用 V-JEPA-2 的 64 帧因果窗口特征和滑动对角高斯 surprise，在局部峰值选取稀疏 8 帧片段；事件记录带触发时间、机器人位姿和联合图文 embedding，附加到 DAAAM 的 4D 场景图，供 Agent 按文字/位置/时间检索。OC-NaVQA 评测使用 7 段 CODa 机器人记录序列；作者报告 GPT-5-mini QA 中 question accuracy 0.796 对 DAAAM 0.711、位置误差 36.57m 对 41.75m、时间误差 1.510min 对 1.792min，比较为相同记忆预算、三个随机种子平均。约 1.28 个 episode/分钟、1.7% 帧存储是该录制评估配置；还报告平均增加 13% token 使用。此证据说明选择性事件记忆能帮助历史问答，但不是持续线上用户助理试验；它不显式表示 Agent 猜测来源/置信/修订，也不输出物体身份或位置的后验概率。

## 八、仍待核查的问题

1. 同类物体长期身份与跨日重识别的外部研究证据、公开标注与适合小规模家居验证的指标。
2. REAL 与后续相关系统是否支持跨回合持久实例状态，以及第三方技能登记／替换的实际边界；按论文和指定版本源码进一步核对。
3. 规划式抓取与 VLA 技能的公开设备、数据、动作定义、权重许可和推理条件；当前仅形成候选对照，不选定模型。
4. MCP 与 ROS 2 action 的请求、反馈、取消和设备停止之间的协议边界，需依据固定规范版本和实现确认。
5. MuJoCo、Isaac／ManiSkill 等候选对首期移动操作任务的资产、ROS 接入、接触仿真和依赖隔离支持。
6. 新增技能后服务覆盖与上层修改量的实验定义，需避免把任务参数变化算成跨任务扩展。
