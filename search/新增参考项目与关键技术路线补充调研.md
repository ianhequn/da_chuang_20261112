## 三、已核查的一手资料

### 3.1 HALO（Apple）

- 论文：[Perceptive Humanoid Motion from Simulation](https://arxiv.org/abs/2611.06908)，arXiv:2611.06908，2026-11-04 提交 v1；作者列表包含 Siyuan Hu、Matthias Müller、Vladlen Koltun 等。
- 官方项目页：[apple-aiml-research.github.io/ml-halo](https://apple-aiml-research.github.io/ml-halo/)。页面明确展示 G1 真机运行、仿真数据生成、系统频率和硬件组成。
- 官方仓库：[apple-aiml-research/ml-halo](https://github.com/apple-aiml-research/ml-halo)。仓库公开 `datagen`、`generator`、`tracker`、`orchestrator`、`system` 等目录，并说明包含数据生成、模型训练和部署代码。

论文摘要报告：HALO 在 1000 个程序化住宅中合成视觉-语言-运动数据，包含坐椅、到达目标物、侧身过半开门、钻桌、推箱等技能；在六个未建图真实环境的 360 次试验中报告 91% 成功率。该数字是论文作者报告的单项/任务试验结果，不等于开放家居任务的普遍成功率。

项目页进一步给出系统分层：约每 2 秒由 VLM 编排器把请求转成子任务；约 3 Hz 的生成器根据 RGB 和当前子任务生成 5 秒、150 帧、36 维全身动作计划；首 0.5 秒提交；跟踪器以 50 Hz 根据深度和本体感知输出 29 个关节目标。仓库说明还明确区分仿真闭环 `run_sim.py`、G1 真机闭环 `run_real.py`、消息通信 `halo_comm` 和设备模型调度 `halo_serve`。

**对本项目的判断：** HALO 是与本项目最接近的新近完整系统先例之一，直接反驳“没有 Agent 编排、动作模型和仿真到现实结合的系统”这类宽泛表述。它仍不等于本项目的语义地图方案：公开页面强调未建图环境、子任务编排和运动执行，没有证明其维护跨观测物体实例身份、历史位置候选或概率校准。其技能集合和平台是人形 G1 全身运动，不能直接推导到移动家居取放、抓取入篮或异构技能热插拔。

### 3.2 AR-WAM

- 论文：[AR-WAM: A Visual-Conditioned Agent-Ready World Action Model for Robotic Manipulation](https://arxiv.org/abs/2609.23578)，arXiv:2609.23578，2026-09-20 提交，2026-10-02 修订至 v2。
- 官方项目页：[ar-wam.github.io](https://ar-wam.github.io/)；官方仓库：[AR-WAM/AR-WAM](https://github.com/AR-WAM/AR-WAM)。

论文摘要明确说明：AR-WAM 用目标视觉框和可学习操作 token 替代自然语言动作指令；模型规模为 0.5B，无语言编码器，提供 `detect`、`execute`、`query` 三个原语，长时程记忆和闭环错误恢复交给 Agent 侧。作者报告其在 RoboTwin 2.0、RMBench 和 Astribot S1 双臂真机上评估，标准操作平均成功率 85.7%，记忆相关任务提升 5.9%，真机长时程任务提升 36.7%，推理延迟 14.1 ms。

**对本项目的判断：** AR-WAM 对“技能专家 + Agent”接口设计高度相关，因为它把动作模型的意图、执行和查询边界显式化；但它把长时程记忆和错误恢复交给 Agent，不能替代本项目的环境语义地图和任务运行时。其操作平台、任务集合和接口假设仍需与家居移动取放平台单独适配。

### 3.3 SENT-Map

- 论文：[SENT Map -- Semantically Enhanced Topological Maps with Foundation Models](https://arxiv.org/abs/2511.03165)，arXiv:2511.03165，2025-11-05 提交；论文页面注明接收于 ICRA 2025 Workshop on Foundation Models and Neuro-Symbolic AI for Robotics。
- 项目页：[rpm-lab-umn.github.io/SENT_map](https://rpm-lab-umn.github.io/SENT_map/)。

论文摘要明确：SENT-Map 用 JSON 文本格式表示室内环境，使人和基础模型都能添加、编辑语义信息；第一阶段由 Vision-FM 和操作员共同建图，第二阶段将 SENT-Map 与自然语言查询交给基础模型规划，并通过把机器人锚定到已有节点来避免部署中的不可行状态。作者报告语义增强能帮助小型本地模型完成室内导航与操作规划。

**对本项目的判断：** SENT-Map 可作为“语义地图服务的可编辑表示和高层规划接口”参考，尤其适合比较 JSON/图结构、节点锚定和语义约束。但摘要没有证明跨观测实例身份后验、动态位置候选、历史衰减或概率校准；因此它只能补充项目的地图表示与规划接口论证，不能替代本项目拟研究的动态物体状态服务。

### 3.4 XLeRobot

- 官方仓库：[Vector-Wangel/XLeRobot](https://github.com/Vector-Wangel/XLeRobot)，README 标题为 “Practical Dual-Arm Mobile Home Robot for $660”，许可证为 Apache-2.0。
- 文档入口：[xlerobot.readthedocs.io](https://xlerobot.readthedocs.io/en/latest/index.html)。

仓库 README 明确列出其依托 LeRobot、SO-100/SO-101、LeKiwi 和 Bambot；仓库结构包括 `hardware`、`software`、`simulation`、`web_control` 和 `XLeVR`。README 还列出键盘、Xbox、Switch Joycon、Quest3 VR 等控制入口，以及 MuJoCo 仿真、RL 环境和新相机支持。仓库自述基础配置约 660 美元，并给出 2025-06 的 0.2.0 版本和“可进行自主家务任务”的项目自述。

**对本项目的判断：** XLeRobot 是可作为支撑平台和仿真/遥操作参考的真实开源平台，适合核查低成本双臂移动底盘、相机和 LeRobot 接入条件。其 README 主要证明平台、控制和仿真资源存在，不能据此证明 Agent 任务编排、语义地图或长期自主服务已经实现；“自主家务任务”应视为项目自述，仍需按具体演示和代码验证。

### 3.5 dual-so101-mobile-manipulator

- 官方仓库：[leo-zhu-agibot/dual-so101-mobile-manipulator](https://github.com/leo-zhu-agibot/dual-so101-mobile-manipulator)。

README 将其定位为“simulation-first v0.1 integration baseline”，组合差速底盘、双 SO-101 机械臂、RGB-D、2D LiDAR 和 IMU。仓库明确列出：27 个 link、26 个 joint 的 Xacro/URDF 和 ros2_control；Isaac Sim 4.5+ 导入和 ROS 2 bridge；100 Hz 控制器；MoveIt 双臂配置；Nav2、RGB-D voxel layer 和 LiDAR obstacle layer；导航到感知、规划、执行、验证的 fail-closed 状态机；rosbag2 数据采集、SQLite 时间戳 QC、标注校验和 SHA-256 episode manifest。

仓库同时明确写出边界：Isaac Sim 需要 NVIDIA 环境，CI 未执行 GPU 物理和硬件标定；项目不是已完成的实体硬件系统，下一步仍包括传感器图生成、Nav2/MoveIt 适配、校准硬件适配和 ACT/Diffusion Policy 评估。

**对本项目的判断：** 这是目前收藏中最适合参考“跨层胶水、平台接口和验证门槛”的工程基线之一。它提供了比单纯硬件 BOM 更具体的状态机、通信契约和数据质量控制，但尚未提供 Agent 任务编排、动态语义地图或已完成的真机端到端服务证据。

## 四、AR-WAM 的报告地位

AR-WAM 不应替代本报告的整体范围，也不应被写成项目完整系统先例。其正确位置是“技能模型与操作能力”组中的重点待核查对象，需回答：

1. AR-WAM 的完整名称、作者、发布日期、代码和许可证是什么；
2. 它生成或预测的动作表示、时间范围和控制接口是什么；
3. 训练数据、机器人平台、传感器和算力条件是什么；
4. 是否有真机、跨任务、跨平台或 sim-to-real 证据；
5. 它是否能够被上层 Agent 作为可验证、可取消、可替换的技能调用；
6. 它是否维护环境状态或对象历史，还是只负责动作生成。

在未完成核查前，建议采用以下限定表述：

> AR-WAM 可作为动作模型路线的候选参考；其对本项目的价值取决于公开接口、真实平台证据和与任务级技能封装的兼容性，不能仅由模型名称推断其具备开放任务组织或家居服务扩展能力。

## 五、HALO 的报告地位

HALO 已完成一手资料核查，报告中的正式定位是“分层人形自主系统和仿真到现实先例”。

> HALO 可作为 Agent 编排、全身动作生成、跟踪控制和仿真到现实协同的强相关对照；其未公开或未证明的动态语义地图、对象身份推断和异构技能扩展能力，不能由项目演示或 91% 试验数字推断。

## 六、四组路线的补充判断

### 4.1 平台与整机

XLeRobot、dual-so101、YOR、Mobile ALOHA 和 LeRobot 可用于比较硬件结构、数据采集、ROS/仿真接入和操作能力来源。它们的公开平台或演示不能直接证明具备 Agent 驱动的开放任务运行时。平台比较应记录底盘、机械臂、相机、控制接口、遥操作方式、许可和实际实验边界。

### 4.2 技能模型与操作

AnyGrasp、Dex4D、HiWET、VAT-Mart 和 AR-WAM/WAM 系列应按“局部动作能力”比较，而不是按系统完整性比较。统一记录输入、输出、动作空间、反馈、失败信号、数据需求和真实机器人证据。只有当模型被封装为具有前置条件、资源约束、结果验证和取消语义的技能，才能进入本项目的技能专家候选。

### 4.3 语义地图与动态寻物

SENT-Map、Clio、Kimera-Semantics 和动态隐蔽空间搜索可补充现有 ConceptGraphs 分析，但需区分：几何/拓扑地图、语义区域、对象实例关联、历史观测和位置候选推断。不能把语义分割或场景图存在，直接写成已经具备概率化动态对象记忆。

### 4.4 系统工程与数据基础设施

OK-Robot 和 LeRobot 更适合补充复现条件、数据流程和平台适配；Neo4j 与 PostGIS 仅是可能的存储组件。它们不能替代任务句柄、事件生命周期、设备取消确认和跨层状态一致性设计。

## 十、原始任务对象的二次核查记录

### REAL

已通过 [arXiv:2607.13653 v2](https://arxiv.org/abs/2607.13653) 复核。论文摘要明确其为无 oracle 感知的开放世界移动操作 Agent，包含主动探索、视觉指代和交互式意图澄清；REAL-Bench 覆盖 241 项任务，论文报告双臂移动机器人 60 个真实回合的 78.3% 端到端成功率，并提供 [InternRobotics/REAL](https://github.com/InternRobotics/REAL) 代码入口。该数字和任务范围可作为主报告引用，但仍应限定为作者设定和其平台，不外推到本项目。

### 当前复核结论

原始任务中 REAL 的关键数字和系统定位已有一手论文依据；HALO、AR-WAM、SENT-Map、XLeRobot、dual-so101 的新增核查也已记录。RoboHarness、ASPIRE、SHAPER、RHO、FARM、OpenIN、ECROM、DynaMem 等在主报告中已有论文定位和限制记录，但若进入最终申报正文，仍应对正文实际引用的数字逐条回到对应 arXiv 版本核对，不能仅引用本补充报告的二次摘要。
