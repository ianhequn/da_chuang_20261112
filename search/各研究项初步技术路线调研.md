## 一、整体路线与已经知道的条件

【拟议】先以可解释、可记录的有限物品取回闭环建立系统基线：用户目标 → 查询候选区域 → 导航／视觉寻找 → 确认目标和可达性 → 抓取入篮并验证 → 返回用户区域 → 汇总与更新。以同一任务运行机制支持用户改要求、技能失败和目标移动，然后通过新增／替换技能验证复用范围。

### 1. 技能专家的构建、封装与应用

【分析】本项目不必为体现“具身”而让所有技能都依赖同一个 VLA／WAM。相反，应比较一种可解释的抓取基线和一种适配本机的学习策略；如果当前 SmolVLA 已在本机稳定工作，它可以成为首期方案，但需要日志与任务条件支持。模型名只是实现选择，贡献应落到能力适配和系统任务结果。

#### 1.2 拟议的封装内容

技能描述至少说明用途、输入输出、对象／区域约束、前置条件、资源占用、可取消阶段及失败类型。导航的“成功”应说明使用的到达容差；抓取应区分未找到、不可达、规划失败、夹取失败、夹持不确定；放置应返回是否验证及证据来源。这些是拟议的语义要求，不在本轮规定详细字段协议。

可复用模型和导航／规划器；需要自行完成本机适配器、能力描述、状态归一、结果核验与必要的复合技能。技能代码重用不等于技能语义可以直接重用，不同模型替换后应重新验证前置条件、动作范围和成功判据。

#### 1.3 首期验证及风险

【拟议】先在固定可达区域验证搜索、抓取、入篮单项，再加入移动后的感知和操作。记录分阶段成功率、耗时、重试、人工干预及失败原因。比较技能实现时保持任务物体与环境条件可比，不能以各自最佳演示替代对照。

主要依赖是硬件能力、标定、数据与算力；关键风险是检测正确但深度或可达性错误、策略动作与本机不匹配、低层失败未被检测。应优先缩小物品尺寸／材质和操作区域，而不是由高层 Agent 反复盲目重试。

### 2. 环境语义地图的整体设计与实现

#### 2.1 已有组件能承担哪些职责

| 需求 | 候选与依据 | 能承担的职责 | 不能未经验证就认为已经具备 |
|---|---|---|---|
| 几何、定位与导航地图 | RTAB-Map／已有 ROS 2 导航基础 [T03](#t03)、[T05](#t05) | RGB-D／激光 SLAM、定位及地图发布，具体取决于配置 | 房间用途、长期物体身份和搜索概率 |
| 对象级三维语义表示 | ConceptGraphs [S11](C:/My_Work/ShuZhi_HW/WORK/大创/search/研究现状与问题分析.md#s11)、[L01](#l01) | 检测反投影、对象点云、多视角特征融合、语言查询和关系图线索 | 动态跨区域搬动物体的可靠身份概率与时序位置后验 |
| 多层空间语义 | Kimera 等 [T06](#t06) | 度量语义建图与三维网格等候选能力 | 与本机传感器兼容、房间用途自动标注与完整家居记忆 |
| 在线动态记忆 | DynaMem [S06](C:/My_Work/ShuZhi_HW/WORK/大创/search/研究现状与问题分析.md#s06) | 结合当前观测更新记忆，查询和探索 | 原样即能维护本项目全部实例候选与概率校准 |
| 历史交互与经验 | MessyMem [S12](C:/My_Work/ShuZhi_HW/WORK/大创/search/研究现状与问题分析.md#s12) | 将交互结果和对象图关联，跨任务复用线索 | 任意长期身份追踪、物理状态总是真实准确 |
| 位置先验／主动搜索 | ECROM [S13](C:/My_Work/ShuZhi_HW/WORK/大创/search/研究现状与问题分析.md#s13) | 基于历史出现、可见性和观察机会推断支持区域先验 | 将频率先验直接当作某实例此刻位置概率 |

【拟议】首期保留既有可用几何地图，人工／半自动标记少量房间、桌面、篮子和观察位；用对象语义记录与观测日志承接感知，不因需要语义而立即替换已经可用的 SLAM。是否全面采用 ConceptGraphs，应由点云开销、实时性和对象需求验证决定；也可以先复用其表示与相似度思路，独立实现较小服务。

#### 2.2 必须区分的三个量

1. **实例关联：**当前检测属于哪个历史物体的候选推断，例如 `P(历史实例 j | 当前观测、观测历史)`，允许“新物体／未知”。同类外观完全相同且缺少证据时，应保留歧义。
2. **当前位置：**在给定实例身份、时间与任务结果后，目标位于哪个候选区域的推断，例如 `P(当前区域 r | 实例 j、历史与当前证据)`，并保留未知／环境外等选项。
3. **长期出现倾向：**物体过去经常出现于哪些支持区域，是搜索先验；不能替代“最近被放入篮子后现在在哪里”的状态推断。ECROM 属于重要参考 [S13](C:/My_Work/ShuZhi_HW/WORK/大创/search/研究现状与问题分析.md#s13)。

公式只表明拟估计的变量，不意味着本项目已有完整贝叶斯实现。ConceptGraphs 的 CLIP 相似度、空间重叠与检测置信度也各有含义；将相似度做 softmax 只能产生归一化分数，不能自动证明概率校准。[L01](#l01)

#### 2.3 最小数据与更新路线

【拟议】组织四类信息：几何／坐标版本、区域与支持面、实例候选状态、不可覆盖的观测／动作结果日志。观测保存时间、来源、传感器位姿、类别／特征、深度定位质量和可见范围；物体状态引用产生它的证据。

实例关联先用类别约束、外观特征、空间和时间信息形成候选排序；避免因空间变化直接认定是新物体，也避免同类物体被强行合并。首期可比较“只用类别和最近位置”“加入外观特征”“加入历史与动作证据”三种版本，再决定需要何种概率模型。

位置推断结合最近观测、任务导致的移动、区域先验和信息时效性。对“在某处未找到”区分未观察、遮挡、深度缺失、检测失败及足够观察机会下未检出。只有后者适合形成受限的负证据；有明确被搬走／放入篮子的验证证据时，应相应修改候选，而非只覆盖坐标。[S06、S13；拟议扩展]

Agent 通过查询获得候选、时间和证据摘要，不能依赖语言模型自由生成物体坐标。技能提交观测和经过验证的结果；服务负责更新和保留版本，跨任务信息可复用。原始日志与当前估计分开，使错误关联有机会撤回与重算。

#### 2.4 评价、依赖和风险

【拟议】建立少量可人工标注的真实序列：同类相似物体、跨区域搬动、暂时遮挡、重复观测、环境外物体和过期记录。记录实例关联准确／召回、错误合并、身份切换、候选位置 top-k 命中、搜索步数、时延和存储增长。

如对外声称概率，另检查可靠性图、Brier 分数或对数损失，并按场景／时间划分验证数据，防止相邻视频帧泄漏。小样本时报告不确定性和计数，不以未经校准的 0.78／0.86 示例作为结果。

主要依赖为可用位姿、深度、时间同步和实例真值；风险包括定位漂移导致重复实例、相似物体不可辨识、负证据误用和长期状态无限累积。首期可限制实例数与区域数，但不删除不确定性和历史需求。

### 3. Agent 层事件驱动系统与能力接入

#### 3.1 候选路线与现成基础

【来源】本地 pi 提供低层 `Agent`、工具描述／执行、事件订阅、输入队列以及较高层的 `createAgentSession` 和持久会话管理。具体版本、函数、调用签名见 L02。本轮确认的是通用 Agent 机制，不是机器人成功执行证据。

【拟议】可比较两种接入深度：

- **pi-agent-core＋自有机器人宿主：**直接控制工具集、消息转换和外部状态；需要自行实现持久任务运行时与会话管理。
- **pi-coding-agent SDK＋机器人工具：**复用会话、压缩和扩展等机制，显式配置工具与资源加载；需处理编码工具默认行为、会话状态来源和运行结束语义。

首期选择应由一个异步技能原型验证，不按“SDK 功能越多越好”判断。Harness VLA 和 CaP-X 已提供编码 Agent 组织机器人原语的证据；它们的本体、原语、反馈与评测条件不能直接复制为 pi 在本项目上的效果。[S14](C:/My_Work/ShuZhi_HW/WORK/大创/search/研究现状与问题分析.md#s14)、[S15](C:/My_Work/ShuZhi_HW/WORK/大创/search/研究现状与问题分析.md#s15)

#### 3.2 长任务与消息调度的关键约束

【来源】本地 `steer()` 把消息加入队列，循环在当前轮及工具批次之后读取；并行工具模式也会等待 `Promise.all(...)` 汇合后继续。`abort()` 设置取消信号，工具接到 `AbortSignal`，但不保证底层驱动已停止。[L02](#l02)

【拟议】导航、搜索、抓取等长任务宜采用“提交后返回任务句柄＋状态／事件＋取消请求”的宿主机制，或具有明确短时限的等待工具；避免让一个长时间不返回的工具阻塞全部新要求。外部事件驱动宿主保存事实，再选择在空闲时唤醒、在合适轮次注入消息，或先发取消并等待确认后重新规划。

引擎消息取消与机器人动作取消分开：不能因为高层运行结束，就认为底盘或机械臂已经停止；不能因用户要求变更，就在未知动作状态下发冲突任务。实时保护与低层停止由支持层负责，高层负责理解任务后续如何处理。

#### 3.3 上下文与三类记忆

【拟议】会话上下文维护用户目标、约束、计划摘要和近期执行进展；用户记忆维护偏好等稳定信息；地图维护环境实体、观测和位置推断。三者通过实体标识、任务标识和证据引用衔接，避免把聊天记录当作环境真值数据库。压缩后仍应能从结构化任务日志恢复必要事实。

事件输入应给出“发生了什么、何时、涉及何任务、事实是否确认”，Agent 再决定后续行动。技能失败、超时、断连和用户更改目标具有不同含义，不能都变成一段无结构“失败了”的文本。

#### 3.4 需要自行完成的工作与验证

本项目需完成机器人宿主、任务上下文、事件到消息的适配、可用能力选择、必要的资源约束、反馈落地和执行日志。引擎本身不提供本机任务可靠性。

【拟议】用同一技能集比较固定任务流程和 Agent 组织；设计运行中换目标、追加限制、目标未找到、抓取失败、连接恢复等情况。统计正确后续决策、总任务成功、无效调用、恢复步数和响应延迟。LLM 输出合理不等于执行成功，两种结果分别记录。

### 4. 各层胶水与通信机制

#### 4.1 先分清需求，再选通信

| 信息或操作 | 候选机制 | 理由与约束 |
|---|---|---|
| 支持层导航／操作长任务 | ROS 2 action 或设备 SDK 原有任务机制 [T02](#t02)、[T03](#t03)、[T04](#t04) | action 支持目标、反馈、结果和取消；具体服务端是否及时取消仍需验证 |
| 地图查询／观测提交 | 同机库接口、ROS service 或 HTTP／RPC | 查询时延、数据量、部署方式与调用语言决定选择；不提前冻结协议 |
| 高层 TypeScript 与 Python／ROS 适配 | 小型适配服务，候选 HTTP＋事件流、WebSocket 或其他 RPC | 避免直接要求所有模型运行在同一语言；需要显式关联请求和任务 |
| 状态变化与事件 | 现有 ROS topic 或独立事件流 | 区分可重放事实、临时进度和最新状态；断连后需能核对当前任务 |
| 图像、点云与模型输入 | 尽量保留在感知／技能侧，用引用或摘要提供上层 | 避免将大体量实时数据塞入语言模型消息；具体传输需测延迟和带宽 |

【来源】ROS 2 官方文档将 action 定义为由 service／topic 组合的长任务机制，支持反馈、结果和取消。[T02](#t02) 这能支撑支持层任务，不直接解决 Agent 会话、地图一致性和多框架任务语义。

#### 4.2 拟议的公共运行机制

任务至少要能关联提交、受理、运行、完成、失败、取消请求、取消确认与超时；细节后续设计。“超时”描述等待方不再等，不必然说明执行方已停止。请求重试应有幂等或重复检测，尤其抓取、释放等有物理副作用的动作，不能在结果丢失后直接重复执行。

事件维护来源、任务、时间、顺序／版本与可追踪证据。断连重连先查询服务端状态，核对已经发生的动作，再决定继续、取消或重建任务。物理结果、地图记录和会话摘要可能暂不一致，应明确由谁确认、修复和保留未决状态。

多技能并发要考虑资源：共享底盘、机械臂或相机的技能不因引擎支持并行就能同时执行。资源互斥、动作优先级和时限属于系统宿主与技能运行机制，不能交由语言模型仅凭文字自律。

可复用 ROS／SDK 与引擎工具机制；需自行完成跨语言适配、任务记录、事件归一、状态核对、重复抑制和运行可观测性。首期验证取消期间断连、重复完成事件、迟到结果、重启后任务状态和同资源竞争，范围按实际选定部署缩小。

## 三、跨板块关键衔接

1. **定位、坐标、时间是共同基础。** 同一物体的地图位置、相机深度、抓取坐标和导航目标应可追溯到相同坐标关系及版本。平台误差需要反馈至关联和操作置信信息。
2. **技能结果是环境证据，不只是聊天信息。** 抓取、释放、移动后要区分命令完成与物理结果确认；地图更新引用验证证据，Agent 记录当前未决状态。
3. **地图向技能提供决策依据，也接收观测。** 候选区域帮助搜索，执行的新视角和结果修正地图；不要让地图查询和视觉搜索维护两套互不一致的对象状态。
4. **任务句柄贯通引擎、适配器与机器人。** 取消、超时、迟到结果、断连恢复都要找到对应任务；单纯转发字符串难以支持可靠恢复。
5. **能力描述影响高层可规划范围。** 新技能接入不仅是接口连通，还涉及前置条件、参数落地、资源、结果验证和地图语义。
6. **评价按证据对象分开。** 引擎推理质量、模型单项成功、地图推断质量、整机成功与扩展成本分别报告，不能用局部结果替代整机结论。

上述为拟议的系统设计要求；相关工作说明其必要性，本项目仍需实现和验证。

## 六、技术来源补充目录

均访问于 2026-11-14。未给出明确修订日期的文档以访问日期记录，不猜测发布时间；线上滚动文档不作为冻结版本安装指令。

<a id="t01"></a>
**T01 — AnyGrasp.** Fang 等，*AnyGrasp: Robust and Efficient Grasp Perception in Spatial and Temporal Domains*，[arXiv](https://arxiv.org/abs/2212.08333)，首发 2022-12-16，页面列 IEEE T-RO 2023；[官方 SDK](https://github.com/graspnet/anygrasp_sdk)。定位：论文摘要及仓库开放模块、安装／模型使用说明。候选用途为点云抓取；不是整个机械臂控制器。

<a id="t02"></a>
**T02 — ROS 2 actions.** [Jazzy 官方文档源文件](https://github.com/ros2/ros2_documentation/blob/jazzy/source/Concepts/Basic/About-Actions.rst)，本轮读取 [raw 正文](https://raw.githubusercontent.com/ros2/ros2_documentation/jazzy/source/Concepts/Basic/About-Actions.rst)。定位：Background、Actions，说明长任务、反馈、取消与 client/server。文档站访问受限时回到官方源；未据此假定本机发行版是 Jazzy。

<a id="t03"></a>
**T03 — Navigation2.** [官方仓库](https://github.com/ros-navigation/navigation2)，README 及导航文档入口。定位：行为树、导航任务、服务端与客户端等模块。候选为已有 Nav2 基础的继续利用；实际版本和配置待平台核对。

<a id="t04"></a>
**T04 — MoveIt Planning Scene.** [官方教程](https://moveit.picknik.ai/main/doc/examples/planning_scene/planning_scene_tutorial.html)，定位 PlanningScene、碰撞检查与约束检查。用于运动规划与环境约束候选，不保证已有机械臂配置可直接使用。

<a id="t05"></a>
**T05 — RTAB-Map.** [官方仓库](https://github.com/introlab/rtabmap)，[README 原文](https://raw.githubusercontent.com/introlab/rtabmap/master/README.md)。定位：RGB-D、双目、激光 SLAM 及 ROS 集成入口。几何建图与语义对象记忆职责分开。

<a id="t06"></a>
**T06 — Kimera.** [MIT-SPARK 官方仓库](https://github.com/MIT-SPARK/Kimera)，README 的实时 metric-semantic mapping 与各子模块说明。本轮只读官方入口，不作其本机部署和房间分割能力保证。

<a id="t07"></a>
**T07 — MuJoCo.** [官方文档](https://mujoco.readthedocs.io/en/stable/overview.html)，定位 Overview 及仿真模型／传感器入口。用于候选仿真范围分析；未安装和验证 ROS 接入。

<a id="t08"></a>
**T08 — XLeRobot.** [官方仓库](https://github.com/Vector-Wangel/XLeRobot)，README 的硬件、操作和仿真入口。本轮不记录易变价格或由演示推断 Agent 架构，也未审计其完整代码。

<a id="t09"></a>
**T09 — LeKiwi.** [Hugging Face LeRobot 官方文档](https://huggingface.co/docs/lerobot/lekiwi)，定位平台介绍及组装、控制和训练工作流。公开平台方案可借鉴，但需适配本机动作与设备。
