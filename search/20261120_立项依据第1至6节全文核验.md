# 《立项依据》第1—6节全文核验

核验日期：2026-11-20；交接版整理日期：2026-11-20。对象：项目根目录《立项依据.md》的第（1）—（6）节，以及这些正文引用的30条参考文献。第（7）节不纳入核验。本报告仅提供核验发现及修订建议，不表示任何建议已被正文采纳。

## 一、结论与核验范围

当前正文引用的28篇 arXiv 文献、Evo-1 的 CVF 会议记录和 Pi 的固定提交文档均已取得原始资料，并针对正文实际使用的主张核对。未发现当前编号指向另一篇无关论文、用不存在的论文支持正文、把主要仿真结果写成整机真机结果等问题。发现概括过强、项目基础与外部文献混写、版本未固定等问题，详见第五节的待处理事项。

这里的“核验”是检查原始资料是否支持正文的具体表述、引用元数据是否对应，不是独立复现作者实验，也不是对本项目尚未实施的方案作效果保证。正文提出的接口、概率推断、事件调度和扩展机制，属于拟研究方案；文献只提供已有方法和先例，不能替代本项目的后续实验。

核验前快照、论文文本、OpenWAM PDF、官方文献记录、Pi 固定提交文档及历史机器检查结果保存在同目录的 `20261120_全文核验资料/`。抓取清单保留了首次失败和后续补抓记录，不把下载失败或验证页面记为读到原文。OpenWAM 的 HTML 获取失败后，实际取得并提取了43页论文 PDF；Pi 的原始网络地址失败后，实际读取了本地同一固定提交的 Git 对象。

## 二、核验方法

1. 确认当前正文，保存核验前快照，区分已有工作陈述、相关研究事实、项目方案及预期结果。
2. 获取文献原文及元数据；阅读与正文主张对应的方法、实验设置、结果及必要附录，不用搜索摘要替代实验范围判断。
3. 逐段检查第1—6节的证据对应、技术逻辑与研究范围，记录问题、证据边界与建议，供修订者判断，不将建议当成正文现状。
4. 检查参考文献编号、版本、作者、日期、链接和引用覆盖；记录版本对应关系；不核验第七节内容。

## 五、待处理问题与修订建议

1. **研究目的的行业判断**：建议用明确先例替换“成熟方案少、规模生态难找”等未建立判据的概括。本轮检索不能证明整个领域不存在成熟方案或规模生态。
2. **部分可观测性的表述**：建议从“绝对追踪几乎不可能”收紧为“多个状态与观测相容时，证据不足以唯一确定”。观测不足不意味着所有情况下都无法追踪，也不自动证明概率模型有效。
3. **HALO 的技术链条**：建议分清运动生成器和运动跟踪器，保留其作为合成数据与仿真到真机参考的地位。
4. **第二项创新的结果语气**：建议保留环境认知为 Agent 提供共同依据的设计重心，将预期能力明确写为拟实现并由实验检验。
5. **项目基础与外部证据**：建议让 SmolVLA 论文引用对应模型原理和异步推理方法；团队已有单臂概念验证应由项目过程资料或实验记录支持。对“小木块”和既有 TCP/ROS 2/控制器连接细节，未取得直接实验或程序证明，应由修订者补充直接证据；若无证据，建议改为待核对的连接方案。slam_toolbox 的已有使用基础同样需项目证据，不能仅凭未检索到记录便否定；项目名建议采用 `slam_toolbox`。
6. **基准使用边界**：建议说明适配或改规则后的结果须单列，不直接与原榜单比较。不建议凭空增设成功率门槛或要求复现整套基准。
7. **参考文献版本与可追溯性**：建议将原先未带版本的9条 arXiv 引用固定为本轮核对版本：[4]v1、[5]v2、[6]v1、[15]v1、[18]v1、[21]v1、[22]v1、[24]v1、[25]v1。若按本轮复核重新著录，可将访问日期更新为2026-11-20；建议[29]增加 CVF 直接地址，[30]指向固定提交的 SDK 文件。
8. **作者元数据歧义**：[20] 的页面/全文显示第三作者为 `Chen Jizhuo`，而其导出元数据按 `Jizhuo, Chen` 排列。建议保留完整姓名原样，或进一步取得作者姓名顺序的可靠证据后再缩写；这属于元数据歧义，不宜直接断定原著录错误。其余作者缩写、题名、首发日期及已标版本与本次取得的原始记录相符。

核验前参考文献中的括号日期沿用 arXiv 首次提交日期，不表示所固定版本的修订日期。例如 MAESTRO 首次提交于2025年，正文核对使用的是2026年修订的 v3；不能仅凭首发年份判断正文依据的版本。
